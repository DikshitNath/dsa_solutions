# 📈 Online Stock Span

> **Platform:** LeetCode | **Topic:** Stack | **Technique:** Monotonic Stack

**Question Link:** [https://leetcode.com/problems/online-stock-span/](https://leetcode.com/problems/online-stock-span/)

---

## 📌 Problem Summary

Design a class `StockSpanner` that collects daily stock prices and returns the **span** of the current day's price — the number of **consecutive days** (including today) where the price was **less than or equal to** today's price.

---

## 💡 Core Intuition

Instead of looking back every time (O(n) per call), we use a **monotonic decreasing stack** that stores `{price, span}` pairs. When today's price is greater than or equal to previous prices, we **absorb their spans** into today's span.

> 📦 **Analogy:** Imagine stacking boxes. If today's box is taller, you swallow all the smaller ones under it — their heights (spans) just add up to yours.

---

## 🤔 Why Store Span in the Stack?

We don't store individual days — we store **accumulated spans**. When we pop a smaller price off the stack, instead of re-counting its history, we just **add its precomputed span** to the current span. This gives us `O(1)` amortized time per call.

---

## 🪜 Algorithm Steps

1. 🟢 Initialize `span = 1` (today always counts)
2. 🔁 While stack is **not empty** AND `top.price <= current price`:
   - ➕ Add `top.span` to current `span`
   - 🗑️ Pop the top (it's absorbed into today)
3. 📥 Push `{price, span}` onto stack
4. 📤 Return `span`

### Full C++ Solution

```cpp
class StockSpanner {
public:
    stack<pair<int, int>> st;   // {price, span}

    StockSpanner() {}

    int next(int price) {
        int span = 1;

        while (!st.empty() && st.top().first <= price) {
            span += st.top().second;    // accumulate spans
            st.pop();
        }

        st.push({price, span});         // push today with total span
        return span;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(1) amortized | Each price is pushed and popped at most once |
| 🧠 **Space** | O(N) | Stack holds at most N elements |

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | Stack is **monotonically decreasing** — larger prices never get popped by smaller ones |
| 2 | Storing `span` in the stack avoids **re-traversal** of old prices |
| 3 | Each element is pushed/popped **exactly once** → amortized O(1) |
| 4 | This is a classic **Monotonic Stack** pattern |

---

## ⚠️ Common Mistakes

- ❌ **Starting span at 0** instead of `1` → today's day is never counted
- ❌ **Using `<` instead of `<=`** → equal prices on previous days should be absorbed
- ❌ **Storing only price** without span → forces re-counting, breaking O(1) amortized

---

## 🧠 Monotonic Stack Pattern

    → Use when you need "how far back does a condition hold"
    → Store extra info (like span) to avoid redundant recomputation
    → Amortized O(1) because each element enters/exits stack once
