# 📚 Validate Stack Sequences

> **Platform:** LeetCode | **Topic:** Stack | **Technique:** Stack Simulation

**Question Link:** [https://leetcode.com/problems/validate-stack-sequences/](https://leetcode.com/problems/validate-stack-sequences/)

---

## 📌 Problem Summary

Given two integer arrays `pushed` and `popped`, return `true` if they could represent a valid sequence of push and pop operations on an **initially empty stack**.

    pushed = [1,2,3,4,5], popped = [4,5,3,2,1] → true
    pushed = [1,2,3,4,5], popped = [4,3,5,1,2] → false

---

## 💡 Core Intuition

**Simulate** the push/pop process greedily. Push elements one by one. After each push, check if the stack's top matches the next expected pop — if yes, keep popping. If we successfully process all pops, the sequences are valid.

> 🏭 **Analogy:** Loading boxes onto a stack one at a time. After each box is placed, check if it's the next box the customer wants — if yes, immediately hand it over. If all requests are fulfilled at the end, the sequence was valid.

---

## 🤔 Why Greedy Popping Works?

Once the top of the stack matches `popped[j]`, there's **no reason to delay** popping it — pushing more elements on top would only bury it deeper, making it impossible to pop next. So popping immediately is always the right choice.

    If st.top() == popped[j]:
    → Pop now or never — greedy is always optimal here ✅

---

## 🪜 Algorithm Steps

1. 🔁 For each element in `pushed` (pointer `i`):
   - Push `pushed[i]` onto stack
   - 🔁 While stack not empty AND `st.top() == popped[j]`:
     - Pop from stack
     - Advance `j`
   - Advance `i`
2. 📤 Return `st.empty()` — all pushed elements should have been popped

## 🧩 Code Walkthrough

### Dry Run — Valid

    pushed = [1,2,3,4,5]
    popped = [4,5,3,2,1]

    i=0: push 1 → st=[1],     top=1 ≠ popped[0]=4 → no pop
    i=1: push 2 → st=[1,2],   top=2 ≠ 4 → no pop
    i=2: push 3 → st=[1,2,3], top=3 ≠ 4 → no pop
    i=3: push 4 → st=[1,2,3,4]
         top=4 == popped[0]=4 → pop, j=1
         top=3 ≠ popped[1]=5 → stop
    i=4: push 5 → st=[1,2,3,5]
         top=5 == popped[1]=5 → pop, j=2
         top=3 == popped[2]=3 → pop, j=3
         top=2 == popped[3]=2 → pop, j=4
         top=1 == popped[4]=1 → pop, j=5
         st=[]

    st.empty() = true → return true ✅

### Dry Run — Invalid

    pushed = [1,2,3,4,5]
    popped = [4,3,5,1,2]

    ... after processing all pushes ...
    At some point: need to pop 1 before 2
    but 2 is on top of 1 → impossible

    st not empty → return false ✅

### Pseudocode

    validateStackSequences(pushed, popped):
        i=0, j=0
        stack = []

        while i < n AND j < n:
            stack.push(pushed[i])

            while stack not empty AND stack.top == popped[j]:
                stack.pop()
                j++

            i++

        return stack.empty()

### Full C++ Solution

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& pushed, vector<int>& popped) {
        int n = pushed.size();
        stack<int> st;
        int i = 0, j = 0;

        while (i < n && j < n) {
            st.push(pushed[i]);                         // push next element

            while (!st.empty() && j < n &&
                   st.top() == popped[j]) {             // greedy pop
                st.pop();
                j++;
            }
            i++;
        }

        return st.empty();                              // all matched?
    }
};
```

| Metric | Complexity | Reason |

| 🧠 **Space** | O(N) | Stack holds at most N elements |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Greedy pop** — always pop immediately when top matches next expected pop |
| 2 | `return st.empty()` — if all pushes led to valid pops, stack must be empty |
| 3 | Inner while loop handles **consecutive pops** triggered by one push |
| 4 | `j < n` guard in inner loop prevents out-of-bounds on `popped[j]` |

---

## ⚠️ Common Mistakes

- ❌ **Only popping once per push** → misses consecutive pops triggered by one push
- ❌ **Not checking `!st.empty()` in inner while** → `st.top()` on empty stack = crash
- ❌ **Returning `j == n`** instead of `st.empty()` → same thing here but less intuitive

---

## 🔁 After the While Loop

    What if pushed has elements left (i reaches n before j)?
    Remaining pops can't happen → st won't be empty → return false ✅

    What if all pushed elements processed but stack not empty?
    Some elements never matched a pop → st not empty → return false ✅
