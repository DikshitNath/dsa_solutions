# 🔢 Counting Bits

> **Platform:** LeetCode 338 | **Topic:** Dynamic Programming / Bit Manipulation | **Technique:** DP via Right-Shift Pattern

**Question Link:** https://leetcode.com/problems/counting-bits/

---

## 📌 Problem Summary

Given an integer `n`, return an array `ans` of length `n+1` where `ans[i]` is the number of `1`s in the binary representation of `i`.

```
n=5 → [0, 1, 1, 2, 1, 2]

i=0: 000 → 0 ones
i=1: 001 → 1 one
i=2: 010 → 1 one
i=3: 011 → 2 ones
i=4: 100 → 1 one
i=5: 101 → 2 ones
```

---

## 💡 Core Intuition — Right Shift DP

**Key observation:** Right-shifting a number by 1 (i.e., `i >> 1` = `i/2`) removes the **least significant bit**. So:

```
bits(i) = bits(i >> 1) + (i & 1)
        = bits(i / 2)  + (i % 2)
```

- `i/2` (right shift) — same number but with LSB removed
- `i%2` — the LSB itself (0 or 1)

> 🔑 Since we compute `ans[0..n]` left to right, `ans[i/2]` is always already computed when we need it — classic DP reuse.

---

## 🔍 Why This Works — Binary Pattern

```
Number | Binary | i/2 | bits(i/2) | i%2 | bits(i)
-------|--------|-----|-----------|-----|--------
0      | 0000   |  0  |     0     |  0  |   0
1      | 0001   |  0  |     0     |  1  |   1
2      | 0010   |  1  |     1     |  0  |   1
3      | 0011   |  1  |     1     |  1  |   2
4      | 0100   |  2  |     1     |  0  |   1
5      | 0101   |  2  |     1     |  1  |   2
6      | 0110   |  3  |     2     |  0  |   2
7      | 0111   |  3  |     2     |  1  |   3
8      | 1000   |  4  |     1     |  0  |   1

Shifting right = chopping off the last bit. Count it separately with i%2.
```

---

## 💻 Your Solution

```cpp
class Solution {
public:
    vector<int> countBits(int n) {
        vector<int> ans(n + 1);
        ans[0] = 0;

        for (int i = 1; i <= n; i++) {
            if (i % 2 == 0)
                ans[i] = ans[i / 2];       // even: LSB=0, same bits as i/2
            else
                ans[i] = ans[i / 2] + 1;   // odd:  LSB=1, one more than i/2
        }

        return ans;
    }
};
```

### 💡 One-Line Equivalent

```cpp
// Combines both branches into one expression:
ans[i] = ans[i / 2] + (i % 2);
// or using bit ops (faster):
ans[i] = ans[i >> 1] + (i & 1);
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **`bits(i) = bits(i/2) + (i%2)`** — the core recurrence |
| 2 | **Right shift removes LSB** — the remaining bits = `i/2`, the removed bit = `i%2` |
| 3 | **Prefer `i >> 1` and `i & 1`** over `/2` and `%2` — bitwise ops are faster |
| 4 | **`n==0` guard unnecessary** — `vector<int>(n+1)` initializes `ans[0]=0`, loop starts at 1 |
| 5 | Reuse of previous results (`ans[i/2]`) is what makes this DP |

## ⚠️ Common Mistakes

- ❌ **Brute force per number** → O(N log N), not O(N)
- ❌ **`ans[i] = ans[i-1] + 1` for odd** → works locally but breaks pattern for even numbers
- ❌ **Forgetting `ans[0] = 0`** → initialized by default in C++ vector, but be explicit for clarity

## 🔁 Three Equivalent Formulations

```cpp
// Version 1 — Your code (if-else, division/modulo)
ans[i] = (i % 2 == 0) ? ans[i/2] : ans[i/2] + 1;

// Version 2 — One-liner (division/modulo)
ans[i] = ans[i/2] + (i%2);

// Version 3 — Bitwise (fastest, idiomatic)
ans[i] = ans[i>>1] + (i&1);
```

All three are mathematically identical. Version 3 is preferred in competitive programming.

---

## 🔁 Alternative DP — Offset / Highest Power of 2

```cpp
// dp[i] = 1 + dp[i - offset], where offset = largest power of 2 ≤ i
vector<int> ans(n + 1);
int offset = 1;

for (int i = 1; i <= n; i++) {
    if (offset * 2 == i) offset = i;   // update offset at each power of 2
    ans[i] = 1 + ans[i - offset];
}
```

```
offset meaning:
  i=1: offset=1 (2^0)  → dp[1] = 1 + dp[0] = 1
  i=2: offset=2 (2^1)  → dp[2] = 1 + dp[0] = 1
  i=3: offset=2         → dp[3] = 1 + dp[1] = 2
  i=4: offset=4 (2^2)  → dp[4] = 1 + dp[0] = 1
  i=5: offset=4         → dp[5] = 1 + dp[1] = 2
```

Both give same result — `i>>1` version is cleaner.
