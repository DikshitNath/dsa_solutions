# ✏️ Words Within Two Edits of Dictionary

> **Platform:** LeetCode 2452 | **Topic:** Strings / Brute Force | **Technique:** Pairwise Hamming Distance Check

**Question Link:** https://leetcode.com/problems/words-within-two-edits-of-dictionary/

---

## 📌 Problem Summary

Given two arrays of equal-length lowercase words, return all `queries` words that match **at least one** `dictionary` word with **at most 2 differing positions**.

```
queries    = ["word", "note", "ants"]
dictionary = ["wood", "joke", "nots"]

"word" vs "wood" → 1 diff  → keep
"note" vs "nots" → 1 diff  → keep
"ants" vs any     → more than 2 diffs → discard
```

> 🔑 This is a **Hamming distance ≤ 2** check between every query and every dictionary word.

---

## 💡 Core Intuition

For each query word, compare it with each dictionary word character-by-character. Count how many positions differ. If the count is at most 2 for any dictionary word, keep that query.

> 🧠 Since all words have the same length, you never need edit distance DP — a simple mismatch count is enough.

---

## 🔍 Why the Early Break Works

Once `diff > 2`, that pair can no longer match. There is no need to continue comparing remaining characters — the query already fails against that dictionary word.

Similarly, once a query matches **one** dictionary word within 2 edits, you can immediately add it to the answer and break out of the inner loop.

---

## 🪜 Algorithm Steps

1. Initialize `ans` as empty.
2. For each `query` in `queries`:
   - Compare it with each word `s` in `dictionary`.
   - Count differing characters.
   - If `diff > 2`, stop checking that pair.
   - If `diff <= 2`, add `query` to `ans` and break.
3. Return `ans`.

---

## 🧩 Dry Run

```
queries    = ["word", "note", "ants"]
dictionary = ["wood", "joke", "nots"]

query = "word"
  compare with "wood":
    w==w, o==o, r!=o (diff=1), d==d → diff=1 ≤ 2 → keep "word"

query = "note"
  compare with "wood": diff > 2 → fail
  compare with "joke": diff > 2 → fail
  compare with "nots": n==n, o==o, t==t, e!=s → diff=1 ≤ 2 → keep "note"

query = "ants"
  compare with all dictionary words → each diff > 2 → discard

ans = ["word", "note"]
```

---

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<string> twoEditWords(vector<string>& queries, vector<string>& dictionary) {
        vector<string> ans;

        for (string query : queries) {
            for (string s : dictionary) {
                int diff = 0;

                for (int i = 0; i < (int)query.size(); i++) {
                    if (query[i] != s[i]) {
                        diff++;
                    }
                    if (diff > 2) break;
                }

                if (diff <= 2) {
                    ans.push_back(query);
                    break;
                }
            }
        }

        return ans;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Same length words** → compare positions directly, no edit-DP needed |
| 2 | **`diff > 2` break early** — saves unnecessary character checks |
| 3 | **`break` after match** — each query only needs one dictionary match |
| 4 | This is essentially **Hamming distance ≤ 2** |
| 5 | Brute force is acceptable because constraints are small |

---

## ⚠️ Common Mistakes

- ❌ **Using edit distance DP** → overkill and much slower than needed
- ❌ **Forgetting same-length guarantee** → if lengths varied, this approach would not work
- ❌ **Not breaking when `diff > 2`** → wasted work
- ❌ **Not breaking after a match** → duplicates in answer or extra work

---

## 🔁 Why This Is Not Edit Distance

```cpp
// Edit distance allows insert/delete/replace.
// This problem only allows replacing letters, and only counts positions that differ.

// Because all words have equal length:
// number of replacements needed = number of mismatched positions
// So just count mismatches.
```

That’s why the code is short and direct — no dynamic programming required.
