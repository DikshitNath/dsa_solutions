# 🔤 Group Anagrams

> **Platform:** LeetCode | **Topic:** String / HashMap | **Technique:** Sorted Key Grouping

**Question Link:** [https://leetcode.com/problems/group-anagrams/](https://leetcode.com/problems/group-anagrams/)

---

## 📌 Problem Summary

Given an array of strings `strs`, group all **anagrams** together and return them as a list of groups. Anagrams are strings that contain the same characters in any order.

    Input:  ["eat","tea","tan","ate","nat","bat"]
    Output: [["eat","tea","ate"], ["tan","nat"], ["bat"]]

---

## 💡 Core Intuition

Two strings are anagrams if and only if their **sorted versions are identical**. Use the sorted string as a **hash map key** — all anagrams map to the same key and get grouped together automatically.

> 🗝️ **Analogy:** Sort the letters of each word alphabetically to get its "fingerprint". Words with the same fingerprint are anagrams — bucket them together.

    "eat" → sorted → "aet"
    "tea" → sorted → "aet"   ← same key → same group ✅
    "tan" → sorted → "ant"   ← different key → different group

---

## 🪜 Algorithm Steps

1. 🔁 For each string `s` in `strs`:
   - Sort a copy of `s` → `temp`
   - Use `temp` as key → push original `s` into `mp[temp]`
2. 🗂️ Collect all values from the map into `ans`
3. 📤 Return `ans`

---

## 🧩 Code Walkthrough

### Dry Run Example

    strs = ["eat", "tea", "tan", "ate", "nat", "bat"]

    "eat" → sorted "aet" → mp["aet"] = ["eat"]
    "tea" → sorted "aet" → mp["aet"] = ["eat","tea"]
    "tan" → sorted "ant" → mp["ant"] = ["tan"]
    "ate" → sorted "aet" → mp["aet"] = ["eat","tea","ate"]
    "nat" → sorted "ant" → mp["ant"] = ["tan","nat"]
    "bat" → sorted "abt" → mp["abt"] = ["bat"]

    Map:
    "aet" → ["eat", "tea", "ate"]
    "ant" → ["tan", "nat"]
    "abt" → ["bat"]

    Output: [["eat","tea","ate"], ["tan","nat"], ["bat"]] ✅

### Pseudocode

    groupAnagrams(strs):
        mp = hashmap

        for s in strs:
            temp = sort(s)          // sorted copy = canonical key
            mp[temp].push(s)        // group by key

        for each group in mp:
            ans.push(group)

        return ans

### Full C++ Solution

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> mp;
        vector<vector<string>> ans;

        for (int i = 0; i < strs.size(); i++) {
            string temp = strs[i];          // copy original
            sort(begin(temp), end(temp));   // sort copy as key

            mp[temp].push_back(strs[i]);    // group originals by sorted key
        }

        for (auto it : mp) {
            ans.push_back(it.second);       // collect all groups
        }

        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N × K log K) | N strings, each sorted in O(K log K) where K = max string length |
| 🧠 **Space** | O(N × K) | Map stores all strings with their sorted keys |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Sorted string = canonical anagram key** — all anagrams share the same sorted form |
| 2 | Sort a **copy** (`temp`), not the original — originals must be preserved in the output |
| 3 | `unordered_map` gives O(1) average lookup — faster than `map`'s O(log N) |
| 4 | Map values are automatically `vector<string>` — no manual group creation needed |

---

## ⚠️ Common Mistakes

- ❌ **Sorting the original string** instead of a copy → destroys input data
- ❌ **Using `map` instead of `unordered_map`** → works but slower (O(N K log K log N))
- ❌ **Iterating `mp` with `auto it`** (by value) instead of `auto& it` → copies each vector unnecessarily

---

## 🚀 O(NK) Alternative — Frequency Key

Instead of sorting (O(K log K)), build a frequency count key (O(K)):

    For each string, count frequency of each of 26 letters.
    Encode as a string: "a2b0c1..." → use as key.

    "eat" → {e:1, a:1, t:1} → "#1#0#0#0#1#...#1#..." → same as "tea" ✅

    Time: O(N × K)  — better when strings are long
    Space: O(N × K)
