# 🌧️ Trapping Rain Water

> **Platform:** LeetCode | **Topic:** Array | **Technique:** Precomputed Left & Right Max Arrays

**Question Link:** [https://leetcode.com/problems/trapping-rain-water/](https://leetcode.com/problems/trapping-rain-water/)

---

## 📌 Problem Summary

Given an array `height` representing an elevation map where each bar has width 1, compute how much **rainwater can be trapped** between the bars after it rains.

---

## 💡 Core Intuition

Water trapped at any index `i` depends on:
- The **tallest bar to its left** (including itself)
- The **tallest bar to its right** (including itself)

Water level at `i` = `min(leftMax[i], rightMax[i])` — the **shorter of the two walls**.
Water trapped at `i` = water level - actual height = `min(leftMax[i], rightMax[i]) - height[i]`

> 🪣 **Analogy:** Imagine each bar is a wall. Water can only fill up to the height of the **shorter surrounding wall**. Anything above the bar itself is trapped water.

---

## 🤔 Why `min(leftMax, rightMax)`?

Water can't rise above the **shorter** of the two boundary walls — it would spill over. So the water level at any point is capped by the minimum of the two.

    Water at i = min(leftMax[i], rightMax[i]) - height[i]

If this value is negative (current bar is taller than a wall), it means no water is trapped — but this never happens since `leftMax[i] >= height[i]` and `rightMax[i] >= height[i]` always.

---

## 🪜 Algorithm Steps

1. 🏗️ Build `leftMax[]` — for each `i`, the max height from index `0` to `i`
2. 🏗️ Build `rightMax[]` — for each `i`, the max height from index `i` to `n-1`
3. 🔁 For each index `i`:
   - Compute `h = min(leftMax[i], rightMax[i]) - height[i]`
   - Add `h` to total `sum`
4. 📤 Return `sum`

### How leftMax is Built

    left[0] = height[0]
    for i = 1 to n-1:
        left[i] = max(left[i-1], height[i])

    → Each cell = max of all heights seen so far from the left

### How rightMax is Built

    right[n-1] = height[n-1]
    for i = n-2 to 0:
        right[i] = max(right[i+1], height[i])

    → Each cell = max of all heights seen so far from the right

### Pseudocode

    trap(height):
        leftMax  = buildLeftMax(height)
        rightMax = buildRightMax(height)

        sum = 0
        for i in 0 to n-1:
            sum += min(leftMax[i], rightMax[i]) - height[i]

        return sum

### Full C++ Solution

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int n = height.size();

        vector<int> leftMax  = getLeftMaxArr(height, n);
        vector<int> rightMax = getRightMaxArr(height, n);

        int sum = 0;
        for (int i = 0; i < n; i++) {
            int h = min(leftMax[i], rightMax[i]) - height[i];
            sum += h;
        }
        return sum;
    }

    vector<int> getLeftMaxArr(vector<int>& height, int n) {
        vector<int> left(n);
        left = height;
        for (int i = 1; i < n; i++)
            left[i] = max(left[i-1], height[i]);
        return left;
    }

    vector<int> getRightMaxArr(vector<int>& height, int n) {
        vector<int> right(n);
        right[n-1] = height[n-1];
        for (int i = n-2; i >= 0; i--)
            right[i] = max(right[i+1], height[i]);
        return right;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | Water at `i` = `min(leftMax[i], rightMax[i]) - height[i]` is the **core formula** |
| 2 | `leftMax[i]` always `>= height[i]` so water is **never negative** |
| 3 | Breaking into helper functions makes logic clean and testable |
| 4 | This can be further optimized to O(1) space using the **two pointer approach** |

---

## ⚠️ Common Mistakes

- ❌ **Using `max` instead of `min`** → water would overflow the shorter wall
- ❌ **Not including current bar in leftMax/rightMax** → formula breaks at edge bars
- ❌ **Initializing leftMax/rightMax with 0** instead of `height[0]`/`height[n-1]`

---

## 🔄 Two Approaches Compared

| Feature | Precomputed Arrays (this) | Two Pointers |
|---------|--------------------------|--------------|
| Time | O(N) | O(N) |

| Passes | 3 passes | 1 pass |
