# 🔍 Find Original Array from Doubled Array

> **Platform:** LeetCode | **Topic:** Array | **Technique:** Sorting + Frequency Map (Greedy)

**Question Link:** [https://leetcode.com/problems/find-original-array-from-doubled-array/](https://leetcode.com/problems/find-original-array-from-doubled-array/)

---

## 📌 Problem Summary

An original array was transformed into a **doubled array** by appending the double of every element. Given the shuffled doubled array `changed`, recover and return the **original array**. If it's not valid, return `{}`.

    Original: [1, 3, 4]
    Doubled:  [1, 2, 3, 4, 6, 8]  (each element + its double, shuffled)

---

## 💡 Core Intuition

Sort the array so smaller numbers come first. For each number `num`, greedily try to **pair it with `num*2`** using a frequency map. If we can always pair every element with its double, we've found the original array.

> 🧩 **Analogy:** Think of it like matching socks. Sort them by size. Always try to match the smallest unmatched sock with one exactly twice its size. If you can't, the pairing is invalid.

---

## 🤔 Why Sort First?

Sorting guarantees we always process the **smaller number before its double**. This prevents a number from being incorrectly consumed as a double of something else.

    Without sort: [4, 2, 1] → might try to pair 4 with 8 before seeing 2
    With sort:    [1, 2, 4] → correctly pairs 1→2, then 2→4 ✅

---

## 🪜 Algorithm Steps

1. 🚫 If `n` is **odd** → return `{}` (can't split evenly)
2. 📊 **Sort** `changed` in ascending order
3. 🗺️ Build a **frequency map** of all elements
4. 🔁 Iterate through sorted `changed`:
   - `freq[num] == 0` → already used, **skip**
   - `freq[num*2] == 0` → no valid pair → **return `{}`**
   - Otherwise → add `num` to answer, decrement both `freq[num]` and `freq[num*2]`
5. 📤 Return answer

## 🧩 Code Walkthrough

### Dry Run Example

    changed = [3, 1, 3, 6, 1, 2]
    sorted  = [1, 1, 2, 3, 3, 6]
    freq    = {1:2, 2:1, 3:2, 6:1}

    num=1 → dbl=2,  freq[2]=1 ✅ → ans=[1],  freq={1:1, 2:0, 3:2, 6:1}
    num=1 → dbl=2,  freq[2]=0 ✅ → ans=[1],  freq={1:0, 2:0... wait
    
    Actually:
    num=1 → freq[1]=2, dbl=2, freq[2]=1 → ans=[1], freq[1]=1, freq[2]=0
    num=1 → freq[1]=1, dbl=2, freq[2]=0 → ❌ return {}

    changed = [1, 3, 4, 2, 6, 8]
    sorted  = [1, 2, 3, 4, 6, 8]
    freq    = {1:1, 2:1, 3:1, 4:1, 6:1, 8:1}

    num=1 → dbl=2  ✅ → ans=[1],     freq[1]=0, freq[2]=0
    num=2 → freq[2]=0 → skip
    num=3 → dbl=6  ✅ → ans=[1,3],   freq[3]=0, freq[6]=0
    num=4 → dbl=8  ✅ → ans=[1,3,4], freq[4]=0, freq[8]=0
    num=6 → freq[6]=0 → skip
    num=8 → freq[8]=0 → skip

    Output: [1, 3, 4] ✅

### Special Case: `num = 0`

    num=0, dbl=0*2=0
    Both num and dbl point to the SAME key in the map!
    freq[0] must be >= 2 for a valid pair.
    → The code handles this correctly since freq[0]-- twice still works
      as long as freq[0] started at 2 or more.

### Pseudocode

    findOriginalArray(changed):
        if n is odd → return {}

        sort(changed)
        build freq map

        for num in changed:
            if freq[num] == 0 → skip
            if freq[num*2] == 0 → return {}

            ans.push(num)
            freq[num]--
            freq[num*2]--

        return ans

### Full C++ Solution

```cpp
class Solution {
public:
    vector<int> findOriginalArray(vector<int>& changed) {
        int n = changed.size();
        if (n % 2 != 0) return {};          // must be even

        sort(changed.begin(), changed.end());

        unordered_map<int, int> freq;
        for (int i : changed) freq[i]++;

        vector<int> ans;
        for (int num : changed) {
            if (freq[num] == 0) continue;   // already paired, skip

            int dbl = num * 2;
            if (freq.find(dbl) == freq.end() || freq[dbl] == 0)
                return {};                  // no valid pair exists

            ans.push_back(num);
            freq[num]--;
            freq[dbl]--;
        }
        return ans;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Sort first** — ensures smaller element is always processed before its double |
| 2 | **Skip when `freq[num] == 0`** — element was already consumed as a double |
| 3 | **Greedy pairing** always works after sorting — no backtracking needed |
| 4 | **Edge case: `num = 0`** — pairs with itself, needs `freq[0] >= 2` |

---

## ⚠️ Common Mistakes

- ❌ **Not sorting** → smaller elements may be incorrectly consumed as doubles
- ❌ **Forgetting `freq[num] == 0` skip** → double-counts already paired elements
- ❌ **Not checking odd length** → odd-sized arrays can never be valid
- ❌ **Using `freq[dbl] == 0` without checking existence** → unordered_map creates key with 0 on access

---

## 🔢 Why Greedy Works Here

    After sorting, for the smallest remaining unpaired element `num`:
    - It CANNOT be the double of anything smaller (all smaller elements already paired)
    - So it MUST be paired with num*2
    - If num*2 doesn't exist → invalid input

    This greedy choice is always forced → no ambiguity → no backtracking needed.
