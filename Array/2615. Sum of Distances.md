# 📐 Sum of Distances

> **Platform:** LeetCode 2615 | **Topic:** Arrays / Prefix Sum | **Technique:** Two-Pass Prefix Count + Index Sum

**Question Link:** https://leetcode.com/problems/sum-of-distances/

---

## 📌 Problem Summary

Given a 0-indexed array `nums`, return an array `ans` where `ans[i]` is the sum of `|i - j|` for all `j` such that `nums[j] == nums[i]`.

```
nums = [1, 3, 1, 1, 2]

For index 0 (value=1, same-value indices: 0,2,3):
  |0-0| + |0-2| + |0-3| = 0+2+3 = 5

For index 2 (value=1, same-value indices: 0,2,3):
  |2-0| + |2-2| + |2-3| = 2+0+1 = 3

ans = [5, 0, 3, 4, 0]
```

---

## 💡 Core Intuition — Split Into Left + Right

For each index `i`, the sum of distances to all same-value indices `j` splits into:

```
Left contribution  (j < i):  sum of (i - j) = freq_left * i - sum_left
Right contribution (j > i):  sum of (j - i) = sum_right - freq_right * i
ans[i] = (freq_left * i - sum_left) + (sum_right - freq_right * i)
```

Two passes:
- **Left-to-right pass** computes the left contribution for each `i`
- **Right-to-left pass** computes the right contribution for each `i`

---

## 🔍 The Left-Pass Formula

When processing index `i` (left to right):
- `indexCount[v]` = how many times value `v` appeared **before** `i`
- `indexSum[v]` = sum of all previous indices where value `v` appeared

```
Left contribution = sum of (i - j) for all j < i where nums[j] == v
                  = freq * i - sum   (distribute the subtraction)
```

**After** recording ans contribution, update maps with index `i`.

---

## 🔍 The Right-Pass Formula

When processing index `i` (right to left):
- `indexCount[v]` = how many times value `v` appeared **after** `i`
- `indexSum[v]` = sum of all future indices where value `v` appeared

```
Right contribution = sum of (j - i) for all j > i where nums[j] == v
                   = sum - freq * i
```

---

## 🪜 Algorithm Steps

**Left-to-right pass:**
1. For each `i` from 0 to n-1:
   - `ans[i] += indexCount[nums[i]] * i - indexSum[nums[i]]`
   - Update: `indexSum[nums[i]] += i`, `indexCount[nums[i]]++`

**Right-to-left pass:**
2. Clear both maps. For each `i` from n-1 to 0:
   - `ans[i] += indexSum[nums[i]] - indexCount[nums[i]] * i`
   - Update: `indexSum[nums[i]] += i`, `indexCount[nums[i]]++`

---

## 🧩 Dry Run

```
nums = [1, 3, 1, 1, 2]
ans  = [0, 0, 0, 0, 0]

--- LEFT PASS ---
i=0, v=1: freq=0, sum=0 → ans[0] += 0*0-0=0 | update: sum[1]=0, cnt[1]=1
i=1, v=3: freq=0, sum=0 → ans[1] += 0        | update: sum[3]=1, cnt[3]=1
i=2, v=1: freq=1, sum=0 → ans[2] += 1*2-0=2  | update: sum[1]=2, cnt[1]=2
i=3, v=1: freq=2, sum=2 → ans[3] += 2*3-2=4  | update: sum[1]=5, cnt[1]=3
i=4, v=2: freq=0, sum=0 → ans[4] += 0        | update: sum[2]=4, cnt[2]=1

ans = [0, 0, 2, 4, 0]  (left contributions only)

--- RIGHT PASS (clear maps) ---
i=4, v=2: freq=0, sum=0 → ans[4] += 0-0=0    | update: sum[2]=4, cnt[2]=1
i=3, v=1: freq=0, sum=0 → ans[3] += 0-0=0    | update: sum[1]=3, cnt[1]=1
i=2, v=1: freq=1, sum=3 → ans[2] += 3-1*2=1  | update: sum[1]=5, cnt[1]=2
i=1, v=3: freq=0, sum=0 → ans[1] += 0-0=0    | update: sum[3]=1, cnt[3]=1
i=0, v=1: freq=2, sum=5 → ans[0] += 5-2*0=5  | update: sum[1]=5, cnt[1]=3

ans = [0+5, 0+0, 2+1, 4+0, 0+0] = [5, 0, 3, 4, 0] ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<long long> distance(vector<int>& nums) {
        int n = nums.size();
        vector<long long> ans(n, 0);
        unordered_map<int, long long> indexSum, indexCount;

        // Left pass: left contribution
        for (int i = 0; i < n; i++) {
            long long freq = indexCount[nums[i]];
            long long sum  = indexSum[nums[i]];
            ans[i] += freq * i - sum;
            indexSum[nums[i]]   += i;
            indexCount[nums[i]]++;
        }

        indexSum.clear();
        indexCount.clear();

        // Right pass: right contribution
        for (int i = n - 1; i >= 0; i--) {
            long long freq = indexCount[nums[i]];
            long long sum  = indexSum[nums[i]];
            ans[i] += sum - freq * i;
            indexSum[nums[i]]   += i;
            indexCount[nums[i]]++;
        }

        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ Time | O(N) | Two passes, O(1) hashmap ops per element |
| 🧠 Space | O(N) | Hashmaps store at most N distinct values |

> 🏆 Optimal — brute force O(N²) would TLE for large inputs.

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Split `|i-j|` into left + right** — avoids absolute value complexity |
| 2 | **Left: `freq*i - sum`** — factor out `i` from `(i-j₁) + (i-j₂) + ...` |
| 3 | **Right: `sum - freq*i`** — factor out `i` from `(j₁-i) + (j₂-i) + ...` |
| 4 | **Update AFTER computing ans[i]** — maps must hold only previously seen indices |
| 5 | **`long long`** — index sums can overflow `int` for large inputs |

---

## ⚠️ Common Mistakes

- ❌ **Updating maps BEFORE reading freq/sum** → includes current index in its own contribution → wrong
- ❌ **Using `int` instead of `long long`** → index sums overflow for large N
- ❌ **Not clearing maps between passes** → right pass counts left-pass indices → wrong totals
- ❌ **Single pass only** → misses either left or right contribution

---

## 🔁 Why Two Passes Instead of One?

```
For ans[i] we need:
  Left:  all j < i where nums[j]==v  → only known after processing left to right
  Right: all j > i where nums[j]==v  → only known after processing right to left

These two sets are computed in opposite directions.
A single pass can't know both simultaneously.

Exception: if you pre-group indices by value, you CAN do it in one forward pass
(see alternative below), but two passes is simpler to understand.
```

---

## 🔁 Alternative — Pre-group by Value

```cpp
// Group indices by value first, then use prefix sums within each group
unordered_map<int, vector<int>> groups;
for (int i = 0; i < n; i++) groups[nums[i]].push_back(i);

for (auto& [v, idx] : groups) {
    // Build prefix sum of indices within this group
    long long prefixSum = 0;
    for (int k = 0; k < idx.size(); k++) {
        // Left contribution: k elements to the left
        ans[idx[k]] += (long long)k * idx[k] - prefixSum;
        prefixSum += idx[k];
    }
    prefixSum = 0;
    for (int k = idx.size()-1; k >= 0; k--) {
        // Right contribution
        ans[idx[k]] += prefixSum - (long long)(idx.size()-1-k) * idx[k];
        prefixSum += idx[k];
    }
}
```

Same O(N) complexity, different code style. Your two-pass approach is cleaner.
