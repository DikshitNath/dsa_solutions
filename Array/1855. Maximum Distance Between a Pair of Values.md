# 📏 Maximum Distance Between a Pair of Values

> **Platform:** LeetCode 1855 | **Topic:** Two Pointers | **Technique:** Two Pointer on Non-Increasing Arrays

**Question Link:** https://leetcode.com/problems/maximum-distance-between-a-pair-of-values/

---

## 📌 Problem Summary

You are given two **non-increasing** arrays `nums1` and `nums2`. Find the maximum value of `j - i` such that:
- `0 <= i <= j`
- `nums1[i] <= nums2[j]`

Return the maximum distance. If no valid pair exists, return `0`.

```
nums1 = [55, 30, 5, 4, 2]
nums2 = [100, 20, 10, 10, 5]

Valid pairs: (0,0),(2,2),(2,3),(2,4),(3,3),(3,4),(4,4)
Maximum distance = 2 with pair (2,4): nums1[2]=5 <= nums2[4]=5 ✅
```

---

## 💡 Core Intuition — Two Pointer

Both arrays are **non-increasing** — values decrease as indices increase. This allows a greedy two-pointer approach:

- If `nums1[i] <= nums2[j]` → **valid pair!** Record distance `j-i`, try to increase it by moving `j` right
- If `nums1[i] > nums2[j]` → condition violated, moving `j` further right only makes `nums2[j]` smaller (worse) → **must move `i` right** to get a smaller `nums1[i]`

> 🔑 Key insight: once `nums1[i] > nums2[j]`, there's no point advancing `j` — `nums2` is non-increasing, so all values to the right are ≤ `nums2[j]`, still violating the condition with the same `i`.

---

## 🤔 Why Can We Always Move `i` Forward When Stuck?

```
nums1 is non-increasing: nums1[i] >= nums1[i+1]

If nums1[i] > nums2[j]:
  nums2[j+1] <= nums2[j] < nums1[i]   → still invalid with i
  nums2[j+1] <= nums2[j] < nums1[i]   → but nums1[i+1] <= nums1[i]
  → moving i forward reduces nums1[i], possibly satisfying condition

Also note: i always stays ≤ j because:
  - j starts at 0 and only moves right
  - i only moves right when stuck
  - if i would surpass j, the while condition keeps them in bounds
```

---

## 🪜 Algorithm Steps

1. 🏁 `i = 0, j = 0, ans = 0`
2. 🔁 While `i < nums1.size() && j < nums2.size()`:
   - `nums1[i] > nums2[j]` → condition violated → `i++`
   - `nums1[i] <= nums2[j]` → valid pair → `ans = max(ans, j-i)`, `j++`
3. 📤 Return `ans`

## 🧩 Dry Run

```
nums1 = [55, 30, 5, 4, 2]
nums2 = [100, 20, 10, 10, 5]
        idx:   0   1   2   3  4

i=0, j=0: nums1[0]=55 <= nums2[0]=100 ✅ → ans=max(0,0-0)=0, j++
i=0, j=1: nums1[0]=55 > nums2[1]=20   ❌ → i++
i=1, j=1: nums1[1]=30 > nums2[1]=20   ❌ → i++
i=2, j=1: nums1[2]=5  <= nums2[1]=20  ✅ → ans=max(0,1-2)=-1→0, j++

Wait: j-i = 1-2 = -1 → max(0,-1) = 0, j++

i=2, j=2: nums1[2]=5  <= nums2[2]=10  ✅ → ans=max(0,2-2)=0, j++
i=2, j=3: nums1[2]=5  <= nums2[3]=10  ✅ → ans=max(0,3-2)=1, j++
i=2, j=4: nums1[2]=5  <= nums2[4]=5   ✅ → ans=max(1,4-2)=2, j++

j=5 >= nums2.size()=5 → exit loop

return 2 ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    int maxDistance(vector<int>& nums1, vector<int>& nums2) {
        int i = 0, j = 0;
        int ans = 0;

        while (i < (int)nums1.size() && j < (int)nums2.size()) {
            if (nums1[i] > nums2[j])
                i++;                         // condition violated, advance i
            else {
                ans = max(ans, j - i);       // valid pair, record distance
                j++;                         // try to extend further right
            }
        }

        return ans;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Both arrays non-increasing** — enables directional two-pointer moves |
| 2 | **`i++` when invalid** — reduces `nums1[i]`, only way to fix condition |
| 3 | **`j++` when valid** — tries to increase `j-i` distance |
| 4 | **`i` never exceeds `j`** — guaranteed by pointer logic + loop condition |
| 5 | **`j - i` can be 0 or negative (same index)** — `max(ans, j-i)` handles it cleanly |

---

## ⚠️ Common Mistakes

- ❌ **Moving `j++` when invalid** → `nums2` is non-increasing, `j++` makes it worse
- ❌ **Not handling signed/unsigned comparison** → `nums1.size()` returns `size_t` (unsigned); if `i` or `j` are `int`, cast needed for large inputs
- ❌ **`ans = max(ans, j-i)` after `i++`** → recording distance on invalid pair
- ❌ **Forgetting `j-i` can be 0** — a pair at same index `(k,k)` has distance 0, valid

---

## 🔁 Why Not Move `j` When Condition Fails?

```
nums1[i] > nums2[j]: condition FAILS
  Moving j++ → nums2[j+1] <= nums2[j]  (non-increasing)
             → nums2[j+1] < nums1[i]   (still fails or worse)
  → j++ doesn't help with current i ❌

  Moving i++ → nums1[i+1] <= nums1[i]  (non-increasing)
             → nums1[i+1] might be <= nums2[j]
  → i++ might fix the condition ✅
```

## 🆚 Two Pointer vs Binary Search Approach

| Feature | Two Pointer (your code) | Binary Search |
|---------|------------------------|---------------|
| Time | O(M + N) ✅ | O(M log N) |
| Space | O(1) | O(1) |
| Intuition | Greedy pointer movement | For each i, find max valid j |
| Code length | Short | Longer |
| Preferred | Always (strictly better) | Interview alternative |

**Binary Search sketch (for reference):**
```cpp
for (int i = 0; i < nums1.size(); i++) {
    // find rightmost j where nums2[j] >= nums1[i], starting from i
    int lo = i, hi = nums2.size() - 1, best = i - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums2[mid] >= nums1[i]) { best = mid; lo = mid + 1; }
        else hi = mid - 1;
    }
    if (best >= i) ans = max(ans, best - i);
}
```
