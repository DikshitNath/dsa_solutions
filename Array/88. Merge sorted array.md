# 🔀 Merge Sorted Array

> **Platform:** LeetCode | **Topic:** Array / Two Pointers | **Technique:** Reverse Two-Pointer Merge

**Question Link:** [https://leetcode.com/problems/merge-sorted-array/](https://leetcode.com/problems/merge-sorted-array/)

---

## 📌 Problem Summary

Given two sorted arrays `nums1` (size `m+n`, last `n` spots are `0`) and `nums2` (size `n`), merge `nums2` into `nums1` **in-place** in sorted order.

---

## 💡 Core Intuition

Instead of merging from the front (which would require shifting elements), merge **from the back**. The end of `nums1` has `n` empty slots — fill them with the **largest elements first** by comparing from the end of both arrays.

> 📦 **Analogy:** Two sorted stacks of papers. Instead of inserting from the top (which shuffles everything), place pages from the bottom — largest first — into the empty slots at the back. No shifting needed.

---

## 🤔 Why Merge From the Back?

Forward merging overwrites valid elements in `nums1` before they're used.
Backward merging writes into the **empty trailing zone** — no data is ever lost.

    nums1 = [1, 3, 5, 0, 0, 0]   ← slots after index m-1 are safe to overwrite
    nums2 = [2, 4, 6]

    Fill from k = m+n-1 = 5 downward → never touches unprocessed elements ✅

---

## 🪜 Algorithm Steps

1. 🏁 Set `i = m-1` (last valid in nums1), `j = n-1` (last in nums2), `k = m+n-1` (last slot)
2. 🔁 While both `i ≥ 0` and `j ≥ 0`:
   - If `nums1[i] > nums2[j]` → place `nums1[i]` at `k`, decrement `i` and `k`
   - Else → place `nums2[j]` at `k`, decrement `j` and `k`
3. 🔁 If `nums2` has leftovers (`j ≥ 0`) → copy remaining into `nums1`
4. ✅ If `nums1` has leftovers (`i ≥ 0`) → already in place, nothing to do

## 🧩 Code Walkthrough

### Dry Run Example

    nums1 = [1, 3, 5, 0, 0, 0],  m=3
    nums2 = [2, 4, 6],            n=3

    i=2, j=2, k=5
    nums1[2]=5 vs nums2[2]=6 → 6 wins → nums1[5]=6, j=1, k=4
    → [1, 3, 5, 0, 0, 6]

    nums1[2]=5 vs nums2[1]=4 → 5 wins → nums1[4]=5, i=1, k=3
    → [1, 3, 5, 0, 5, 6]

    nums1[1]=3 vs nums2[1]=4 → 4 wins → nums1[3]=4, j=0, k=2
    → [1, 3, 5, 4, 5, 6]

    nums1[1]=3 vs nums2[0]=2 → 3 wins → nums1[2]=3, i=0, k=1
    → [1, 3, 3, 4, 5, 6]

    nums1[0]=1 vs nums2[0]=2 → 2 wins → nums1[1]=2, j=-1, k=0
    → [1, 2, 3, 4, 5, 6]

    j < 0 → main loop ends
    i=0 ≥ 0 → while(i≥0): nums1[0]=nums1[0]=1, already in place

    Output: [1, 2, 3, 4, 5, 6] ✅

### Why the `while(i >= 0)` loop is usually a no-op

    If nums1 elements are leftover (i ≥ 0), they're already
    sitting in the correct positions at the front of nums1.
    The loop runs but writes nums1[i] back to nums1[k]
    where k == i — effectively a no-op in most cases.

    The while(j >= 0) loop DOES matter — nums2 elements
    must be explicitly copied into nums1.

### Pseudocode

    merge(nums1, m, nums2, n):
        i = m-1,  j = n-1,  k = m+n-1

        while i >= 0 AND j >= 0:
            if nums1[i] > nums2[j]:
                nums1[k--] = nums1[i--]
            else:
                nums1[k--] = nums2[j--]

        while j >= 0:               // leftover nums2 elements
            nums1[k--] = nums2[j--]

        // leftover nums1 elements already in place — no action needed

### Full C++ Solution

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        int i = m-1, j = n-1, k = m+n-1;   // start from the end

        while (i >= 0 && j >= 0) {
            if (nums1[i] > nums2[j])
                nums1[k--] = nums1[i--];    // place larger element at back
            else
                nums1[k--] = nums2[j--];
        }

        while (i >= 0) nums1[k--] = nums1[i--];  // nums1 leftovers
        while (j >= 0) nums1[k--] = nums2[j--];  // nums2 leftovers
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(M + N) | Each element from both arrays placed exactly once |
| 🧠 **Space** | O(1) | Fully in-place, no extra array needed |

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Merging from back** avoids overwriting unprocessed elements — key insight |
| 2 | `k = m+n-1` points to the last slot — always safe to write since it's in the empty zone |
| 3 | `while(j >= 0)` handles remaining `nums2` — **this is the only critical cleanup loop** |
| 4 | `while(i >= 0)` is technically correct but a no-op in practice |

---

## ⚠️ Common Mistakes

- ❌ **Merging from front** → overwrites valid nums1 elements before they're processed
- ❌ **Forgetting the `while(j >= 0)` loop** → leftover nums2 elements never copied
- ❌ **Starting `k = m+n`** (off by one) → writes out of bounds on first placement

---

## 🆚 Forward vs Backward Merge

| Feature | Forward Merge | Backward Merge (this) |
|---------|--------------|----------------------|
| Extra space needed | O(M) temp array | ✅ O(1) |
| Risk of overwrite | ❌ Yes | ✅ No |
| Direction | Left → Right | Right → Left |
| Complexity | O(M+N) | O(M+N) |
