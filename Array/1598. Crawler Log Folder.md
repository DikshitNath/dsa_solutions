# 📁 Crawler Log Folder

> **Platform:** LeetCode 1598 | **Topic:** Stack / Simulation | **Techniques:** Counter (O(1) space) + Stack (O(N) space)

**Question Link:** https://leetcode.com/problems/crawler-log-folder/

---

## 📌 Problem Summary

Given a list of folder operations, return the **minimum number of `"../"` operations** needed to return to the main (root) folder.

- `"../"` → move to parent (can't go above root)
- `"./"` → stay in current folder
- `"x/"` → move into child folder `x`

**Examples:**

- Input: `logs = ["d1/","d2/","../","d21/","./"]` → Output: `2`
- Input: `logs = ["d1/","../","../","../"]` → Output: `0` (can't go above root)

---

## 💡 Core Intuition

The **minimum operations to return to root = current depth**. Every folder entry increases depth, every `"../"` decreases it (floor 0), `"./"` is a no-op. The answer is simply the depth at the end.

> 🏢 **Analogy:** Count which floor of a building you're on. Each folder = go up one floor, `"../"` = go down one floor (can't go below ground). Minimum steps back = current floor number.

---

## 🔵 Approach 1 — Counter (Optimal)

### 💡 Intuition

Track depth as a single integer. No need to remember the actual path — only the **depth level** matters for the answer.

### 💻 Solution

```cpp
class Solution {
public:
    int minOperations(vector<string>& logs) {
        int depth = 0;

        for (string str : logs) {
            if (str == "../")      depth = max(depth - 1, 0); // go up, floor 0
            else if (str == "./")  continue;                  // stay, no-op
            else                   depth++;                   // enter folder
        }

        return depth;
    }
};
```

### 📊 Complexity

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ Time | O(N) | Single pass through logs |
| 🧠 Space | O(1) | Single integer counter |

---

## 🟢 Approach 2 — Stack (Intuitive)

### 💡 Intuition

Simulate the actual path using a stack. Push folder names, pop on `"../"`, ignore `"./"`. The stack size at the end = depth = answer.

### 💻 Solution

```cpp
class Solution {
public:
    int minOperations(vector<string>& logs) {
        stack<string> st;

        for (string str : logs) {
            if (str == "../") {
                if (!st.empty()) st.pop();   // go up if not at root
            }
            else if (str != "./") {
                st.push(str);                // enter folder
            }
        }

        return st.size();
    }
};
```

### 📊 Complexity

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ Time | O(N) | Single pass through logs |
| 🧠 Space | O(N) | Stack can hold all folder names |

## 🧩 Dry Run — Both Approaches

**Example:** `logs = ["d1/", "d2/", "../", "d21/", "./"]`

### Counter Approach:

| Operation | Depth | Note |
|-----------|-------|------|
| "d1/" | 1 | Enter folder |
| "d2/" | 2 | Enter folder |
| "../" | 1 | Go to parent |
| "d21/" | 2 | Enter folder |
| "./" | 2 | Stay (no-op) |

**Return:** `2` ✅

### Stack Approach:

| Operation | Stack | Note |
|-----------|-------|------|
| "d1/" | [d1] | Push |
| "d2/" | [d1, d2] | Push |
| "../" | [d1] | Pop |
| "d21/" | [d1, d21] | Push |
| "./" | [d1, d21] | Stay (no-op) |

**Return:** `st.size() = 2` ✅

---

## 🧩 Dry Run — Root Boundary

**Example:** `logs = ["d1/","../","../","../"]`

### Counter Approach:

| Operation | Depth | Note |
|-----------|-------|------|
| "d1/" | 1 | Enter folder |
| "../" | 0 | Go to parent (root) |
| "../" | 0 | `max(0-1, 0) = 0` (stay at root) |
| "../" | 0 | `max(0-1, 0) = 0` (stay at root) |

**Return:** `0` ✅

### Stack Approach:

| Operation | Stack | Note |
|-----------|-------|------|
| "d1/" | [d1] | Push |
| "../" | [] | Pop |
| "../" | [] | Empty, skip |
| "../" | [] | Empty, skip |

**Return:** `0` ✅

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Only depth matters** — not the actual path names → counter beats stack |
| 2 | **`max(depth-1, 0)`** — prevents going below root in counter approach |
| 3 | **`!st.empty()` before `st.pop()`** — prevents popping from empty stack |
| 4 | **`"./"` is a no-op** — `continue` in counter, simply not pushed in stack |
| 5 | **`st.size()` returns `size_t` (unsigned)** — safe to return as `int` here since size fits |

---

## ⚠️ Common Mistakes

- ❌ **`depth--` without `max(0,...)`** → depth goes negative → wrong answer
- ❌ **`st.pop()` without empty check** → runtime error on `"../"` at root
- ❌ **Pushing `"./"` onto stack** → inflates stack size → wrong answer
- ❌ **Returning `depth` for stack approach** → should return `st.size()`

---

## 🆚 Counter vs Stack

| Feature | Counter (Approach 1) | Stack (Approach 2) |
|---------|---------------------|-------------------|
| Space | O(1) ✅ | O(N) |
| Time | O(N) | O(N) |
| Stores actual path | ❌ | ✅ |
| Interview preference | Optimal answer | Shows stack intuition |
| When to use | Final answer only | Need to track full path |

> 📝 Always lead with the counter approach in interviews — then mention the stack as an alternative that uses O(N) space but mirrors the actual filesystem more closely.
