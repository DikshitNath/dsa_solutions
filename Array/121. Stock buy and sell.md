# 📈 Best Time to Buy and Sell Stock

> **Platform:** LeetCode | **Topic:** Array | **Technique:** Greedy (Track Running Minimum)

**Question Link:** [https://leetcode.com/problems/best-time-to-buy-and-sell-stock/](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/)

---

## 📌 Problem Summary

Given an array `prices` where `prices[i]` is the stock price on day `i`, find the **maximum profit** from one single buy-sell transaction. You must buy **before** you sell. Return `0` if no profit is possible.

---

## 💡 Core Intuition

Track the **minimum price seen so far** as you scan left to right. At each day, the best profit you could make if you **sell today** = `prices[i] - minPrice`. Keep updating the global maximum of this.

> 📉📈 **Analogy:** As you walk through the days, you always remember the cheapest price you've ever seen. At each new price, ask — "if I had bought at the cheapest point and sell today, how much do I earn?" Track the best answer.

---

## 🤔 Why This Works (Greedy Argument)

For any selling day `i`, the best buying day is always the **minimum price in `prices[0..i-1]`**. Scanning left to right and tracking the running minimum captures this exactly — no need to look back.

    profit at day i = prices[i] - min(prices[0..i])

We never need to consider any other buy day for a fixed sell day.

---

## 🪜 Algorithm Steps

1. 🏁 Initialize `minPrice = prices[0]`, `maxProfit = 0`
2. 🔁 For each price `prices[i]`:
   - 📉 Update `minPrice = min(minPrice, prices[i])` — cheapest buy so far
   - 📈 Update `maxProfit = max(maxProfit, prices[i] - minPrice)` — best sell today
3. 📤 Return `maxProfit`

## 🧩 Code Walkthrough

### Dry Run Example

    prices = [7, 1, 5, 3, 6, 4]

    i | price | minPrice | profit today | maxProfit
    --|-------|----------|--------------|----------
    0 |   7   |    7     |   7-7 = 0    |    0
    1 |   1   |    1     |   1-1 = 0    |    0
    2 |   5   |    1     |   5-1 = 4    |    4
    3 |   3   |    1     |   3-1 = 2    |    4
    4 |   6   |    1     |   6-1 = 5    |    5
    5 |   4   |    1     |   4-1 = 3    |    5

    Output: 5 ✅  (buy at 1, sell at 6)

### All-Decreasing Edge Case

    prices = [7, 6, 4, 3, 1]

    minPrice keeps updating but profit is always 0 or negative
    maxProfit stays 0 → return 0 ✅  (no profitable transaction)

### Pseudocode

    maxProfit(prices):
        minPrice  = prices[0]
        maxProfit = 0

        for price in prices:
            minPrice  = min(minPrice, price)         // cheapest buy so far
            maxProfit = max(maxProfit, price-minPrice) // best profit if sell today

        return maxProfit

### Full C++ Solution

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int minPrice  = prices;
        int maxProfit = 0;

        for (int i = 0; i < prices.size(); i++) {
            minPrice  = min(prices[i], minPrice);           // track cheapest buy
            maxProfit = max(maxProfit, prices[i]-minPrice); // best sell today
        }
        return maxProfit;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Track running minimum** — the best buy price for any future sell day |
| 2 | `maxProfit = 0` initialization correctly handles **no-profit scenarios** |
| 3 | Both updates happen in **same iteration** — order matters: update min first, then profit |
| 4 | Only **one transaction** allowed — this approach breaks for multiple transactions |

---

## ⚠️ Common Mistakes

- ❌ **Updating `maxProfit` before `minPrice`** → uses yesterday's min for today's price, same iteration so it's fine here, but logically update min first
- ❌ **Initializing `minPrice = 0`** → artificially inflates profit (0 is never a valid price context)
- ❌ **Initializing `maxProfit = INT_MIN`** → unnecessary; profit is always ≥ 0 since we skip negative trades

---

## 🔁 This is Kadane's in Disguise

This problem can be reframed as **max subarray sum** on a difference array:

    diff[i] = prices[i] - prices[i-1]   // daily change

    Max profit = max subarray sum of diff[]
               = Kadane's Algorithm on diff[]

    Both approaches are O(N) and conceptually equivalent.
