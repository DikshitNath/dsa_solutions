# ↗️ Diagonal Traverse

> **Platform:** LeetCode | **Topic:** Matrix | **Technique:** Diagonal Grouping + Alternating Reverse

**Question Link:** [https://leetcode.com/problems/diagonal-traverse/description/](https://leetcode.com/problems/diagonal-traverse/description/)

---

## 📌 Problem Summary

Given an `m x n` matrix `mat`, return all elements in **diagonal order** — alternating between going up-right and down-left diagonally.

---

## 💡 Core Intuition

Every element `mat[i][j]` that lies on the **same diagonal** shares the same value of `i + j`. Group all elements by their `i+j` value, then **alternate reversing** each group to simulate the zigzag diagonal traversal.

> 🎯 **Key Observation:**
>     Diagonal 0 → i+j = 0  →  {(0,0)}
>     Diagonal 1 → i+j = 1  →  {(0,1), (1,0)}
>     Diagonal 2 → i+j = 2  →  {(0,2), (1,1), (2,0)}
>     ...and so on

---

## 🤔 Why Alternate Reverse?

Elements are naturally collected **top-to-bottom** within each diagonal group (since outer loop goes row by row). The traversal direction alternates:
- **Even diagonal** (i+j=0,2,4...) → goes **up-right** → needs reversed order
- **Odd diagonal**  (i+j=1,3,5...) → goes **down-left** → already in correct order

---

## 🪜 Algorithm Steps

1. 🗂️ Use a `map<int, vector<int>>` to **group elements by diagonal** (`i+j`)
2. 🔁 Iterate all cells, push `mat[i][j]` into `mp[i+j]`
3. 🔀 Traverse the map in order, **alternating reverse** on each diagonal's list
4. 📥 Append each group's elements to the answer array

### Pseudocode

    findDiagonalOrder(mat):
        map mp   // key = i+j, value = list of elements

        for i in 0 to m-1:
            for j in 0 to n-1:
                mp[i+j].push_back(mat[i][j])

        flip = true
        for each diagonal group in mp:
            if flip → reverse the group
            append group to ans
            flip = !flip

        return ans

### Full C++ Solution

```cpp
class Solution {
public:
    vector<int> findDiagonalOrder(vector<vector<int>>& mat) {
        int m = mat.size(), n = mat.size();
        map<int, vector<int>> mp;
        vector<int> ans;

        // Group elements by diagonal index (i+j)
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                mp[i+j].push_back(mat[i][j]);

        bool flip = true;
        for (auto& it : mp) {
            if (flip) reverse(it.second.begin(), it.second.end()); // up-right
            for (int num : it.second)
                ans.push_back(num);
            flip = !flip;
        }

        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(M × N) | Every element visited once; map operations O(log(M+N)) |
| 🧠 **Space** | O(M × N) | Map stores all elements grouped by diagonal |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | `i + j` is the **diagonal index** — all cells on the same diagonal share it |
| 2 | Elements are naturally collected **top-to-bottom**, so only even diagonals need reversal |
| 3 | `map` is used (not `unordered_map`) to ensure diagonals are processed **in order** |
| 4 | `flip` toggles on every diagonal — no need to track even/odd explicitly |

---

## ⚠️ Common Mistakes

- ❌ **Using `unordered_map`** → diagonals processed in random order → wrong output
- ❌ **Reversing odd diagonals instead of even** → direction flipped from expected
- ❌ **Off-by-one on `flip` init** → all diagonals reversed in wrong direction

---

## 🔁 Diagonal Index Trick

    This same i+j grouping trick applies to many matrix diagonal problems:

    i + j = same  →  same top-right to bottom-left diagonal  (this problem)
    i - j = same  →  same top-left  to bottom-right diagonal (anti-diagonal)
