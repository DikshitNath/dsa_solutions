# 🔍 Find Minimum in Rotated Sorted Array

> **Platform:** LeetCode | **Topic:** Binary Search | **Technique:** Binary Search on Pivot

**Question Link:** [https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/)

---

## 📌 Problem Summary

A sorted array was rotated at some unknown pivot. Find the **minimum element** in O(log N) time.

    Original: [1, 2, 3, 4, 5]
    Rotated:  [3, 4, 5, 1, 2]  ← minimum is 1

---

## 💡 Core Intuition

In a rotated sorted array, the minimum is the **inflection point** — where the sequence drops. Using binary search, compare `nums[m]` with `nums[r]`:
- If `nums[m] > nums[r]` → the drop (minimum) is in the **right half**
- Otherwise → the minimum is in the **left half or at `m`**

> 📉 **Analogy:** Walking along a mountain ridge that was shifted. You can always tell which direction to go downhill by comparing your current height with the rightmost point in view.

---

## 🤔 Why Compare `nums[m]` with `nums[r]` (not `nums[l]`)?

The right end `nums[r]` is our **stable reference point**:

    Case 1: nums[m] > nums[r]
    → m is in the HIGHER left portion → minimum is to the RIGHT → l = m+1

    Case 2: nums[m] <= nums[r]
    → m is in the LOWER right portion → minimum is HERE or to the LEFT → r = m

Comparing with `nums[l]` is ambiguous for unrotated arrays (both sides look sorted).

---

## 🪜 Algorithm Steps

1. 🏁 Set `l = 0`, `r = n-1`
2. 🔁 While `l < r`:
   - Compute `m = (l+r)/2`
   - If `nums[m] > nums[r]` → minimum is in right half → `l = m+1`
   - Else → minimum is at `m` or left of it → `r = m`
3. 📤 Return `nums[r]` (= `nums[l]` since `l == r`)

## 🧩 Code Walkthrough

### Dry Run — Rotated Array

    nums = [4, 5, 6, 7, 0, 1, 2]
            0  1  2  3  4  5  6

    l=0, r=6 → m=3: nums[3]=7 > nums[6]=2 → l=4
    l=4, r=6 → m=5: nums[5]=1 < nums[6]=2 → r=5
    l=4, r=5 → m=4: nums[4]=0 < nums[5]=1 → r=4
    l=4, r=4 → loop ends

    return nums[4] = 0 ✅

### Dry Run — No Rotation

    nums = [1, 2, 3, 4, 5]

    l=0, r=4 → m=2: nums[2]=3 < nums[4]=5 → r=2
    l=0, r=2 → m=1: nums[1]=2 < nums[2]=3 → r=1
    l=0, r=1 → m=0: nums[0]=1 < nums[1]=2 → r=0
    l=0, r=0 → loop ends

    return nums[0] = 1 ✅

### Why `r = m` (not `r = m-1`)?

    When nums[m] <= nums[r], m itself could BE the minimum.
    Setting r = m-1 would skip it entirely → wrong answer.

    r = m keeps m in the search range until l == r confirms it. ✅

### Pseudocode

    findMin(nums):
        l = 0,  r = n-1

        while l < r:
            m = (l+r)/2
            if nums[m] > nums[r]:
                l = m + 1       // minimum in right half
            else:
                r = m           // minimum at m or in left half

        return nums[r]          // l == r == pivot index

### Full C++ Solution

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int n = nums.size();
        int l = 0, r = n-1;

        while (l < r) {
            int m = (l+r)/2;

            if (nums[m] > nums[r])
                l = m + 1;      // min is in right half
            else
                r = m;          // min is here or left
        }
        return nums[r];         // converged to minimum
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | Compare `nums[m]` with `nums[r]` — **right end is the stable reference** |
| 2 | `r = m` (not `r = m-1`) — minimum could be at `m` itself |
| 3 | Loop condition is `l < r` — exits when both converge on the minimum |
| 4 | Works correctly for **non-rotated arrays** too — naturally returns `nums[0]` |

---

## ⚠️ Common Mistakes

- ❌ **`r = m-1`** when `nums[m] <= nums[r]` → skips potential minimum at `m`
- ❌ **Comparing with `nums[l]`** → ambiguous on non-rotated subarrays
- ❌ **Loop condition `l <= r`** → overshoots; use `l < r` to stop exactly at minimum
- ❌ **Returning `nums[l-1]`** or `nums[m]` after loop → `nums[r]` is always correct at convergence

---

## 🆚 This vs Search in Rotated Array

| Feature | Find Minimum | Search in Rotated |
|---------|-------------|-------------------|
| Goal | Find pivot value | Find target index |
| Returns | `nums[r]` (value) | Index or -1 |
| Steps | 1 binary search | Find pivot + 2 binary searches |
| Complexity | O(log N) | O(log N) |
