# 🎯 Find First and Last Position of Element in Sorted Array

> **Platform:** LeetCode | **Topic:** Binary Search | **Technique:** Modified Binary Search (First & Last Occurrence)
> 

**Question Link:** https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/

---

## 📌 Problem Summary

Given a sorted array `nums` and a `target`, return `[first occurrence index, last occurrence index]`. Return `[-1, -1]` if target is not found. Must run in **O(log N)**.

```
nums = [5,7,7,8,8,10], target = 8
Output: [3, 4]
```

---

## 💡 Core Intuition

Run **two separate binary searches**:

- `first()` — when target found, record index and **go left** (`r = m-1`) to find earlier occurrence
- `last()` — when target found, record index and **go right** (`l = m+1`) to find later occurrence

> 🎯 **Analogy:** To find the first seat in a row of identical seats, keep moving left when you find one. To find the last, keep moving right. Two separate sweeps.
> 

---

## 🤔 The Key Difference Between `first()` and `last()`

Both functions are identical **except for one line** when `nums[m] == target`:

| Function | On match | Why |
| --- | --- | --- |
| `first()` | `ans = m; r = m-1` | Record, then search **left** for earlier |
| `last()` | `ans = m; l = m+1` | Record, then search **right** for later |

The `ans` variable saves the best answer found so far — even as we keep searching.

---

## 🪜 Algorithm Steps

**For `first()`:**

1. Standard binary search
2. On match → save index to `ans`, move `r = m-1` (search left half)
3. On `nums[m] > target` → `r = m-1`
4. On `nums[m] < target` → `l = m+1`
5. Return `ans` (or `1` if never matched)

**For `last()`:**

1. Same as `first()` but on match → save index to `ans`, move `l = m+1` (search right half)

### Pseudocode

```
searchRange(nums, target):
    return [first(nums, target), last(nums, target)]

first(nums, target):
    ans = -1
    while l <= r:
        m = (l+r)/2
        if nums[m] == target: ans=m; r=m-1  // save + go left
        if nums[m] >  target: r=m-1
        if nums[m] <  target: l=m+1
    return ans

last(nums, target):
    ans = -1
    while l <= r:
        m = (l+r)/2
        if nums[m] == target: ans=m; l=m+1  // save + go right
        if nums[m] >  target: r=m-1
        if nums[m] <  target: l=m+1
    return ans
```

### Full C++ Solution

```cpp
class Solution {
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int n = nums.size();
        return {first(nums, target, 0, n-1),
                last (nums, target, 0, n-1)};
    }

    int first(vector<int>& nums, int target, int l, int r) {
        int ans = -1;
        while (l <= r) {
            int m = (l+r)/2;
            if      (nums[m] == target) { ans = m; r = m-1; }  // save + go left
            else if (nums[m] >  target)   r = m-1;
            else                          l = m+1;
        }
        return ans;
    }

    int last(vector<int>& nums, int target, int l, int r) {
        int ans = -1;
        while (l <= r) {
            int m = (l+r)/2;
            if      (nums[m] == target) { ans = m; l = m+1; }  // save + go right
            else if (nums[m] >  target)   r = m-1;
            else                          l = m+1;
        }
        return ans;
    }
};
```

| 🧠 **Space** | O(1) | Only pointers and `ans` variable |

## ✅ Key Takeaways

| # | Insight |
| --- | --- |
| 1 | **Don't stop on first match** — save it and keep searching the relevant half |
| 2 | `ans = -1` initialization correctly handles **target not found** |
| 3 | `first` and `last` differ by **only one character** — `r = m-1` vs `l = m+1` on match |
| 4 | Both searches are fully **independent** — no shared state |

---

## ⚠️ Common Mistakes

- ❌ **Returning immediately on match** → finds some occurrence, not first/last
- ❌ **`first()` doing `l = m+1` on match** → searches right instead of left
- ❌ **`last()` doing `r = m-1` on match** → searches left instead of right
- ❌ **Not initializing `ans = -1`** → returns garbage if target doesn't exist
