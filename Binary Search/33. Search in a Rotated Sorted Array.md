# 🔄 Search in Rotated Sorted Array

> **Platform:** LeetCode | **Topic:** Binary Search | **Technique:** Find Pivot + Two Binary Searches

**Question Link:** [https://leetcode.com/problems/search-in-rotated-sorted-array/](https://leetcode.com/problems/search-in-rotated-sorted-array/)

---

## 📌 Problem Summary

A sorted array was **rotated** at some pivot. Given the rotated array and a `target`, return the index of `target` or `-1` if not found — in **O(log N)** time.

    Original: [1, 2, 3, 4, 5, 6, 7]
    Rotated:  [4, 5, 6, 7, 1, 2, 3]   ← pivot at index 4

---

## 💡 Core Intuition

A rotated sorted array is really **two sorted subarrays** joined together. Find the **pivot (minimum element index)** first — it splits the array into two clean sorted halves. Then binary search the correct half.

> 🔪 **Analogy:** A rotated array is like a book that was cut and swapped. Find where the cut happened, then search the right half of the book normally.

---

## 🤔 Three Functions — Each Has One Job

| Function | Job |
|----------|-----|
| `search` | Orchestrator — find pivot, search left half, search right half |
| `findMinIdx` | Finds the **pivot** (index of minimum element) via binary search |
| `binarySearch` | Standard binary search on a given range `[l, r]` |

---

## 🤔 How `findMinIdx` Works

The minimum element is where the rotation happened. Key insight:

    If nums[m] > nums[r]:
        minimum is in the RIGHT half → l = m + 1
    Else:
        minimum is in the LEFT half (or at m) → r = m

    Loop ends when l == r → that's the pivot index ✅

    Example: [4, 5, 6, 7, 1, 2, 3]
    l=0, r=6, m=3: nums[3]=7 > nums[6]=3 → l=4
    l=4, r=6, m=5: nums[5]=2 < nums[6]=3 → r=5
    l=4, r=5, m=4: nums[4]=1 < nums[5]=2 → r=4
    l=4, r=4 → return 4  (nums[4]=1 is minimum) ✅

---

## 🪜 Algorithm Steps

1. 🔍 Find `pivotIdx` = index of minimum element
2. 🔎 Binary search in **left half** `[0, pivotIdx-1]`
3. ✅ If found → return result
4. 🔎 Binary search in **right half** `[pivotIdx, n-1]`
5. 📤 Return result (or `-1` if not found in either half)

## 🧩 Code Walkthrough

### Dry Run Example

    nums = [4, 5, 6, 7, 0, 1, 2],  target = 1

    Step 1: findMinIdx
    l=0,r=6 → m=3: nums[3]=7>nums[6]=2 → l=4
    l=4,r=6 → m=5: nums[5]=1<nums[6]=2 → r=5
    l=4,r=5 → m=4: nums[4]=0<nums[5]=1 → r=4
    l=4,r=4 → pivotIdx = 4

    Two halves:
    Left:  [4,5,6,7]  indices [0,3]
    Right: [0,1,2]    indices [4,6]

    Step 2: binarySearch(target=1, l=0, r=3)
    m=1: nums[1]=5>1 → r=0
    m=0: nums[0]=4>1 → r=-1 → return -1

    Step 3: binarySearch(target=1, l=4, r=6)
    m=5: nums[5]=1 == 1 → return 5 ✅

    Output: 5 ✅

### Edge Case — No Rotation

    nums = [1, 2, 3, 4, 5]
    findMinIdx → pivotIdx = 0

    Left half: [0, -1] → binarySearch skips (l > r) → returns -1
    Right half: [0, 4] → full array → normal binary search ✅

### Pseudocode

    search(nums, target):
        pivotIdx = findMinIdx(nums)

        res = binarySearch(nums, target, 0, pivotIdx-1)
        if res != -1 → return res

        return binarySearch(nums, target, pivotIdx, n-1)

    findMinIdx(nums):
        l=0, r=n-1
        while l < r:
            m = (l+r)/2
            if nums[m] > nums[r] → l = m+1   // min is to the right
            else                 → r = m      // min is here or to the left
        return r

    binarySearch(nums, target, l, r):
        while l <= r:
            m = (l+r)/2
            if nums[m] > target → r = m-1
            if nums[m] < target → l = m+1
            else                → return m
        return -1

### Full C++ Solution

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int pivotIdx = findMinIdx(nums);

        int res = binarySearch(nums, target, 0, pivotIdx-1);   // left half
        if (res != -1) return res;

        return binarySearch(nums, target, pivotIdx, nums.size()-1); // right half
    }

    int binarySearch(vector<int>& nums, int target, int l, int r) {
        while (l <= r) {
            int m = (l+r)/2;
            if      (nums[m] > target) r = m-1;
            else if (nums[m] < target) l = m+1;
            else                       return m;
        }
        return -1;
    }

    int findMinIdx(vector<int>& nums) {
        int l = 0, r = nums.size()-1;
        while (l < r) {
            int m = (l+r)/2;
            if (nums[m] > nums[r]) l = m+1;  // min is in right half
            else                   r = m;     // min is here or left
        }
        return r;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(log N) | `findMinIdx` = O(log N) + two binary searches = O(log N) each |
| 🧠 **Space** | O(1) | All iterative, no extra space |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Pivot = minimum element index** — splits rotated array into 2 sorted halves |
| 2 | `findMinIdx` compares `nums[m]` with `nums[r]` — not `nums[l]` — to find minimum |
| 3 | When `pivotIdx = 0` (no rotation), left half `[0, -1]` is skipped automatically |
| 4 | Two binary searches on clean sorted halves → clean and readable |

---

## ⚠️ Common Mistakes

- ❌ **Comparing `nums[m]` with `nums[l]`** in findMinIdx → ambiguous, use `nums[r]`
- ❌ **Not handling `pivotIdx = 0`** → `binarySearch(0, -1)` must safely return `-1` (it does since `l > r`)
- ❌ **Using `m = (l+r)/2` outside while loop** (original code has a dead `m` before the loop) → the one inside the loop is what actually matters

---

## 🔁 One-Pass Alternative

Instead of finding pivot first, determine which sorted half `target` lies in at each step:

    while l <= r:
        m = (l+r)/2
        if nums[m] == target → return m

        if nums[l] <= nums[m]:          // left half is sorted
            if nums[l] <= target < nums[m] → r = m-1
            else → l = m+1
        else:                           // right half is sorted
            if nums[m] < target <= nums[r] → l = m+1
            else → r = m-1

    Time: O(log N) | Space: O(1) — single pass, no pivot needed
