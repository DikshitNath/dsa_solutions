# 🔄 Reverse Linked List

> **Platform:** LeetCode | **Topic:** Linked List | **Technique:** Recursive Reversal

**Question Link:** [https://leetcode.com/problems/reverse-linked-list/](https://leetcode.com/problems/reverse-linked-list/)

---

## 📌 Problem Summary

Given the `head` of a singly linked list, reverse the list and return the new head.

    Input:  1 → 2 → 3 → 4 → 5 → NULL
    Output: 5 → 4 → 3 → 2 → 1 → NULL

---

## 💡 Core Intuition

Recurse all the way to the **last node** — it becomes the new head. On the way back up, reverse each link: make `head->next->next = head` (point the next node back to current), then cut the old forward link with `head->next = NULL`.

> 🪢 **Analogy:** Imagine a chain of people each pointing to the one in front. Walk to the end, then on the way back, each person grabs the one behind them instead — and lets go of the one in front.

---

## 🤔 Recursive Call Stack Visualized

    reverseList(1)
    └── reverseList(2)
        └── reverseList(3)
            └── reverseList(4)
                └── reverseList(5)
                    └── returns 5 (base case: no next)

    Unwinding:
    At node 4: 4→5→NULL becomes 4←5, 4→NULL  → newHead=5
    At node 3: 3→4→NULL becomes 3←4, 3→NULL  → newHead=5
    At node 2: 2→3→NULL becomes 2←3, 2→NULL  → newHead=5
    At node 1: 1→2→NULL becomes 1←2, 1→NULL  → newHead=5

    Final: 5→4→3→2→1→NULL ✅

---

## 🤔 Why `head->next->next = head` Works

At each unwind step, `head->next` still points to the **next node in old chain**. That node needs to now point **back** to `head`.

    Before: head → next → ...
    Step 1: head → next → head   (head->next->next = head)
    Step 2: head → NULL          (head->next = NULL)
    Result: next → head → NULL   ✅

`head->next = NULL` is critical — without it, `head` still points forward, creating a **cycle**.

---

## 🪜 Algorithm Steps

1. 🚫 Base case: if `head == null` or `head->next == null` → return `head`
2. 🔁 Recurse: `newHead = reverseList(head->next)`
3. 🔗 Reverse link: `head->next->next = head`
4. ✂️ Cut old link: `head->next = NULL`
5. 📤 Return `newHead` (bubbles up unchanged — always the last node)

### Pseudocode

    reverseList(head):
        if head is null OR head.next is null → return head   // base case

        newHead = reverseList(head.next)     // recurse to end

        head.next.next = head               // reverse the link
        head.next = NULL                    // cut old forward link

        return newHead                      // always the original last node

### Full C++ Solution

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        if (!head || !head->next) return head;   // base case

        ListNode* newHead = reverseList(head->next);  // recurse to end

        head->next->next = head;    // point next node back to current
        head->next = NULL;          // remove old forward link

        return newHead;             // new head never changes after base case
    }
};
```

| 🧠 **Space** | O(N) | Recursion stack depth = list length |

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | `newHead` is set **once** at the base case and returned unchanged all the way up |
| 2 | `head->next = NULL` is **critical** — prevents cycles during unwinding |
| 3 | The recursive approach is elegant but uses O(N) stack space — iterative is O(1) space |
| 4 | Base case handles both **empty list** and **single node** list |

---

## ⚠️ Common Mistakes

- ❌ **Forgetting `head->next = NULL`** → creates a cycle (e.g. 1↔2 loop)
- ❌ **Returning `head` instead of `newHead`** → returns original head, not reversed head
- ❌ **Base case only checks `!head`** → crashes on single node (need `!head->next` too)

---

## 🔁 Iterative Version (O(1) Space)

    reverseList(head):
        prev = NULL
        curr = head

        while curr != NULL:
            next = curr->next    // save next
            curr->next = prev    // reverse link
            prev = curr          // move prev forward
            curr = next          // move curr forward

        return prev              // prev is new head

    Time: O(N) | Space: O(1) ✅ — preferred for large lists

---

## 🆚 Recursive vs Iterative

| Feature | Recursive | Iterative |
|---------|-----------|-----------|
| Time | O(N) | O(N) |
| Space | O(N) stack | ✅ O(1) |
| Readability | Elegant, concise | Slightly more explicit |
| Risk | Stack overflow on huge lists | None |
