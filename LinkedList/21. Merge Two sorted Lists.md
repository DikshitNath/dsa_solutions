# 🔀 Merge Two Sorted Lists

> **Platform:** LeetCode | **Topic:** Linked List | **Technique:** Recursive Merge

**Question Link:** [https://leetcode.com/problems/merge-two-sorted-lists/](https://leetcode.com/problems/merge-two-sorted-lists/)

---

## 📌 Problem Summary

Given the heads of two sorted linked lists, merge them into one **sorted** linked list and return its head.

    list1: 1 → 2 → 4
    list2: 1 → 3 → 4
    Output: 1 → 1 → 2 → 3 → 4 → 4

---

## 💡 Core Intuition

At each step, pick the **smaller head** from the two lists — it becomes the current node. Then recursively merge the rest of that list with the other list.

> 🃏 **Analogy:** Two sorted decks of cards face-up. Always pick the smaller top card from either deck and add it to your hand. Repeat until both decks are empty.

---

## 🤔 How Recursion Builds the Result

Each call returns the head of the merged sublist. The current node points its `next` to whatever the recursive call returns — chaining nodes together on the way back up.

    mergeTwoLists(1→2→4,  1→3→4)
    list1->val == list2->val → pick list1 (1)
        ans = 1 (list1)
        ans->next = mergeTwoLists(2→4,  1→3→4)
            list2->val < list1->val → pick list2 (1)
                ans = 1 (list2)
                ans->next = mergeTwoLists(2→4, 3→4)
                    ...and so on

---

## 🪜 Algorithm Steps

1. 🚫 Base cases:
   - `list1 == null` → return `list2` (nothing left in list1)
   - `list2 == null` → return `list1` (nothing left in list2)
2. 🔍 Compare current heads:
   - `list1->val < list2->val` → `ans = list1`, recurse with `(list1->next, list2)`
   - Otherwise → `ans = list2`, recurse with `(list1, list2->next)`
3. 🔗 Set `ans->next` to the result of the recursive call
4. 📤 Return `ans`

## 🧩 Code Walkthrough

### Dry Run Example

    list1: 1 → 3 → 5
    list2: 2 → 4 → 6

    merge(1→3→5, 2→4→6): 1<2 → ans=1, next=merge(3→5, 2→4→6)
      merge(3→5, 2→4→6): 2<3 → ans=2, next=merge(3→5, 4→6)
        merge(3→5, 4→6): 3<4 → ans=3, next=merge(5, 4→6)
          merge(5, 4→6): 4<5 → ans=4, next=merge(5, 6)
            merge(5, 6): 5<6 → ans=5, next=merge(null, 6)
              merge(null, 6): return 6  ← base case
            ans=5, 5->next=6 → return 5
          ans=4, 4->next=5 → return 4
        ans=3, 3->next=4 → return 3
      ans=2, 2->next=3 → return 2
    ans=1, 1->next=2 → return 1

    Result: 1→2→3→4→5→6 ✅

### Base Case Logic

    if (!list1) return list2;
    → list1 exhausted → attach remaining list2 as-is (already sorted)

    if (!list2) return list1;
    → list2 exhausted → attach remaining list1 as-is (already sorted)

### Pseudocode

    mergeTwoLists(list1, list2):
        if list1 is null → return list2      // base case
        if list2 is null → return list1      // base case

        if list1.val < list2.val:
            ans = list1
            ans.next = mergeTwoLists(list1.next, list2)
        else:
            ans = list2
            ans.next = mergeTwoLists(list1, list2.next)

        return ans

### Full C++ Solution

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        if (!list1) return list2;   // list1 exhausted
        if (!list2) return list1;   // list2 exhausted

        ListNode* ans;

        if (list1->val < list2->val) {
            ans = list1;
            ans->next = mergeTwoLists(ans->next, list2);   // advance list1
        } else {
            ans = list2;
            ans->next = mergeTwoLists(list1, ans->next);   // advance list2
        }
        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(M + N) | Each node from both lists visited exactly once |
| 🧠 **Space** | O(M + N) | Recursion stack depth = total nodes |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Smaller head always wins** — greedy choice at each step is always correct |
| 2 | Base cases handle the **exhausted list** — attach the other list directly |
| 3 | `ans->next = recursiveCall` chains nodes **on the way back up** the call stack |
| 4 | Uses `<=` implicitly (else branch) — equal values take `list2`; either is fine |

---

## ⚠️ Common Mistakes

- ❌ **No base cases** → null pointer dereference when one list is exhausted
- ❌ **Creating new nodes** → no need, reuse existing nodes by relinking `next` pointers
- ❌ **Passing `list1->next` directly** without assigning to `ans->next` → breaks the chain

---

## 🔁 Iterative Version (O(1) Space)

Use a **dummy head** to simplify list building:

    dummy = new ListNode(0)
    curr  = dummy

    while list1 AND list2:
        if list1.val < list2.val:
            curr.next = list1;  list1 = list1.next
        else:
            curr.next = list2;  list2 = list2.next
        curr = curr.next

    curr.next = list1 OR list2   // attach remaining

    return dummy.next

    Time: O(M+N) | Space: O(1) ✅

---

## 🆚 Recursive vs Iterative

| Feature | Recursive | Iterative |
|---------|-----------|-----------|
| Time | O(M+N) | O(M+N) |
| Space | O(M+N) stack | ✅ O(1) |
| Readability | Clean, elegant | Slightly more explicit |
| Risk | Stack overflow on huge lists | None |
