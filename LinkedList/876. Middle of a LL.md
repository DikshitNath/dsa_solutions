# 🐢🐇 Middle of the Linked List

> **Platform:** LeetCode | **Topic:** Linked List | **Technique:** Slow & Fast Pointer (Floyd's)

**Question Link:** [https://leetcode.com/problems/middle-of-the-linked-list/](https://leetcode.com/problems/middle-of-the-linked-list/)

---

## 📌 Problem Summary

Given the `head` of a singly linked list, return the **middle node**. If there are two middle nodes (even length), return the **second** middle.

    Odd:  1 → 2 → [3] → 4 → 5       → return node 3
    Even: 1 → 2 → 3 → [4] → 5 → 6   → return node 4

---

## 💡 Core Intuition

Use two pointers — `slow` moves **1 step** at a time, `fast` moves **2 steps** at a time. When `fast` reaches the end, `slow` is exactly at the middle.

> 🏁 **Analogy:** Two runners on a track — one runs at double speed. When the faster one finishes the race, the slower one is exactly halfway.

---

## 🤔 Why Does This Work?

    fast covers 2x the distance of slow.
    When fast reaches end (length N):
        slow has covered N/2 steps → exactly the middle ✅

    Odd  (N=5): fast stops at node 5, slow at node 3  → middle
    Even (N=6): fast stops at NULL after node 6, slow at node 4 → second middle

---

## 🤔 Loop Condition: `fast && fast->next`

    fast        → ensures fast itself isn't null (odd length — fast lands on last node)
    fast->next  → ensures fast can take 2 steps (even length — fast would go to NULL)

    Both checks needed to handle odd AND even length lists safely.

---

## 🪜 Algorithm Steps

1. 🏁 Initialize `slow = head`, `fast = head`
2. 🔁 While `fast` and `fast->next` exist:
   - `fast = fast->next->next` (2 steps)
   - `slow = slow->next` (1 step)
3. 📤 Return `slow` (at middle)

---

## 🧩 Code Walkthrough

### Dry Run — Odd Length (5 nodes)

    List: 1 → 2 → 3 → 4 → 5 → NULL

    Start: slow=1, fast=1

    Step 1: fast=3, slow=2
    Step 2: fast=5, slow=3
    Step 3: fast->next=NULL → loop ends

    return slow = node(3) ✅

### Dry Run — Even Length (6 nodes)

    List: 1 → 2 → 3 → 4 → 5 → 6 → NULL

    Start: slow=1, fast=1

    Step 1: fast=3, slow=2
    Step 2: fast=5, slow=3
    Step 3: fast=NULL (5->next->next), slow=4 → loop ends

    return slow = node(4) ✅  (second middle)

### Pointer Movement Table

    Odd (N=5):
    Step | slow | fast
    -----|------|-----
      0  |  1   |  1
      1  |  2   |  3
      2  |  3   |  5   ← fast->next = NULL, stop

    Even (N=6):
    Step | slow | fast
    -----|------|-----
      0  |  1   |  1
      1  |  2   |  3
      2  |  3   |  5
      3  |  4   | NULL ← fast = NULL, stop

### Pseudocode

    middleNode(head):
        slow = head
        fast = head

        while fast AND fast.next:
            fast = fast.next.next    // 2 steps
            slow = slow.next         // 1 step

        return slow                  // at middle

### Full C++ Solution

```cpp
class Solution {
public:
    ListNode* middleNode(ListNode* head) {
        ListNode* slow = head;
        ListNode* fast = head;

        while (fast && fast->next) {
            fast = fast->next->next;    // 2 steps
            slow = slow->next;          // 1 step
        }

        return slow;                    // middle node
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **2:1 speed ratio** → slow is always at half of fast's position |
| 2 | For even length, returns **second** middle — `fast` goes to NULL, not last node |
| 3 | Loop condition needs **both** `fast` and `fast->next` to handle odd and even safely |
| 4 | This slow/fast pointer pattern is a **foundational technique** used in many list problems |

---

## ⚠️ Common Mistakes

- ❌ **Only checking `fast->next`** → null dereference on odd-length lists when `fast` itself is null
- ❌ **Only checking `fast`** → null dereference on `fast->next->next` for even-length lists
- ❌ **`slow = slow->next->next`** → moves slow too fast, skips the middle

---

## 🔁 This Pattern Powers Many Problems

    Slow/Fast pointer is used in:
    → Find Middle           → slow stops at middle
    → Detect Cycle          → fast catches slow if cycle exists
    → Find Cycle Start      → reset one pointer to head after meeting
    → Check Palindrome List → find middle, reverse second half, compare
    → Nth Node from End     → fast starts N steps ahead
