# 🔲 Surrounded Regions

> **Platform:** LeetCode | **Topic:** Graph / Matrix | **Technique:** Boundary DFS Flood Fill

**Question Link:** [https://leetcode.com/problems/surrounded-regions/](https://leetcode.com/problems/surrounded-regions/)

---

## 📌 Problem Summary

Given an `m x n` board of `'X'` and `'O'`, capture all `'O'` regions that are **fully surrounded by `'X'`** — replace them with `'X'`. `'O'`s connected to the **border** are never captured.

    'O' touching border (directly or via chain) → SAFE → stays 'O'
    'O' fully surrounded by 'X'               → CAPTURED → becomes 'X'

---

## 💡 Core Intuition

Instead of finding surrounded regions (hard), find **safe regions** (easy) — any `'O'` reachable from the border. Mark them temporarily as `'T'`, then:
- Remaining `'O'`s → surrounded → flip to `'X'`
- `'T'`s → safe → restore to `'O'`

> 🧱 **Analogy:** Instead of finding prisoners inside the walls, find everyone who can escape through the border. Everyone else gets captured.

---

## 🤔 Why Reverse Thinking (Border → Inward)?

Finding surrounded `'O'`s directly requires knowing if **every** path leads to a dead end — complex. But finding border-connected `'O'`s is just a simple flood fill from the 4 edges — much easier.

    Direct approach:  Is this 'O' surrounded? → check all paths → hard ❌
    Reverse approach: Can this 'O' reach border? → flood from border → easy ✅

---

## 🤔 Why Use `'T'` as Temporary Marker?

Three distinct states needed after pass 1:

| Symbol | Meaning | Action in Pass 2 |
|--------|---------|-----------------|
| `'X'` | Wall | Keep as `'X'` |
| `'O'` | Surrounded region | Flip to `'X'` |
| `'T'` | Safe (border-connected) | Restore to `'O'` |

Without `'T'`, we can't distinguish "originally safe `'O'`" from "surrounded `'O'`" after the DFS.

---

## 🪜 Algorithm Steps

1. 🔍 **Pass 1 — Mark safe regions:**
   - Scan all 4 border edges
   - For each border `'O'` → DFS flood fill, marking connected `'O'`s as `'T'`
2. ✏️ **Pass 2 — Finalize:**
   - `'O'` → `'X'` (surrounded, capture it)
   - `'T'` → `'O'` (safe, restore it)
   - `'X'` → stays `'X'`

    'O' at (1,1),(1,2),(2,2) → all become 'X'

    X X X X

### Border Scanning Logic

    Only trigger DFS from cells that are:
    1. On the border: i==0 || i==m-1 || j==0 || j==n-1
    2. Are 'O': board[i][j] == 'O'

    This covers all 4 edges in one nested loop ✅

### Pseudocode

    solve(board):
        // Pass 1: mark border-safe 'O's as 'T'
        for each border cell (i,j):
            if board[i][j] == 'O' → dfs(board, i, j)

        // Pass 2: finalize
        for each cell (i,j):
            if 'O' → 'X'    // surrounded → capture
            if 'T' → 'O'    // safe → restore

    dfs(board, i, j):
        if out of bounds OR board[i][j] != 'O' → return

        board[i][j] = 'T'           // mark safe

        dfs in all 4 directions

### Full C++ Solution

```cpp
class Solution {
public:
    int m, n;

    void solve(vector<vector<char>>& board) {
        m = board.size();
        n = board.size();

        // Pass 1: flood fill from all border 'O's
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (board[i][j] == 'O' &&
                   (i == 0 || i == m-1 || j == 0 || j == n-1)) {
                    dfs(board, i, j);
                }
            }
        }

        // Pass 2: capture surrounded, restore safe
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (board[i][j] == 'O') board[i][j] = 'X'; // captured
                if (board[i][j] == 'T') board[i][j] = 'O'; // safe
            }
        }
    }

    void dfs(vector<vector<char>>& board, int i, int j) {
        if (i < 0 || i >= m || j < 0 || j >= n ||
            board[i][j] != 'O') return;

        board[i][j] = 'T';              // mark as safe (border-connected)

        dfs(board, i+1, j);
        dfs(board, i-1, j);
        dfs(board, i, j+1);
        dfs(board, i, j-1);
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(M × N) | Each cell visited at most once across all DFS calls + pass 2 |
| 🧠 **Space** | O(M × N) | Recursion stack worst case (all cells are 'O') |

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Reverse thinking** — mark what's SAFE from border instead of finding what's surrounded |
| 2 | **`'T'` as temp marker** — distinguishes safe `'O'`s from surrounded `'O'`s in pass 2 |
| 3 | DFS only spreads through `'O'`s — stops at `'X'`, `'T'`, or boundaries |
| 4 | Pass 2 order doesn't matter — `'O'` and `'T'` checks are independent |

---

## ⚠️ Common Mistakes

- ❌ **DFS from all `'O'`s** instead of only border ones → marks everything as safe
- ❌ **Forgetting `'T'` marker** → can't distinguish safe vs surrounded in pass 2
- ❌ **Restoring `'T'` before flipping `'O'`** → doesn't matter here since they're different chars, but logically always flip `'O'`→`'X'` first
- ❌ **Not scanning all 4 borders** → missing `'O'`s on left/right edges

## 🔁 This Pattern: "Mark from Boundary"

    Many grid problems use this reverse flood-fill from boundary pattern:

    → Surrounded Regions    — safe O's reachable from border
    → Pacific Atlantic Flow — water reachable from each ocean (border)
    → Number of Enclaves    — land cells NOT reachable from border
