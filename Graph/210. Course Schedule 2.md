# 🎓 Course Schedule II — DFS Topological Sort

> **Platform:** LeetCode 210 | **Topic:** Graphs | **Technique:** DFS Post-order Stack + Cycle Detection via inRec

**Question Link:** https://leetcode.com/problems/course-schedule-ii/

---

## 📌 Problem Summary

Given `n` courses and prerequisites `[a, b]` ("finish `b` before `a`"), return a valid **course ordering**. If impossible (cycle), return `{}`.

n=4, prerequisites=[[1,0],[2,0],[3,1],[3,2]] → or
n=2, prerequisites=[[1,0]] → []

---

## 💡 Core Intuition

Run DFS on every unvisited node. After exploring all neighbors of node `u` (post-order), push `u` onto a stack. Popping the stack gives the topological order. If a back edge is detected (`inRec[v] == true`), a cycle exists — return `{}`.

> 🔗 **This is the DFS alternative to the Kahn's BFS solution (LC 210 previous notes).** Same problem, completely different mechanism.

---

## 🤔 Why `hasCycle` as a Class Variable?

DFS is recursive — once a cycle is detected deep in the call stack, you need a way to **propagate that information back up** to `findOrder`. Options:

```cpp
// Option 1: class variable (your approach)
hasCycle = true;
return;   // exits current DFS frame, hasCycle persists ✅

// Option 2: return bool from dfs
bool dfs(...) {
    ...
    if (inRec[v]) return true;   // propagate up
    if (!vis[v] && dfs(...)) return true;
    ...
}
```

Your approach works but has a subtle bug — after setting `hasCycle = true` and returning early, the caller's loop continues iterating over other neighbors and may still push `u` onto the stack. The `if (hasCycle) return {};` in `findOrder` catches this at the end, so the final answer is still correct — but it's slightly inefficient.

---

## 🤔 The Subtle Bug — Missing Early Propagation

```cpp
void dfs(..., int u, ...) {
    vis[u] = true;
    inRec[u] = true;

    for (int v : adj[u]) {
        if (inRec[v]) {
            hasCycle = true;
            return;              // ← exits dfs(u) immediately ✅
        }
        if (!vis[v]) dfs(adj, v, vis, st, inRec);
        // ⚠️ if hasCycle is true here, we still continue the loop!
    }

    st.push(u);                  // ← still pushed even if cycle found elsewhere
    inRec[u] = false;
}
```

**Fix — add early exit check:**
```cpp
if (!vis[v]) {
    dfs(adj, v, vis, st, inRec);
    if (hasCycle) return;        // ← stop immediately if cycle found below ✅
}
```

Without this, the stack gets polluted with nodes from a cyclic graph — but since `findOrder` checks `if (hasCycle) return {}` before using the stack, the final result is still correct. The fix makes it cleaner and avoids unnecessary work.

## 🪜 Algorithm Steps

1. 🏗️ Build `adj[]` from prerequisites (`v → u` for each `[u, v]`)
2. 🏁 Initialize `vis[]`, `inRec[]`, `hasCycle = false`
3. 🔁 For each unvisited node, run `dfs(i)`
4. **Inside DFS:**
   - Mark `vis[u] = true`, `inRec[u] = true`
   - For each neighbor `v`:
     - `inRec[v]` → set `hasCycle = true`, return
     - `!vis[v]` → recurse
   - **Post-order:** `st.push(u)`, `inRec[u] = false`
5. If `hasCycle` → return `{}`
6. Pop stack into `ans`, return `ans`

## 💻 Full C++ Solution (with fix)

```cpp
class Solution {
public:
    bool hasCycle;

    vector<int> findOrder(int n, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(n);

        for (auto& e : prerequisites)
            adj[e].push_back(e);   // prereq e → course e[1]

        vector<bool> vis(n, false), inRec(n, false);
        hasCycle = false;
        stack<int> st;

        for (int i = 0; i < n; i++)
            if (!vis[i]) dfs(adj, i, vis, st, inRec);

        if (hasCycle) return {};

        vector<int> ans;
        while (!st.empty()) { ans.push_back(st.top()); st.pop(); }
        return ans;
    }

    void dfs(vector<vector<int>>& adj, int u,
             vector<bool>& vis, stack<int>& st, vector<bool>& inRec) {
        vis[u] = inRec[u] = true;

        for (int v : adj[u]) {
            if (inRec[v]) { hasCycle = true; return; }
            if (!vis[v]) {
                dfs(adj, v, vis, st, inRec);
                if (hasCycle) return;    // ← propagate early exit ✅
            }
        }

        st.push(u);
        inRec[u] = false;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Post-order push** — `st.push(u)` after all neighbors → correct topo order |
| 2 | **`inRec[]` for cycle** — back edge detection on current DFS path |
| 3 | **`hasCycle` early propagation** — add `if (hasCycle) return` after recursive call |
| 4 | **`hasCycle = false` before loop** — reset matters if called multiple times |
| 5 | **Stack pop → ans** — reverses DFS post-order into correct topo order |

---

## ⚠️ Common Mistakes

- ❌ **No `if (hasCycle) return` after recursion** → continues despite cycle, pollutes stack
- ❌ **`st.push(u)` before recursion** → pre-order push → wrong order
- ❌ **Forgetting `inRec[u] = false` on backtrack** → false cycle detections
- ❌ **Not checking `hasCycle` before building `ans`** → returns garbage order for cyclic graph

---

## 🆚 DFS vs Kahn's for Course Schedule II

| Feature | DFS + Stack (this) | Kahn's BFS |
|---------|-------------------|------------|
| Cycle detection | `inRec[v] == true` | `count != n` |
| Order output | Stack pop | BFS queue order |
| Stack overflow risk | ✅ Deep graphs | ❌ None (iterative) |
| Extra propagation needed | ✅ `if(hasCycle) return` | ❌ None |
| Code complexity | More careful | Cleaner |
| Preferred | DFS practice | Production code |
