# 🎓 Course Schedule

> **Platform:** LeetCode | **Topic:** Graphs | **Technique:** Cycle Detection via DFS (inRec Array)

**Question Link:** [https://leetcode.com/problems/course-schedule/](https://leetcode.com/problems/course-schedule/)

---

## 📌 Problem Summary

Given `V` courses (0 to V-1) and a list of prerequisites `[a, b]` meaning **"to take course `a`, you must first take `b`"**, return `true` if you can finish all courses — i.e., **no cycle exists** in the dependency graph.

    V=2, prerequisites=[[1,0]]       → true  (0→1, no cycle)
    V=2, prerequisites=[[1,0],[0,1]] → false (0→1→0, cycle!)

---

## 💡 Core Intuition

Model courses as a **directed graph** where edge `u → v` means "course `u` depends on `v`". If a **cycle exists**, it means course A requires B which requires A — impossible to complete. So the problem reduces to **cycle detection in a directed graph**.

> 🔄 **Analogy:** Imagine tasks with dependencies. If Task A needs Task B, and Task B needs Task A — you're stuck in a deadlock forever. That's a cycle.

---

## 🤔 Why Two Visited Arrays?

A single `vis[]` array works for undirected graphs but **fails for directed graphs**. You need:

| Array | Meaning | Purpose |
|-------|---------|---------|
| `vis[]` | Node ever visited | Avoid re-processing entire components |
| `inRec[]` | Node in current DFS path | Detect back edges → cycles |

    vis[u] = true   → "I've been here before in some DFS call"
    inRec[u] = true → "I'm currently on the active DFS stack"

A cycle exists only when you reach a node that's **already on the current path** (`inRec[v] == true`) — not just any previously visited node.

---

## 🪜 Algorithm Steps

1. 🏗️ Build adjacency list from `prerequisites`
2. 🏁 Initialize `vis[V]` and `inRec[V]` as `false`
3. 🔁 For each unvisited node `i`, run `dfs(i)`
   - If DFS returns `true` (cycle found) → return `false` (can't finish)
4. 📤 Return `true` (no cycle → all courses completable)

**Inside DFS:**
1. Mark `vis[u] = true`, `inRec[u] = true`
2. For each neighbor `v`:
   - `inRec[v]` → cycle detected → return `true`
   - `!vis[v]` → recurse; propagate `true` if cycle found
3. **Backtrack:** `inRec[u] = false` before returning `false`

## 🧩 Code Walkthrough

### Dry Run — Cycle Exists

    V=3, prerequisites=[[0,1],[1,2],[2,0]]
    Graph: 0→1→2→0 (cycle!)

    DFS from 0:
      vis[0]=T, inRec[0]=T
      → visit 1: vis[1]=T, inRec[1]=T
        → visit 2: vis[2]=T, inRec[2]=T
          → neighbor 0: inRec[0]=T ✅ → return true (CYCLE!)
        ← return true
      ← return true
    ← return true

    canFinish returns false ✅

### Dry Run — No Cycle

    V=3, prerequisites=[[0,1],[1,2]]
    Graph: 0→1→2 (no cycle)

    DFS from 0:
      vis[0]=T, inRec[0]=T
      → visit 1: vis[1]=T, inRec[1]=T
        → visit 2: vis[2]=T, inRec[2]=T
          no neighbors → inRec[2]=F, return false
        ← return false
        inRec[1]=F, return false
      ← return false
      inRec[0]=F, return false

    All nodes visited, no cycle → return true ✅

### Dry Run — Disconnected Graph

    V=4, prerequisites=[[0,1],[2,3]]
    Graph: 0→1  (component 1)
           2→3  (component 2)

    i=0: DFS(0) → visits 0,1 → no cycle
    i=1: vis[1]=T → skip
    i=2: DFS(2) → visits 2,3 → no cycle
    i=3: vis[3]=T → skip

    return true ✅  ← outer loop handles disconnected components

### Pseudocode

    canFinish(V, prerequisites):
        build adj[] from prerequisites

        vis[V] = {false}, inRec[V] = {false}

        for i in 0..V-1:
            if not vis[i]:
                if dfs(adj, i, vis, inRec): return false

        return true

    dfs(adj, u, vis, inRec):
        vis[u] = inRec[u] = true

        for v in adj[u]:
            if inRec[v]: return true          // back edge = cycle
            if not vis[v] and dfs(..., v, ...): return true

        inRec[u] = false                      // backtrack
        return false

### Full C++ Solution

```cpp
class Solution {
public:
    bool canFinish(int V, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(V);

        for (auto& e : prerequisites) {
            adj[e].push_back(e);   // u depends on v: u → v[1]
        }

        vector<bool> vis(V, false), inRec(V, false);

        for (int i = 0; i < V; i++)
            if (!vis[i] && dfs(adj, i, vis, inRec))
                return false;   // cycle found → can't finish

        return true;
    }

    bool dfs(vector<vector<int>>& adj, int u,
             vector<bool>& vis, vector<bool>& inRec) {
        vis[u] = inRec[u] = true;

        for (int v : adj[u]) {
            if (inRec[v])                           return true;  // cycle!
            if (!vis[v] && dfs(adj, v, vis, inRec)) return true;
        }

        inRec[u] = false;   // leaving current path → backtrack
        return false;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **`inRec[]`** detects back edges — the only way cycles appear in directed graphs |
| 2 | **`inRec[u] = false` on backtrack** — critical! Unmark when leaving the current path |
| 3 | **`vis[]` skips re-processing** — prevents re-DFS'ing already safe nodes |
| 4 | Outer loop handles **disconnected graph components** |
| 5 | `inRec[v]` check must come **before** `!vis[v]` check in the loop |

---

## ⚠️ Common Mistakes

- ❌ **Forgetting `inRec[u] = false` on backtrack** → false cycle detections everywhere
- ❌ **Using only `vis[]`** → cross edges misidentified as back edges → wrong answer
- ❌ **Checking `vis[v]` instead of `inRec[v]`** for cycle → visits in other DFS trees trigger false positives
- ❌ **Not running DFS for all nodes** → disconnected components missed

## 🔁 The Critical Backtrack Step Explained
→ →

↓

DFS from 0: path = 0 → 1 → 2
inRec: [T, T, T, F]
2 has no more neighbors → inRec = false ← BACKTRACK

DFS continues: 1 → 3
inRec: [T, T, F, T] ← 3 is now on path, 2 is not
3 has no neighbors → inRec = false

text

Without backtracking, `inRec[2]` stays `true` when exploring `3` → node `2` falsely appears to be on the current path → **false cycle reported**.

---

## 🔁 Why `vis[v]` Check Alone Fails
Graph: 0 → 1 → 2
↑
3 ──┘ (3 also points to 1, no cycle)

DFS(0): visits 0 → 1 → 2
vis = [T, T, T, F]
inRec= [T, T, T, F] (then backtrack: all F)

DFS(3): visits 3 → 1
vis = T already!

If we check vis → "visited before = cycle?" → WRONG ❌

If we check inRec → false (not on current path) → CORRECT ✅

## 🆚 DFS Cycle Detection vs Kahn's Algorithm (BFS/Topo Sort)

| Feature | DFS + inRec (this) | Kahn's Algorithm (BFS) |
|---------|-------------------|------------------------|
| Approach | Detect back edge | Count in-degrees, peel nodes |
| Returns | Cycle found (bool) | Topo order or cycle detection |
| Space | O(V) extra arrays | O(V) queue + in-degree array |
| Bonus output | ❌ | ✅ Topo order if no cycle |
| Code complexity | Moderate | Slightly more verbose |
| Intuition | Recursion stack | Remove nodes with no dependencies |

> 📝 If the interviewer asks for the **actual course order** → use **Kahn's Algorithm** (LeetCode 210). For just yes/no → DFS is cleaner.

## 🧠 Kahn's Algorithm Sketch (for reference)

```cpp
// 1. Build in-degree array
// 2. Push all nodes with in-degree 0 to queue
// 3. BFS: pop node, decrement neighbors' in-degree
//         if neighbor's in-degree hits 0 → push to queue
// 4. If processed nodes == V → no cycle (true)
//    else → cycle exists (false)
```
