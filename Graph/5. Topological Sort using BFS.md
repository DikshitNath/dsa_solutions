# 🗂️ Topological Sort — Kahn's Algorithm (BFS)

> **Platform:** GFG / LeetCode | **Topic:** Graphs | **Technique:** BFS + In-degree Array (Kahn's Algorithm)

**GFG Link:** https://www.geeksforgeeks.org/topological-sorting-indegree-based-solution/

---

## 📌 Problem Summary

Given a **Directed Acyclic Graph (DAG)** with `V` vertices and edges, return a valid **topological ordering** — for every directed edge `u → v`, node `u` must appear **before** node `v`.

```
Edges: 5→0, 5→2, 4→0, 4→1, 2→3, 3→1

One valid output: [4, 5, 0, 2, 3, 1]
Another valid:    [5, 4, 2, 3, 1, 0]
```

---

## 💡 Core Intuition

A node with **in-degree 0** has no dependencies — it can be placed first. Once placed, remove its outgoing edges (decrement neighbors' in-degrees). Any neighbor that now hits in-degree 0 is ready to be placed next. Repeat until all nodes are placed.

> 🍽️ **Analogy:** A cafeteria queue — you can only join once everyone ahead of you has been served. Nodes with no one ahead (in-degree 0) go first. As each is served, they unblock the people behind them.

---

## 🤔 Why In-degree?

In-degree of a node = number of **incoming edges** = number of **prerequisites / dependencies**.

```
In-degree 0 → no prerequisites → can be processed immediately ✅
In-degree > 0 → has prerequisites → must wait ⏳

As we process a node u:
  For each neighbor v of u:
    inDegree[v]--         ← "one of v's prerequisites (u) is now done"
    if inDegree[v] == 0:
      q.push(v)           ← v is now ready ✅
```

---

## 🤔 Kahn's vs DFS Topo Sort — Key Difference

| | DFS (Post-order Stack) | Kahn's (BFS + In-degree) |
|-|----------------------|--------------------------|
| Direction | Go deep first, push on return | Process ready nodes first, unlock next |
| Cycle detection | ❌ Needs separate `inRec[]` | ✅ Built-in: `ans.size() != V` |
| Extra structure | Stack | In-degree array + Queue |
| Intuition | Finish dependencies before self | Process when all dependencies done |

---

## 🪜 Algorithm Steps

1. 🏗️ Build adjacency list from `edges`
2. 📐 Compute `inDegree[v]` for all nodes
3. 🏁 Push all nodes with `inDegree == 0` into queue
4. 🔁 While queue not empty:
   - Pop `u`, add to `ans`
   - For each neighbor `v`: decrement `inDegree[v]`
   - If `inDegree[v] == 0` → push `v` to queue
5. 📤 Return `ans`
   - Bonus: if `ans.size() != V` → cycle exists!

## 🧩 Dry Run

```
V=6, Edges: 5→0, 5→2, 4→0, 4→1, 2→3, 3→1

Adjacency list:
  5 → [0, 2]
  4 → [0, 1]
  2 → [3]
  3 → [1]
  0 → []
  1 → []

Step 1 — Compute in-degrees:
  0: edges from 5,4   → inDeg[0]=2
  1: edges from 4,3   → inDeg[1]=2
  2: edge from 5      → inDeg[2]=1
  3: edge from 2      → inDeg[3]=1
  4: no incoming      → inDeg[4]=0
  5: no incoming      → inDeg[5]=0

Step 2 — Push zero in-degree nodes:
  queue=[4,5]

Step 3 — BFS:

  pop 4 → ans=[4]
    neighbor 0: inDeg[0]=2→1
    neighbor 1: inDeg[1]=2→1
  queue=[5]

  pop 5 → ans=[4,5]
    neighbor 0: inDeg[0]=1→0 → push 0
    neighbor 2: inDeg[2]=1→0 → push 2
  queue=[0,2]

  pop 0 → ans=[4,5,0]
    no neighbors
  queue=[2]

  pop 2 → ans=[4,5,0,2]
    neighbor 3: inDeg[3]=1→0 → push 3
  queue=[3]

  pop 3 → ans=[4,5,0,2,3]
    neighbor 1: inDeg[1]=1→0 → push 1
  queue=[1]

  pop 1 → ans=[4,5,0,2,3,1]
    no neighbors
  queue=[]

Output: [4,5,0,2,3,1] ✅

Verify: ans.size()=6 == V=6 → no cycle ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<int> topoSort(int V, vector<vector<int>>& edges) {
        vector<vector<int>> adj(V);

        for (auto& e : edges)
            adj[e[0]].push_back(e[1]);     // directed: u → v

        // Step 1: compute in-degrees
        vector<int> inDegree(V, 0);
        for (int u = 0; u < V; u++)
            for (int v : adj[u])
                inDegree[v]++;

        // Step 2: push all zero in-degree nodes
        queue<int> q;
        for (int u = 0; u < V; u++)
            if (inDegree[u] == 0) q.push(u);

        // Step 3: BFS
        vector<int> ans;
        while (!q.empty()) {
            int u = q.front();
            ans.push_back(u);
            q.pop();

            for (int v : adj[u]) {
                inDegree[v]--;                   // remove edge u→v
                if (inDegree[v] == 0) q.push(v); // v is now ready
            }
        }

        // Bonus: ans.size() != V → cycle exists
        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(V + E) | In-degree computation O(E) + BFS O(V+E) |
| 🧠 **Space** | O(V + E) | Adjacency list + in-degree array + queue |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **In-degree 0 = ready to process** — no unresolved dependencies |
| 2 | **Decrement + check** — `inDegree[v]--; if(==0) push` is the core BFS step |
| 3 | **`ans.size() != V`** → cycle detected — powerful built-in check |
| 4 | Handles **disconnected graphs** — all zero in-degree nodes seeded initially |
| 5 | No stack needed — BFS naturally produces correct order |

---

## ⚠️ Common Mistakes

- ❌ **Computing in-degree from `edges` directly** instead of `adj[]` — both work but adj loop is cleaner
- ❌ **Not seeding ALL zero in-degree nodes** — only seeding one misses disconnected components
- ❌ **Not checking `ans.size() != V`** — silently gives wrong answer on cyclic graphs
- ❌ **Decrementing before popping** — always pop first, then update neighbors
- ❌ **Using `edges` instead of `adj[]` for neighbor traversal** — O(E) per node instead of O(degree)

---

## 🔁 Cycle Detection — Built Right In

```
DAG (no cycle):
  Every node eventually reaches in-degree 0 → gets pushed → processed
  ans.size() == V ✅

Cyclic Graph (e.g., A→B→C→A):
  Nodes in the cycle never reach in-degree 0
  They're never pushed to queue → never processed
  ans.size() < V ❌ → cycle detected!

if (ans.size() != V) {
    // graph has a cycle → topological sort impossible
}
```

This is why Kahn's is preferred when you need **both topo sort + cycle detection** simultaneously.

---

## 🔁 In-degree Computation — Two Equivalent Ways

```cpp
// Method 1: Loop over adj (your code — clean)
for (int u = 0; u < V; u++)
    for (int v : adj[u])
        inDegree[v]++;

// Method 2: Loop over edges directly
for (auto& e : edges)
    inDegree[e[1]]++;    // destination gets the in-degree

// Both are O(E), Method 2 is slightly more direct
```

## 🆚 Full Comparison — DFS vs Kahn's

| Feature | DFS + Stack | Kahn's BFS (this) |
|---------|------------|-------------------|
| Core idea | Post-order push | Process zero in-degree first |
| Cycle detection | ❌ Separate `inRec[]` needed | ✅ `ans.size() != V` |
| Extra space | Stack | In-degree array |
| Output order | Reverse DFS finish time | BFS discovery order |
| Easier to modify | ❌ | ✅ Great for extensions |
| Use for Course Schedule | Both work | Preferred |
| Use for actual order | Both work | Preferred (cleaner) |
