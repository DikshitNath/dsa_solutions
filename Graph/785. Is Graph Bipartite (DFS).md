# 🎨 Is Graph Bipartite? — DFS (2-Coloring)

> **Platform:** LeetCode 785 | **Topic:** Graphs | **Technique:** DFS 2-Coloring — Detect Odd Cycles

**Question Link:** https://leetcode.com/problems/is-graph-bipartite/

---

## 📌 Problem Summary

Given an undirected graph represented as an adjacency list `graph`, return `true` if the graph is **bipartite** — its nodes can be split into **two independent sets** such that every edge connects a node from one set to the other.

```
graph = [[1,3],[0,2],[1,3],[0,2]]
  0 — 1
  |   |     → forms a square (even cycle) → bipartite ✅
  3 — 2

graph = [[1,2,3],[0,2],[0,1,3],[0,2]]
  0 connected to 1,2,3
  2 connected to 0,1,3 → triangle exists → NOT bipartite ❌
```

---

## 💡 Core Intuition — 2-Coloring

A graph is bipartite **if and only if** it can be colored with 2 colors such that **no two adjacent nodes share the same color**. This is equivalent to saying the graph has **no odd-length cycles**.

**Strategy:** Try to 2-color the graph using DFS. Assign color 1 to start node, color 0 to all its neighbors, alternate as you go deeper. If you ever find a neighbor with the **same color** as the current node → conflict → **not bipartite**.

> 🎨 **Analogy:** Try to color a map where countries sharing a border must have different colors, using only 2 colors. If possible → bipartite. If you get stuck → not bipartite.

---

## 🤔 Why Does Odd Cycle = Not Bipartite?

```
Odd cycle of length 3 (triangle: 0—1—2—0):

Start: color[0] = 1
  DFS(1): color[1] = 0
    DFS(2): color[2] = 1
      neighbor 0: color[0]=1 == color[2]=1 → CONFLICT ❌

Even cycle of length 4 (square: 0—1—2—3—0):

Start: color[0] = 1
  DFS(1): color[1] = 0
    DFS(2): color[2] = 1
      DFS(3): color[3] = 0
        neighbor 0: color[0]=1 ≠ color[3]=0 → OK ✅

Even cycles alternate colors perfectly → bipartite ✅
Odd cycles always end with a conflict → not bipartite ❌
```

---

## 🤔 The Color Toggle — `1 - currColor`

```
currColor = 1 → 1 - 1 = 0  (flip to 0)
currColor = 0 → 1 - 0 = 1  (flip to 1)

Alternates between 0 and 1 at each DFS level ✅
Same as XOR: currColor ^ 1
```

---

## 🪜 Algorithm Steps

1. 🏁 `color[V] = -1` (all uncolored)
2. 🔁 For each unvisited node `i`:
   - Launch `dfs(graph, i, color, 1)`
   - If returns `false` → not bipartite
3. **Inside DFS:**
   - Assign `color[curr] = currColor`
   - For each neighbor `v`:
     - `color[v] == color[curr]` → **conflict → return false**
     - `color[v] == -1` → unvisited → recurse with flipped color
4. Return `true`

## 🧩 Dry Run — Bipartite

```
graph = [[1,3],[0,2],[1,3],[0,2]]
Edges: 0-1, 0-3, 1-2, 2-3  (square)

color = [-1,-1,-1,-1]

i=0: color[0]==-1 → DFS(0, color, 1)
  color[0]=1
  neighbor 1: color[1]==-1 → DFS(1, color, 0)
    color[1]=0
    neighbor 0: color[0]=1 ≠ 0 → skip (already colored, no conflict)
    neighbor 2: color[2]==-1 → DFS(2, color, 1)
      color[2]=1
      neighbor 1: color[1]=0 ≠ 1 → skip
      neighbor 3: color[3]==-1 → DFS(3, color, 0)
        color[3]=0
        neighbor 0: color[0]=1 ≠ 0 → skip
        neighbor 2: color[2]=1 ≠ 0 → skip
        return true
      return true
    return true
  neighbor 3: color[3]=0 ≠ 1 → skip (already colored, no conflict)
  return true

All nodes colored: [1,0,1,0]
Sets: {0,2} and {1,3} → bipartite ✅
```

## 🧩 Dry Run — Not Bipartite

```
graph = [[1,2],[0,2],[0,1]]
Triangle: 0-1-2-0

DFS(0, color=1):
  color[0]=1
  neighbor 1: DFS(1, color=0)
    color[1]=0
    neighbor 0: color[0]=1 ≠ 0 → skip
    neighbor 2: DFS(2, color=1)
      color[2]=1
      neighbor 0: color[0]=1 == color[2]=1 → return false ❌
    return false
  return false

return false → not bipartite ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    bool isBipartite(vector<vector<int>>& graph) {
        int V = graph.size();
        vector<int> color(V, -1);

        for (int i = 0; i < V; i++) {
            if (color[i] == -1) {
                if (!dfs(graph, i, color, 1)) return false;
            }
        }

        return true;
    }

    bool dfs(vector<vector<int>>& graph, int curr,
             vector<int>& color, int currColor) {
        color[curr] = currColor;

        for (int v : graph[curr]) {
            if (color[v] == color[curr]) return false;   // conflict!

            if (color[v] == -1) {
                int colorV = 1 - currColor;              // flip color
                if (!dfs(graph, v, color, colorV)) return false;
            }
        }

        return true;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Bipartite ↔ 2-colorable ↔ no odd cycles** — three equivalent definitions |
| 2 | **`1 - currColor`** — clean toggle between 0 and 1 |
| 3 | **`color[v] == color[curr]`** — conflict check must come BEFORE the `-1` check |
| 4 | **Outer loop handles disconnected graphs** — each component is checked separately |
| 5 | `-1` = unvisited, `0`/`1` = two color groups |

---

## ⚠️ Common Mistakes

- ❌ **Checking `color[v] == -1` before conflict check** → misses conflict on already-colored nodes
- ❌ **No outer loop** → disconnected components never get colored → wrong answer
- ❌ **Using `0` as initial color AND `0` as "unvisited"** → ambiguous; use `-1` for unvisited
- ❌ **Not propagating DFS false return** → `if (!dfs(...)) return false` must be inside neighbor loop

---

## 🔁 Conflict Check Order — Critical

```cpp
for (int v : graph[curr]) {

    // ✅ Correct order (your code):
    if (color[v] == color[curr]) return false;   // Step 1: check conflict
    if (color[v] == -1) { ... dfs ... }          // Step 2: recurse if uncolored

    // ❌ Wrong order:
    if (color[v] == -1) { ... dfs ... }
    if (color[v] == color[curr]) return false;
    // Problem: if v is already colored, step 1 is never reached!
    // (when color[v] != -1, neither block executes → conflict missed)
}
```

The `-1` check is `else if` in spirit — you only recurse on uncolored nodes; already-colored nodes just need the conflict check.

---

## 🆚 DFS vs BFS for Bipartite Check

| Feature | DFS (your code) | BFS |
|---------|----------------|-----|
| Color assignment | Pass as parameter | Read from parent in queue |
| Stack overflow risk | ✅ Deep graphs | ❌ None |
| Code style | Recursive | Iterative |
| Result | Identical | Identical |
| Preferred | Quick to write | Large graphs |

**BFS version sketch:**
```cpp
queue<int> q;
q.push(start);
color[start] = 0;
while (!q.empty()) {
    int u = q.front(); q.pop();
    for (int v : graph[u]) {
        if (color[v] == color[u]) return false;
        if (color[v] == -1) {
            color[v] = 1 - color[u];
            q.push(v);
        }
    }
}
```
