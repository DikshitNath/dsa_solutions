# 🎓 Course Schedule II — Kahn's Algorithm (BFS)

> **Platform:** LeetCode 210 | **Topic:** Graphs | **Technique:** Kahn's Algorithm — Return Topological Order

**Question Link:** https://leetcode.com/problems/course-schedule-ii/

---

## 📌 Problem Summary

Given `n` courses (0 to n-1) and prerequisites `[a, b]` meaning **"must finish `b` before taking `a`"**, return the **ordering of courses** to finish all of them. If impossible (cycle exists), return an **empty array `{}`**.

```
n=4, prerequisites=[[1,0],[2,0],[3,1],[3,2]]
Output: [0,2,1,3] or [0,1,2,3]  (multiple valid orders)

n=2, prerequisites=[[1,0],[0,1]]
Output: []  (cycle → impossible)
```

---

## 💡 Core Intuition

Identical to Course Schedule I — Kahn's BFS topo sort. The only upgrade: **collect the order** as we pop nodes from the queue. If `count == n`, all courses were completed → return the order. Otherwise → cycle → return `{}`.

> 📋 **Upgrade from LC 207:** Instead of just returning `count == V`, we also **store the topo order** and return it.

---

## 🤔 The Trilogy — Three Problems, One Algorithm

```

  return count == V          ← can we finish? (bool)

LC 210 — Course Schedule II (this):
  if count == n: return ans  ← what order? (vector)
  else: return {}

```

All three use **identical Kahn's BFS**. Only the return value changes.

---

## 🤔 Why Return `{}` for Cycles?

Topological ordering is **mathematically undefined** for graphs with cycles — there's no way to linearize nodes when A depends on B and B depends on A. The empty array is the standard signal for "impossible."

```
cycle: 0→1→0

For 0 to come before 1: 0 must come first
For 1 to come before 0: 1 must come first
Contradiction → no valid ordering exists → return {} ✅
```

---

## 🪜 Algorithm Steps

**`findOrder`:**
1. Build `adj[]` from prerequisites (`e[1] → e[0]` for each `[e[0], e[1]]`)
2. Compute `indegree[]` for all nodes
3. Call `topo(adj, n, indegree)`

**`topo`:**
1. Seed all `indegree == 0` nodes into queue
2. BFS: pop `u`, increment `count`, **push `u` to `ans`**, decrement neighbors
3. Push any neighbor that hits `indegree == 0`
4. If `count == n` → return `ans` (valid order)
5. Else → return `{}` (cycle exists)

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<int> topo(vector<vector<int>>& adj, int n, vector<int>& indegree) {
        queue<int> q;
        vector<int> ans;
        int count = 0;

        for (int i = 0; i < n; i++)
            if (indegree[i] == 0) q.push(i);

        while (!q.empty()) {
            int u = q.front();
            q.pop();
            count++;
            ans.push_back(u);           // collect topo order

            for (int v : adj[u]) {
                indegree[v]--;
                if (indegree[v] == 0) q.push(v);
            }
        }

        if (count == n) return ans;     // all processed → valid order
        return {};                      // cycle → impossible
    }

    vector<int> findOrder(int n, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(n);
        vector<int> indegree(n, 0);

        for (auto e : prerequisites) {
            adj[e[1]].push_back(e[0]);  // prereq e[1] → course e[0]
            indegree[e[0]]++;
        }

        return topo(adj, n, indegree);
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **`ans.push_back(u)`** inside BFS loop — collect topo order as we process |
| 2 | **`if (count == n) return ans; return {}`** — single check handles both cases |
| 3 | **Edge: `adj[e[1]].push_back(e[0])`** — prereq points to course, not reversed |
| 4 | Output order is BFS discovery order — valid but not the only valid answer |
| 5 | This is the **full upgrade** of LC 207 — one extra line (`ans.push_back`) |

---

## ⚠️ Common Mistakes

- ❌ **`adj[e[0]].push_back(e[1])`** → reversed graph → wrong topo order
- ❌ **`return ans` unconditionally** → wrong for cyclic graphs (partial order returned)
- ❌ **`return {}` when `count == n`** → logic fully inverted
- ❌ **`for(auto e: prerequisites)` by value** → fine here but use `auto& e` for efficiency

---

## 🔁 Edge Direction — Same Trap as LC 207

```
prerequisites = [[a, b]] = "take b before a"

b is a prerequisite of a
→ b unlocks a after completion
→ directed edge: b → a

In code:
  e[0]=a (needs prereq), e[1]=b (the prereq)
  adj[e[1]].push_back(e[0])  → adj[b].push_back(a) → b→a ✅
  indegree[e[0]]++           → indegree[a]++        ✅
```

---

## 🔁 What Makes a Valid Topological Order?

Multiple valid outputs exist. Any order is valid as long as for every edge `u → v`, node `u` appears before `v`.

```
Graph: 0→1, 0→2, 1→3, 2→3

Valid orders:
  [0,1,2,3] ✅
  [0,2,1,3] ✅

Invalid orders:
  [1,0,2,3] ❌ (0 must come before 1)
  [0,1,3,2] ❌ (2 must come before 3)
```

BFS topo sort produces one valid order based on queue insertion order (which depends on input order).
