# 🔗 Number of Provinces

> **Platform:** LeetCode 547 | **Topic:** Graphs | **Technique:** DFS on Adjacency Matrix — Count Connected Components

**Question Link:** https://leetcode.com/problems/number-of-provinces/

---

## 📌 Problem Summary

Given an `n×n` adjacency matrix `isConnected` where `isConnected[i][j] = 1` means cities `i` and `j` are directly connected, return the number of **provinces** — groups of directly or indirectly connected cities.

```
isConnected = [[1,1,0],
               [1,1,0],
               [0,0,1]]
Output: 2   (cities 0,1 form one province; city 2 alone)

isConnected = [[1,0,0],
               [0,1,0],
               [0,0,1]]
Output: 3   (all isolated)
```

> 📝 This is the classic **"count connected components"** problem on an undirected graph.

---

## 💡 Core Intuition

Each unvisited node is the start of a new component (province). Launch DFS from it — mark all reachable nodes as visited. Every DFS launch = one new province. Count the launches.

> 🗺️ **Analogy:** Imagine each city as a dot, roads as lines. Count the number of separate "islands" of dots — each island is a province.

---

## 🔵 Approach 1 — Build Adjacency List First

### 💡 Intuition

Convert the adjacency matrix to an adjacency list, then run standard DFS on the list. Cleaner separation of concerns — graph construction is separate from traversal.

### 💻 Solution

```cpp
class Solution {
public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = isConnected.size();
        vector<vector<int>> adj(n);
        vector<bool> vis(n, false);

        // Build adjacency list from matrix
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (isConnected[i][j] == 1)
                    adj[i].push_back(j);   // undirected: both directions

        int count = 0;
        for (int i = 0; i < n; i++)
            if (!vis[i]) { dfs(adj, i, vis); count++; }

        return count;
    }

    void dfs(vector<vector<int>>& adj, int u, vector<bool>& vis) {
        vis[u] = true;
        for (int v : adj[u])
            if (!vis[v]) dfs(adj, v, vis);
    }
};
```

### 📊 Complexity

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ Time | O(N²) | Reading the full N×N matrix to build adj list |
| 🧠 Space | O(N²) | Adj list stores up to N² edges + recursion stack |

## 🟢 Approach 2 — DFS Directly on Matrix (Optimal)

### 💡 Intuition

Skip building the adjacency list. DFS directly reads neighbors from `isConnected[u][v]`. Saves the O(N²) space of the adjacency list.

### 💻 Solution

```cpp
class Solution {
public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = isConnected.size();
        vector<bool> vis(n, false);

        int count = 0;
        for (int i = 0; i < n; i++)
            if (!vis[i]) { dfs(isConnected, i, vis, n); count++; }

        return count;
    }

    void dfs(vector<vector<int>>& isConnected, int u, vector<bool>& vis, int n) {
        vis[u] = true;
        for (int v = 0; v < n; v++)
            if (!vis[v] && isConnected[u][v] == 1)
                dfs(isConnected, v, vis, n);
    }
};
```

### 📊 Complexity

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ Time | O(N²) | Each cell of N×N matrix visited once |
| 🧠 Space | O(N) | Only vis[] array + O(N) recursion stack |

## 🧩 Dry Run

```
isConnected = [[1,1,0],
               [1,1,0],
               [0,0,1]]

vis = [F, F, F], count = 0

i=0: vis[0]=F → DFS(0)
  vis[0]=T
  v=0: vis[0]=T → skip
  v=1: vis[1]=F, isConn[0][1]=1 → DFS(1)
    vis[1]=T
    v=0: vis[0]=T → skip
    v=1: vis[1]=T → skip
    v=2: isConn[1][2]=0 → skip
  v=2: isConn[0][2]=0 → skip
  count++ → count=1

i=1: vis[1]=T → skip

i=2: vis[2]=F → DFS(2)
  vis[2]=T
  v=0: isConn[2][0]=0 → skip
  v=1: isConn[2][1]=0 → skip
  v=2: vis[2]=T → skip
  count++ → count=2

return 2 ✅
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Number of provinces = number of connected components** |
| 2 | **Outer loop launches DFS** — each launch = one new component = one province |
| 3 | **DFS marks all reachable nodes** — so subsequent outer loop iterations skip them |
| 4 | **Approach 2 is preferred** — same time complexity, O(N) vs O(N²) space |
| 5 | **`isConnected[i][i] = 1`** always (diagonal) — city is always connected to itself, handled by `vis[]` |

---

## ⚠️ Common Mistakes

- ❌ **Not skipping `vis[v]`** → infinite recursion on undirected edges (0→1→0→1→...)
- ❌ **Building undirected adj with both `adj[i]→j` and `adj[j]→i`** → double edges (harmless but redundant with vis check)
- ❌ **Checking `isConnected[u][v] == 1` without `!vis[v]`** → revisits nodes → TLE
- ❌ **Counting DFS calls instead of outer loop launches** → DFS is recursive, inner calls ≠ new provinces

---

## 🔁 Why Approach 2 is Better

```
Approach 1:
  Build adj list: O(N²) time + O(N²) space
  DFS on adj list: O(N + E) time + O(N) space
  Total space: O(N²)  ← adj list stores all edges

Approach 2:
  No adj list: saved O(N²) space
  DFS directly on matrix: O(N²) time (same — still reads all cells)
  Total space: O(N) ← only vis[] array

Time is identical. Approach 2 uses strictly less space.
```

## 🆚 Approach 1 vs Approach 2

| Feature | Adj List + DFS | Matrix DFS (Optimal) |
|---------|---------------|----------------------|
| Time | O(N²) | O(N²) |
| Space | O(N²) | O(N) ✅ |
| Code clarity | Cleaner DFS | Slightly more logic in DFS |
| Reusability | adj usable elsewhere | Matrix-specific |
| Interview pick | Shows graph building | Preferred for adjacency matrix |

## 🔁 Connected Components — General Template

```cpp
// Works for ANY undirected graph problem asking "how many groups?"
int count = 0;
for (int i = 0; i < n; i++) {
    if (!vis[i]) {
        dfs(i);    // marks all nodes in this component
        count++;   // one new component found
    }
}
return count;
```

This outer loop + DFS pattern is the foundation for:
- Number of Provinces (this)
- Number of Islands (2D grid)
- Number of Connected Components in Graph
- Friend Circles / Social Network clustering
