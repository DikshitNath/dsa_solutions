# 🎨 Flood Fill

> **Platform:** LeetCode | **Topic:** Graph / Matrix | **Technique:** DFS Flood Fill

**Question Link:** [https://leetcode.com/problems/flood-fill/](https://leetcode.com/problems/flood-fill/)

---

## 📌 Problem Summary

Given an `m x n` image (2D array of pixel colors), a starting pixel `(sr, sc)`, and a new `color`, perform a **flood fill** — recolor the starting pixel and all 4-directionally connected pixels of the same original color to the new color.

---

## 💡 Core Intuition

Starting from `(sr, sc)`, recursively spread the new color to all neighboring cells that share the **original color**. Stop when hitting boundaries, different-colored cells, or already-recolored cells.

> 🖌️ **Analogy:** Like the paint bucket tool in MS Paint — click a region and it fills all connected same-colored pixels with the new color instantly.

---

## 🤔 Why the `originColor == color` Early Return?

If the new color is **identical** to the original, every cell would pass the `image[sr][sc] != originColor` check — the fill never stops → **infinite recursion**.

    originColor = 1, newColor = 1
    → fill cell → still passes check → fill again → infinite loop ❌

    Early return short-circuits this case immediately ✅

---

## 🤔 No Separate `vis[]` Needed?

Unlike generic graph DFS, we don't need a visited array here. Changing `image[sr][sc] = color` **acts as the visited marker** — a recolored cell no longer matches `originColor`, so DFS naturally skips it.

    image[sr][sc] = color   →   next call sees color ≠ originColor → returns ✅

---

## 🪜 Algorithm Steps

1. 🎨 Save `originColor = image[sr][sc]`
2. 🚫 If `originColor == color` → return immediately (no-op)
3. 🔁 Run DFS from `(sr, sc)`:
   - If out of bounds OR `image[sr][sc] != originColor` → return
   - Set `image[sr][sc] = color` ← recolor + mark visited
   - Recurse in all 4 directions
4. 📤 Return modified image

### Base Case Breakdown

    if (sr < 0 || sr >= m || sc < 0 || sc >= n || image[sr][sc] != originColor)
        return;
         ↑                  ↑                          ↑
    top/left edge    bottom/right edge        wrong color OR already filled

### Pseudocode

    floodFill(image, sr, sc, color):
        originColor = image[sr][sc]
        if originColor == color → return image    // avoid infinite loop

        dfs(image, sr, sc, color)
        return image

    dfs(image, sr, sc, color):
        if out of bounds OR image[sr][sc] != originColor → return

        image[sr][sc] = color           // recolor = visited marker

        dfs(image, sr+1, sc, color)     // down
        dfs(image, sr-1, sc, color)     // up
        dfs(image, sr, sc+1, color)     // right
        dfs(image, sr, sc-1, color)     // left

### Full C++ Solution

```cpp
class Solution {
public:
    int m, n, originColor;

    vector<vector<int>> floodFill(vector<vector<int>>& image,
                                   int sr, int sc, int color) {
        m = image.size();
        n = image.size();
        originColor = image[sr][sc];

        if (originColor == color) return image;     // avoid infinite loop

        dfs(image, sr, sc, color);
        return image;
    }

    void dfs(vector<vector<int>>& image, int sr, int sc, int color) {
        if (sr < 0 || sr >= m || sc < 0 || sc >= n ||
            image[sr][sc] != originColor) return;

        image[sr][sc] = color;                      // recolor + mark visited

        dfs(image, sr+1, sc, color);                // down
        dfs(image, sr-1, sc, color);                // up
        dfs(image, sr, sc+1, color);                // right
        dfs(image, sr, sc-1, color);                // left
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(M × N) | Each cell visited at most once |
| 🧠 **Space** | O(M × N) | Recursion stack in worst case (all same color) |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Recoloring acts as visited marker** — no separate `vis[]` array needed |
| 2 | **Early return when `originColor == color`** — prevents infinite recursion |
| 3 | DFS stops on **color mismatch** — only spreads through connected same-color region |
| 4 | This is the foundation for **Number of Islands** and similar flood fill problems |

---

## ⚠️ Common Mistakes

- ❌ **Missing `originColor == color` check** → infinite recursion when colors are same
- ❌ **Checking `image[sr][sc] != color`** instead of `!= originColor` → breaks when filling over a region that partially overlaps the new color
- ❌ **Using a separate `vis[]`** → unnecessary; the color change itself serves as the marker

---

## 🆚 Flood Fill vs Number of Islands

| Feature | Flood Fill | Number of Islands |
|---------|-----------|-------------------|
| Visited marker | Overwrite with new color | Mark as `'$'` or `'0'` |
| What to count | Nothing (modify in place) | Number of DFS triggers |
| Stop condition | Color mismatch | Not `'1'` |
| Returns | Modified image | Integer count |
