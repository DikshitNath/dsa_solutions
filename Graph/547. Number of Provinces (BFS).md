# 🔗 Number of Provinces — BFS

> **Platform:** LeetCode 547 | **Topic:** Graphs | **Technique:** BFS — Count Connected Components

**Question Link:** https://leetcode.com/problems/number-of-provinces/

## 📌 Problem Summary

Given an `n×n` adjacency matrix `isConnected`, return the number of **provinces** (connected components).

```
isConnected = [[1,1,0],
               [1,1,0],
               [0,0,1]]
Output: 2   (cities 0,1 together; city 2 alone)
```

> 📝 You already have the DFS version in previous notes. This is the **BFS variant** — same outer loop, different traversal engine.

## 🚨 Critical Bug in Your Code

Your BFS function has a bug — **it calls `bfs()` recursively instead of using the queue**:

```cpp
// ❌ Your code — BFS that calls itself recursively (defeats the purpose)
while (!q.empty()) {
    int curr = q.front();
    q.pop();

    for (int v : adj[curr]) {
        if (!vis[v]) {
            bfs(adj, v, vis);   // ← recursive call, not pushing to queue!
        }
    }
}

// ✅ Correct BFS — push neighbors to queue, don't recurse
while (!q.empty()) {
    int curr = q.front();
    q.pop();

    for (int v : adj[curr]) {
        if (!vis[v]) {
            vis[v] = true;      // mark BEFORE pushing to avoid duplicates
            q.push(v);          // ← push to queue, not recursive call
        }
    }
}
```

**What your code actually does:** Launches a new BFS for each unvisited neighbor — creating independent BFS calls that share the same `vis[]`. It works correctly because `vis[]` is shared by reference, but it's not true BFS — it's accidental recursion that happens to produce the right answer.

**True BFS** explores all neighbors level-by-level using the queue without ever calling itself.

---

## 💡 Core Intuition

Same as DFS version: each outer loop launch = one new province. BFS marks all reachable nodes via queue instead of call stack.

> 🌊 **BFS vs DFS for this problem:** Both explore the same nodes, just in different orders. BFS is iterative (no stack overflow risk). DFS is recursive (simpler code, but risky on large graphs).

## 💻 Corrected BFS Solution

```cpp
class Solution {
public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = isConnected.size();
        vector<vector<int>> adj(n);
        vector<bool> vis(n, false);

        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (isConnected[i][j] == 1)
                    adj[i].push_back(j);

        int count = 0;
        for (int i = 0; i < n; i++)
            if (!vis[i]) { bfs(adj, i, vis); count++; }

        return count;
    }

    void bfs(vector<vector<int>>& adj, int u, vector<bool>& vis) {
        vis[u] = true;
        queue<int> q;
        q.push(u);

        while (!q.empty()) {
            int curr = q.front();
            q.pop();

            for (int v : adj[curr]) {
                if (!vis[v]) {
                    vis[v] = true;   // mark before pushing ✅
                    q.push(v);       // push to queue, NOT recursive call ✅
                }
            }
        }
    }
};
```

## 💻 BFS Directly on Matrix (No Adj List)

```cpp
class Solution {
public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = isConnected.size();
        vector<bool> vis(n, false);
        int count = 0;

        for (int i = 0; i < n; i++) {
            if (!vis[i]) {
                vis[i] = true;
                queue<int> q;
                q.push(i);

                while (!q.empty()) {
                    int curr = q.front(); q.pop();
                    for (int v = 0; v < n; v++) {
                        if (!vis[v] && isConnected[curr][v] == 1) {
                            vis[v] = true;
                            q.push(v);
                        }
                    }
                }
                count++;
            }
        }
        return count;
    }
};
```

## ⚠️ Common Mistakes

- ❌ **`q.push(v)` without `vis[v]=true`** → same node pushed multiple times → TLE
- ❌ **Recursive call inside BFS** → your exact bug — not true BFS, just accidental DFS in disguise
- ❌ **`vis[u]=true` outside BFS** → forgetting to mark start node → start node revisited
- ❌ **Counting after BFS regardless of `vis`** → `count++` must be inside `if (!vis[i])` only

---

## 🔁 Mark Before Push vs Mark After Pop

```cpp
// ❌ Mark after pop (common mistake)
while (!q.empty()) {
    int curr = q.front(); q.pop();
    vis[curr] = true;                    // too late!
    for (int v : adj[curr])
        if (!vis[v]) q.push(v);         // v may be pushed multiple times
}

// ✅ Mark before push (correct)
if (!vis[v]) {
    vis[v] = true;                       // marked immediately
    q.push(v);                           // guaranteed pushed only once
}
```

Marking before push ensures each node enters the queue **exactly once** — crucial for correctness and efficiency.
