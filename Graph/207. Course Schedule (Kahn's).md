# 🎓 Course Schedule — Kahn's Algorithm (BFS)

> **Platform:** LeetCode 207 | **Topic:** Graphs | **Technique:** Kahn's Algorithm — Cycle Detection via Count Check

**Question Link:** https://leetcode.com/problems/course-schedule/

---

## 📌 Problem Summary

Given `V` courses (0 to V-1) and prerequisites `[a, b]` meaning **"to take course `a`, you must first finish course `b`"**, return `true` if you can finish all courses — i.e., **no cycle** exists in the dependency graph.

```
V=2, prerequisites=[[1,0]]       → true  (0 must be done before 1, linear)
V=2, prerequisites=[[1,0],[0,1]] → false (0 needs 1, 1 needs 0 → deadlock)
```

---

## 💡 Core Intuition

Model as a directed graph. If a **cycle exists → deadlock → can't finish**. Use Kahn's Algorithm: nodes in a cycle **never reach in-degree 0** and are never processed. If `count == V`, all nodes were processed → no cycle → can finish.

> 🔗 **Connection to previous problem:** This is identical to "Detect Cycle in Directed Graph" — just returns `!hasCycle` instead of `hasCycle`.

---

## 🤔 Critical Detail — Edge Direction

Prerequisites `[a, b]` means **"b must come before a"** → directed edge `b → a`.

```cpp
// prerequisite [a, b] = "take b before a" = b → a
adj[v].push_back(u);   // v=b, u=a → edge b→a
indegree[u]++;         // a has one more prerequisite
```

If you reverse this (`adj[u]→v`), the graph is flipped and the topo order is wrong.

```
prerequisites = [[1,0]] means: finish 0 before 1
  Correct edge: 0 → 1 (0 is prerequisite of 1)
  adj[0].push_back(1)  ✅

  Your code: adj[v].push_back(u) where v=e[1]=0, u=e[0]=1
  → adj[0].push_back(1) ✅ same result
```

---

## 🤔 Why a Separate `topo()` Function?

Separating the Kahn's BFS into its own function makes the code:
- **Reusable** — `topo()` can be called for any graph
- **Testable** — cycle detection logic is isolated
- **Clean** — `canFinish` only handles graph construction

This is good code design for interviews — shows separation of concerns.

---

## 🪜 Algorithm Steps

**`canFinish`:**
1. Build `adj[]` from prerequisites (`v → u` for each `[u, v]`)
2. Compute `indegree[]` for all nodes
3. Call `topo(adj, indegree, V)`

**`topo`:**
1. Seed all `indegree == 0` nodes into queue
2. BFS: pop `u`, increment `count`, decrement neighbors' in-degrees
3. If any neighbor hits `indegree == 0` → push to queue
4. Return `count == V`

## 🧩 Dry Run — Can Finish (No Cycle)

```
V=4, prerequisites=[[1,0],[2,0],[3,1],[3,2]]
Meaning: 0 before 1, 0 before 2, 1 before 3, 2 before 3

Edges (v→u from [u,v]):
  [1,0] → 0→1
  [2,0] → 0→2
  [3,1] → 1→3
  [3,2] → 2→3

adj:  0→[1,2], 1→[3], 2→[3]
inDeg: 0=0, 1=1, 2=1, 3=2

Seed: push 0, count=0
queue=[0]

pop 0, count=1:
  neighbor 1: inDeg[1]=1→0 → push 1
  neighbor 2: inDeg[2]=1→0 → push 2
queue=[1,2]

pop 1, count=2:
  neighbor 3: inDeg[3]=2→1
queue=[2]

pop 2, count=3:
  neighbor 3: inDeg[3]=1→0 → push 3
queue=[3]

pop 3, count=4:
  no neighbors
queue=[]

count=4 == V=4 → return true ✅
```

## 🧩 Dry Run — Cannot Finish (Cycle)

```
V=3, prerequisites=[[0,1],[1,2],[2,0]]
Meaning: 1 before 0, 2 before 1, 0 before 2 → cycle!

Edges (v→u):
  [0,1] → 1→0
  [1,2] → 2→1
  [2,0] → 0→2

adj:  1→[0], 2→[1], 0→[2]
inDeg: 0=1(from 1), 1=1(from 2), 2=1(from 0)

Seed: no node has inDeg=0 → queue empty, count=0

BFS: queue empty → loop never runs

count=0 != V=3 → return false ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    bool topo(vector<vector<int>>& adj, vector<int>& indegree, int V) {
        queue<int> q;

        for (int i = 0; i < V; i++)
            if (indegree[i] == 0) q.push(i);

        int count = 0;

        while (!q.empty()) {
            int u = q.front();
            q.pop();
            count++;                          // node successfully processed

            for (int v : adj[u]) {
                indegree[v]--;
                if (indegree[v] == 0) q.push(v);
            }
        }

        return count == V;    // all nodes processed = no cycle = can finish
    }

    bool canFinish(int V, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(V);
        vector<int> indegree(V, 0);

        for (auto& e : prerequisites) {
            int u = e[0], v = e[1];
            adj[v].push_back(u);   // "v before u" → edge v→u
            indegree[u]++;
        }

        return topo(adj, indegree, V);
    }
};
```

## ⚠️ Common Mistakes

- ❌ **`adj[u].push_back(v)` instead of `adj[v].push_back(u)`** → reversed graph → wrong topo order
- ❌ **`indegree[v]++` instead of `indegree[u]++`** → wrong in-degree tracking
- ❌ **`count != V` instead of `count == V`** → returns false when it should return true (logic flipped)
- ❌ **Not passing `indegree` by reference** → `topo()` gets a copy, original unchanged — works here since we don't reuse it, but matters in other contexts

## 🔁 Edge Direction — The Subtle Trap

```
prerequisites = [[a, b]] means "take b before a"

Interpretation as dependency graph:
  b is a prerequisite of a → b must come before a in topo order
  → directed edge: b → a

In code:
  e[0] = a (the course needing the prereq)
  e[1] = b (the prerequisite)
  adj[e[1]].push_back(e[0])  → adj[b].push_back(a) → b→a ✅
  indegree[e[0]]++           → indegree[a]++        ✅

Common mistake:
  adj[e[0]].push_back(e[1])  → a→b ❌ (reversed)
```
