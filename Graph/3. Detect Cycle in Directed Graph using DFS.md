# 🔄 Detect Cycle in a Directed Graph (DFS)

> **Platform:** GeeksForGeeks | **Topic:** Graph | **Technique:** DFS + Recursion Stack

**Question Link:** https://www.geeksforgeeks.org/problems/detect-cycle-in-a-directed-graph/1
---

## 📌 Problem Summary

Given a **directed graph** with `V` vertices and a list of edges, determine whether the graph contains **any cycle**.

---

## 💡 Core Intuition

In a directed graph, a cycle exists when DFS reaches a node that is **already part of the current DFS call stack** — meaning we've looped back to an ancestor in the same path.

> 🔦 **Analogy:** Imagine following a one-way road system. If you ever end up on a road you're currently travelling — you're going in circles.

---

## 🤔 Why `inRec[]` Instead of Just `vis[]`?

This is the **key difference** from undirected cycle detection.

| Scenario | Undirected | Directed |
|----------|-----------|---------|
| Already visited neighbor | = Cycle 🚨 | Not necessarily a cycle ⚠️ |
| Cycle condition | `vis[v] && v != parent` | `inRec[v] == true` |

In a directed graph, a visited node might have been explored via a **completely different path**. Only if it's in the **current active DFS path** (`inRec`) does it confirm a cycle.

---

## 🪜 Algorithm Steps

1. 🏗️ Build a **directed adjacency list** (one direction only: `u → v`)
2. 🔁 Iterate over all vertices to handle **disconnected components**
3. 🚀 For each unvisited vertex, run DFS
4. 🔍 Inside DFS:
   - Mark `vis[u] = true` and `inRec[u] = true`
   - For each neighbor `v`:
     - `!vis[v]` → recurse; if it returns `true` → 🚨 cycle
     - `inRec[v]` → 🚨 back edge to ancestor = **cycle!**
   - Before returning, **unmark** `inRec[u] = false` (backtrack)

### Full C++ Solution

```cpp
class Solution {
  public:
    bool isCycleDFS(vector<vector<int>>& adj, vector<bool>& vis,
                    int u, vector<bool>& inRec) {
        vis[u] = true;
        inRec[u] = true;

        for (int v : adj[u]) {
            if (!vis[v] && isCycleDFS(adj, vis, v, inRec))
                return true;            // cycle found deeper in DFS
            else if (inRec[v])
                return true;            // back edge = cycle!
        }

        inRec[u] = false;               // backtrack: remove from current path
        return false;
    }

    bool isCyclic(int V, vector<vector<int>>& edges) {
        vector<vector<int>> adj(V);
        for (auto& e : edges)
            adj[e].push_back(e); // directed: only one way

        vector<bool> vis(V, false);
        vector<bool> inRec(V, false);

        for (int i = 0; i < V; i++) {
            if (!vis[i] && isCycleDFS(adj, vis, i, inRec))
                return true;
        }
        return false;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | `O(V + E)` | DFS visits every node and edge once |
| 🧠 **Space** | `O(V + E)` | Adj list + `vis[]` + `inRec[]` + recursion stack |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | `inRec[]` tracks the **current DFS path**, not all visited nodes |
| 2 | `inRec[u] = false` on backtrack is **essential** — don't forget it |
| 3 | Adjacency list is **one-directional** for directed graphs |
| 4 | Outer loop handles **disconnected components** |

---

## ⚠️ Common Mistakes

- ❌ **Forgetting `inRec[u] = false`** on backtrack → causes false positives for other paths
- ❌ **Building bidirectional adj list** → converts it into an undirected graph
- ❌ **Using only `vis[]`** → a node visited from another path falsely triggers a cycle

---

## 🆚 Undirected vs Directed Cycle Detection

| Feature | Undirected (DFS) | Directed (DFS) |
|---------|-----------------|----------------|
| Extra array | ❌ Just `vis[]` + parent | ✅ `vis[]` + `inRec[]` |
| Cycle condition | `vis[v] && v != parent` | `inRec[v] == true` |
| Edge direction | Bidirectional adj list | One-way adj list |
| Backtracking needed | ❌ No | ✅ Yes (`inRec[u] = false`) |
