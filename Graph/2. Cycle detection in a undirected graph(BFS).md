# 🔄 Detect Cycle in an Undirected Graph (BFS)

> **Platform:** GeeksForGeeks | **Topic:** Graph | **Technique:** BFS

**Question Link:** https://www.geeksforgeeks.org/problems/detect-cycle-in-an-undirected-graph/1

---

## 📌 Problem Summary

Given an undirected graph with `V` vertices and a list of edges, determine whether the graph contains **any cycle** — using a **BFS (level-order)** approach.

---

## 💡 Core Intuition

Instead of recursion, we use a **queue** that stores each node along with its **parent**. During BFS, if we encounter a neighbor that is:
- ✅ Already visited
- ❌ Not the current node's parent

→ We've found a **back edge** — a cycle exists!

> 🥾 **Analogy:** Imagine spreading water level by level. If the water from two different paths reaches the same spot — there's a loop in between.

---

## 🤔 BFS vs DFS — Why Store Parent in Queue?

In DFS, parent is passed as a **function argument** (tracked via call stack).

In BFS, there's no call stack — so we store `{node, parent}` as a **pair in the queue** to remember where each node came from.

---

## 🪜 Algorithm Steps

1. 🏗️ Build an **adjacency list** from the edge list
2. 🔁 Iterate over all vertices to handle **disconnected components**
3. 🚀 For each unvisited vertex, start BFS — push `{node, -1}` into queue
4. 🔍 For each node dequeued, check all neighbors `v`:
   - `!vis[v]` → mark visited, push `{v, current}` into queue ✅
   - `vis[v] && v != parent` → 🚨 **cycle found!** return `true`

## 🧩 Code Walkthrough

### Pseudocode

```cpp
isCycleBFS(adj, start, vis):
    push {start, -1} into queue
    vis[start] = true

    while queue not empty:
        {ele, parent} = dequeue

        for v in adj[ele]:
            if !vis[v]:
                vis[v] = true
                enqueue {v, ele}
            else if v != parent:
                return true 🚨 back edge = cycle!

    return false

isCycle(V, edges):
    Build adj list
    for each vertex i:
        if not visited:
            if isCycleBFS(adj, i, vis) → return true
    return false
```


### Full C++ Solution

```cpp
class Solution {
  public:
    bool isCycleBFS(vector<vector<int>>& adj, int u, vector<bool>& vis) {
        queue<pair<int, int>> q;
        q.push({u, -1});
        vis[u] = true;

        while (!q.empty()) {
            auto [ele, parent] = q.front();
            q.pop();

            for (int v : adj[ele]) {
                if (!vis[v]) {
                    vis[v] = true;
                    q.push({v, ele});       // store parent alongside node
                } else if (v != parent) {
                    return true;            // back edge = cycle!
                }
            }
        }
        return false;
    }

    bool isCycle(int V, vector<vector<int>>& edges) {
        vector<vector<int>> adj(V);
        for (auto& e : edges) {
            adj[e].push_back(e);
            adj[e].push_back(e);
        }

        vector<bool> vis(V, false);
        for (int i = 0; i < V; i++) {
            if (!vis[i] && isCycleBFS(adj, i, vis))
                return true;
        }
        return false;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | `O(V + E)` | BFS visits every node and edge once |
| 🧠 **Space** | `O(V + E)` | Adj list + visited array + queue |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | Parent is stored **inside the queue** as a pair — no recursion stack needed |
| 2 | `vis[v] && v != parent` is the **exact cycle condition** |
| 3 | Outer `for` loop handles **disconnected components** |
| 4 | BFS and DFS solutions have the **same time and space complexity** |

---

## ⚠️ Common Mistakes

- ❌ **Not storing parent in queue** → can't distinguish back edges from tree edges
- ❌ **Skipping the outer loop** → disconnected components go unchecked
- ❌ **Only checking `vis[v]`** without `v != parent` → every edge is a false cycle

---

## 🆚 DFS vs BFS Approach

| Feature | DFS | BFS |
|--------|-----|-----|
| Parent tracking | Function argument | Stored in queue pair |
| Uses recursion | ✅ Yes | ❌ No |
| Stack overflow risk | ⚠️ Large graphs | ✅ Safe |
| Code complexity | Slightly simpler | Slightly more explicit |
