# 🔄 Detect Cycle in Directed Graph — Kahn's Algorithm (BFS)

> **Platform:** GFG | **Topic:** Graphs | **Technique:** Kahn's Algorithm — Count vs V Check

**GFG Link:** https://www.geeksforgeeks.org/detect-cycle-in-a-directed-graph-using-bfs/

---

## 📌 Problem Summary

Given a Directed Graph with `V` vertices and `E` edges, return `true` if the graph contains a **cycle**, `false` otherwise.

```
Edges: [[0,1],[1,2],[2,0]]  → true  (0→1→2→0, cycle!)
Edges: [[0,1],[1,2]]        → false (0→1→2, linear DAG)
```

---

## 💡 Core Intuition

Kahn's Algorithm for Topological Sort **only works on DAGs** (no cycles). If a cycle exists, the nodes inside it **never reach in-degree 0** — they always have at least one unresolved incoming edge from within the cycle. So they're never added to the queue and never processed.

**Key insight:**
```
No cycle → every node eventually gets in-degree 0 → count == V ✅
Cycle exists → nodes in cycle never reach in-degree 0 → count < V ❌
```

> 🪤 **Analogy:** A group of people each waiting for someone else in the group to go first. Nobody can move — they're deadlocked. That deadlock is the cycle. The count of people who successfully moved will be less than the total.

---

## 🤔 Why Count Instead of Boolean Flag?

We track `count` = number of nodes successfully processed (reached in-degree 0 at some point). If `count == V`, all nodes were processed → no cycle. If `count < V`, some nodes were stuck → cycle exists.

```cpp
return count != V;   // true = cycle exists, false = no cycle
```

This is essentially **reusing the topo sort** — if topo sort can complete for all nodes → DAG → no cycle.

---

## 🤔 Your Code — Two Ways to Count

Your code increments `count` in **both** the initial seeding loop and inside the BFS loop:

```cpp
// Seeding: count nodes pushed initially
for (int i = 0; i < V; i++)
    if (indegree[i] == 0) { q.push(i); count++; }

// BFS: count nodes unlocked during traversal
if (indegree[v] == 0) { q.push(v); count++; }
```

This is equivalent to counting **every node that ever gets pushed to the queue** = every node that was ever "processable". Simpler alternative: count pops instead.

```cpp
// Cleaner alternative — count pops (= nodes processed)
while (!q.empty()) {
    int u = q.front(); q.pop();
    count++;                        // count here instead
    for (int v : adj[u]) { ... }
}
```

Both approaches give the same result.

---

## 🪜 Algorithm Steps

1. 🏗️ Build adjacency list from `edges`
2. 📐 Compute `inDegree[v]` for all nodes
3. 🏁 Push all `inDegree == 0` nodes to queue, count them
4. 🔁 BFS:
   - Pop `u`, decrement neighbors' in-degrees
   - If any neighbor hits `inDegree == 0` → push + count
5. 📤 Return `count != V`

## 🧩 Dry Run — Cycle Exists

```
V=3, Edges: [[0,1],[1,2],[2,0]]
Graph: 0→1→2→0

In-degrees:
  0: incoming from 2 → inDeg[0]=1
  1: incoming from 0 → inDeg[1]=1
  2: incoming from 1 → inDeg[2]=1

All in-degrees > 0 → NO node seeded to queue
count = 0

BFS loop: queue is empty → loop never runs

count=0 != V=3 → return true ✅ (cycle detected!)
```

## 🧩 Dry Run — No Cycle

```
V=4, Edges: [[0,1],[0,2],[1,3],[2,3]]
Graph: 0→1→3, 0→2→3

In-degrees:
  0: 0 incoming  → inDeg[0]=0
  1: from 0      → inDeg[1]=1
  2: from 0      → inDeg[2]=1
  3: from 1,2    → inDeg[3]=2

Seed: push 0, count=1
queue=[0]

pop 0:
  neighbor 1: inDeg[1]=1→0 → push 1, count=2
  neighbor 2: inDeg[2]=1→0 → push 2, count=3
queue=[1,2]

pop 1:
  neighbor 3: inDeg[3]=2→1 (not 0, don't push)
queue=[2]

pop 2:
  neighbor 3: inDeg[3]=1→0 → push 3, count=4
queue=[3]

pop 3: no neighbors
queue=[]

count=4 == V=4 → return false ✅ (no cycle)
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    bool isCyclic(int V, vector<vector<int>>& edges) {
        vector<vector<int>> adj(V);

        for (auto& e : edges)
            adj[e[0]].push_back(e[1]);

        // Compute in-degrees
        vector<int> inDegree(V, 0);
        for (int u = 0; u < V; u++)
            for (int v : adj[u])
                inDegree[v]++;

        // Seed all zero in-degree nodes
        queue<int> q;
        int count = 0;
        for (int i = 0; i < V; i++)
            if (inDegree[i] == 0) { q.push(i); }

        // BFS — Kahn's algorithm
        while (!q.empty()) {
            int u = q.front();
            q.pop();

            count++;                // total pops = total nodes processed

            for (int v : adj[u]) {
                inDegree[v]--;
                if (inDegree[v] == 0) { q.push(v); }
            }
        }

        return count != V;   // true = cycle, false = no cycle
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Cycle nodes never reach in-degree 0** — permanently blocked by each other |
| 2 | **`count != V`** is the entire cycle detection logic — elegant and O(1) extra |
| 3 | Counting pushes (your approach) = counting pops = same result |
| 4 | Works for **disconnected graphs** — all zero in-degree nodes seeded initially |
| 5 | This is literally **topo sort + one comparison** — no extra code for cycle detection |

## ⚠️ Common Mistakes

- ❌ **Not counting initial seeds** → count only tracks BFS-unlocked nodes → misses nodes that were already in-degree 0
- ❌ **`count == V` → no cycle** logic flipped → returning wrong boolean
- ❌ **Not handling disconnected graphs** → only seeding one node misses isolated components
- ❌ **Comparing `ans.size()` to `V`** in topo sort variant → same logic, just different variable name

## 🔁 Why Cycle Nodes Are Permanently Stuck

```
Cycle: A → B → C → A

inDeg[A] = 1 (from C)
inDeg[B] = 1 (from A)
inDeg[C] = 1 (from B)

For A to reach inDeg=0: C must be processed first
For C to reach inDeg=0: B must be processed first
For B to reach inDeg=0: A must be processed first

Circular dependency → none of them ever reach 0 → deadlock ✅
```

## 🆚 Kahn's vs DFS for Cycle Detection

| Feature | Kahn's BFS (this) | DFS + inRec[] |
|---------|------------------|---------------|
| Cycle detection | `count != V` | `inRec[v] == true` |
| Extra structures | In-degree array + queue | `vis[]` + `inRec[]` |
| Also gives | Topo order (if no cycle) | Nothing extra |
| Code complexity | Slightly more setup | Slightly more logic |
| Stack overflow risk | ❌ None (iterative) | ✅ Deep graphs (recursive) |
| Preferred when | Need topo order too | Simple yes/no cycle check |

---

## 🔁 Three Cycle Detection Approaches — Summary

```
1. DFS + inRec[] (directed graph):
   Detects back edges on current path
   → Cycle if inRec[v] == true during DFS

2. Kahn's BFS (directed graph, this):
   Nodes in cycle never reach in-degree 0
   → Cycle if count != V after BFS

3. DFS + visited color (undirected graph):
   Detects if we reach an already-visited node
   that isn't the parent
   → NOT applicable for directed graphs
```
