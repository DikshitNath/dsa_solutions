"# 🏆 Find Players With Zero or One Losses

> **Platform:** LeetCode 2225 | **Topic:** Hashing | **Technique:** Loss Frequency Map + Smart Insertion

**Question Link:** https://leetcode.com/problems/find-players-with-zero-or-one-losses/

---

## 📌 Problem Summary

Given a list of matches `[winner, loser]`, return a 2D array where:
- `ans[0]` = players who **never lost** (sorted)
- `ans[1]` = players who **lost exactly once** (sorted)

```
matches = [[1,3],[2,3],[3,6],[5,6],[5,7],[4,5],[4,8],[4,9],[10,4],[10,9]]
ans[0] = [1, 2, 10]     (never lost)
ans[1] = [4, 5, 7, 8]   (lost exactly once)
```

---

## 💡 Core Intuition

Use a single `unordered_map<int,int> lostMap` to track **loss counts** per player. Then in a second pass:
- If a winner is **not in the map** → they never lost → add to `not_lost`, mark as `2` (sentinel)
- If a loser's count is exactly `1` → lost once → add to `lost_once`

> 🗂️ **One map does double duty** — tracks loss frequency AND marks already-processed winners.

---

## 🤔 Why `lostMap[winner] = 2` as Sentinel?

After the first pass, `lostMap` only contains losers. Winners who never lost are **absent** from the map. In the second pass:

```
if (lostMap.find(winner) == lostMap.end())  → never lost → add to not_lost
```

But once added, if the same winner appears in multiple matches, we'd add them again. Setting `lostMap[winner] = 2` prevents re-insertion on the next iteration:

```
Match 1: winner=1 → not in map → push to not_lost, set lostMap[1]=2
Match 2: winner=1 → in map (value=2) → skip ✅ (2 is the sentinel)
```

Why `2` specifically? Any value that isn't `0` or `1` works — since we only push losers with count `== 1`. Value `2` clearly signals "already processed winner, not a real loss count."

---

## 🤔 Why Two Passes?

**Pass 1** — only processes losers:
```cpp
for matches: lostMap[loser]++
```
This gives us the complete loss count for every loser before we start categorizing.

**Why not one pass?** If we categorize winners in the same loop as counting losses, a winner might appear before all their losses are counted — leading to premature categorization.

```
Example: matches = [[1,2],[3,1]]
One pass: process [1,2] → winner=1, not in map → push 1 to not_lost
          process [3,1] → loser=1, lostMap[1]++ → 1 now has 1 loss
          But 1 was already pushed to not_lost ❌
```

Two passes guarantees all losses are tallied before categorization.

---

## 🪜 Algorithm Steps

**Pass 1 — Count losses:**
1. For each match `[w, l]`: `lostMap[l]++`

**Pass 2 — Categorize:**
2. For each match `[w, l]`:
   - If `w` not in `lostMap` → push to `not_lost`, set `lostMap[w] = 2`
   - If `lostMap[l] == 1` → push to `lost_once`

3. Sort both vectors, return `{not_lost, lost_once}`

## 🧩 Dry Run

```
matches = [[1,3],[2,3],[3,6],[5,6],[5,7]]

Pass 1 — count losses:
  [1,3]: lostMap[3]=1
  [2,3]: lostMap[3]=2
  [3,6]: lostMap[6]=1
  [5,6]: lostMap[6]=2
  [5,7]: lostMap[7]=1

lostMap = {3:2, 6:2, 7:1}

Pass 2 — categorize:
  [1,3]: winner=1 → not in map → not_lost=[1], lostMap[1]=2
         loser=3  → lostMap[3]=2 ≠ 1 → skip
  [2,3]: winner=2 → not in map → not_lost=[1,2], lostMap[2]=2
         loser=3  → lostMap[3]=2 ≠ 1 → skip
  [3,6]: winner=3 → in map (value=2) → skip
         loser=6  → lostMap[6]=2 ≠ 1 → skip
  [5,6]: winner=5 → not in map → not_lost=[1,2,5], lostMap[5]=2
         loser=6  → lostMap[6]=2 ≠ 1 → skip
  [5,7]: winner=5 → in map (value=2) → skip (sentinel works ✅)
         loser=7  → lostMap[7]=1 == 1 → lost_once=[7]

Sort: not_lost=[1,2,5], lost_once=[7]

Output: [[1,2,5],[7]] ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<vector<int>> findWinners(vector<vector<int>>& matches) {
        unordered_map<int, int> lostMap;

        // Pass 1: count losses for every loser
        for (int i = 0; i < matches.size(); i++)
            lostMap[matches[i][1]]++;

        vector<int> not_lost, lost_once;

        // Pass 2: categorize winners and losers
        for (int i = 0; i < matches.size(); i++) {
            int winner = matches[i][0];
            int loser  = matches[i][1];

            if (lostMap.find(winner) == lostMap.end()) {
                not_lost.push_back(winner);
                lostMap[winner] = 2;          // sentinel: already processed
            }

            if (lostMap[loser] == 1)
                lost_once.push_back(loser);
        }

        sort(not_lost.begin(), not_lost.end());
        sort(lost_once.begin(), lost_once.end());

        return {not_lost, lost_once};
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Two-pass design** — fully count losses before categorizing |
| 2 | **Sentinel `lostMap[winner] = 2`** — prevents duplicate pushes for repeated winners |
| 3 | **`lostMap.find(winner) == lostMap.end()`** — cleanly checks "never appeared as loser" |
| 4 | **`lostMap[loser] == 1`** — exact loss count check, not `<= 1` |
| 5 | Players who only appear as winners are **absent from lostMap** after pass 1 |

---

## ⚠️ Common Mistakes

- ❌ **Single pass** → winners categorized before all losses counted → wrong output
- ❌ **No sentinel for winners** → same winner pushed multiple times → duplicates in output
- ❌ **`lostMap[loser] <= 1`** → losers with 0 losses don't exist (only losers are in map after pass 1) — use `== 1`
- ❌ **Not sorting** → problem requires sorted output

---

## 🔁 Sentinel Value — Why Any Value ≥ 2 Works

```
Real loss counts: 1, 2, 3, ... (natural numbers)
Condition checks:
  not_lost: lostMap.find(winner) == end()  → only true if ABSENT
  lost_once: lostMap[loser] == 1           → only true if count is exactly 1

Sentinel = 2:
  After marking lostMap[winner] = 2:
    find(winner) != end() → winner skipped ✅
    lostMap[winner] == 1? No (it's 2) → not pushed to lost_once ✅

Any value ≥ 2 works as sentinel. 2 is the conventional choice.
```

## 🆚 Alternative — Cleaner with `unordered_set`

```cpp
// Slightly cleaner approach
unordered_map<int,int> losses;
unordered_set<int> allPlayers;

for (auto& m : matches) {
    allPlayers.insert(m[0]);
    allPlayers.insert(m[1]);
    losses[m[1]]++;
}

vector<int> not_lost, lost_once;
for (int p : allPlayers) {
    if (losses.count(p) == 0)    not_lost.push_back(p);
    else if (losses[p] == 1)     lost_once.push_back(p);
}

sort(not_lost.begin(), not_lost.end());
sort(lost_once.begin(), lost_once.end());
```

| Feature | Your approach | Set approach |
|---------|--------------|--------------|
| Extra DS | Sentinel value in map | Separate `allPlayers` set |
| Clarity | Clever but less obvious | More explicit |
| Space | O(N) | O(N) |
| Time | O(N log N) | O(N log N) |
