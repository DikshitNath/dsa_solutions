# 🔢 Unique Number of Occurrences

> **Platform:** LeetCode 1207 | **Topic:** Arrays / Hashing | **Technique:** Frequency Array + Sort + Duplicate Check

**Question Link:** https://leetcode.com/problems/unique-number-of-occurrences/

---

## 📌 Problem Summary

Given an array `arr`, return `true` if the number of occurrences of each value is **unique** — no two distinct values share the same frequency.

```
arr = [1,2,2,1,1,3]  → freq: {1:3, 2:2, 3:1} → all unique → true
arr = [1,2]           → freq: {1:1, 2:1} → duplicate freq  → false
```

---

## 💡 Core Intuition

Count frequencies, then **sort the frequency array** and check for adjacent duplicates. If any two adjacent non-zero frequencies are equal, two values share the same count → return `false`.

> 📊 **Analogy:** Count how many times each person showed up, sort those counts, then check if any two counts are identical.

---

## 🤔 Why Offset `x + 1000`?

Array values range from `-1000` to `1000`. Direct array indexing requires non-negative indices. Shifting by `+1000` maps:

```
-1000 → index 0
    0 → index 1000
 1000 → index 2000

Array size: 2001 covers all values ✅
```

This avoids using `unordered_map` — O(1) access with a fixed-size array.

---

## 🤔 Why Sort + Adjacent Check Instead of a Set?

Two approaches work:

```cpp
// Approach 1: Sort freq array, check adjacent (your code)
sort(freq.begin(), freq.end());
for (int i = 1; i < 2001; i++)
    if (freq[i] != 0 && freq[i] == freq[i-1]) return false;

// Approach 2: Insert into unordered_set, check duplicates
unordered_set<int> seen;
for (int f : freq)
    if (f != 0 && !seen.insert(f).second) return false;
```

| Feature | Sort + Adjacent (your code) | Set approach |
|---------|-----------------------------|--------------|
| Time | O(N + 2001 log 2001) = O(N) | O(N) |
| Space | O(1) extra | O(distinct values) |
| Elegance | Clever, no extra DS | More intuitive |

Both are valid. Sorting a fixed-size array is effectively O(1) since 2001 is constant.

---

## 🪜 Algorithm Steps

1. 🏁 Initialize `freq[2001] = {0}`
2. 🔁 For each `x` in `arr`: `freq[x + 1000]++`
3. 📊 Sort `freq` array
4. 🔁 For `i = 1` to `2000`:
   - If `freq[i] != 0` AND `freq[i] == freq[i-1]` → return `false`
5. 📤 Return `true`

## 🧩 Dry Run — Unique Frequencies

```
arr = [1, 2, 2, 1, 1, 3]

Step 1 — Count:
  freq[1001] = 3  (value 1, offset +1000)
  freq[1002] = 2  (value 2)
  freq[1003] = 1  (value 3)
  all others = 0

Step 2 — Sort freq:
  [0, 0, 0, ..., 1, 2, 3]

Step 3 — Check adjacent non-zeros:
  1 ≠ 0 → ok
  2 ≠ 1 → ok
  3 ≠ 2 → ok

return true ✅
```

---

## 🧩 Dry Run — Duplicate Frequencies

```
arr = [1, 2]

freq[1001] = 1  (value 1)
freq[1002] = 1  (value 2)

Sort: [0, 0, ..., 1, 1]

Adjacent check:
  freq[i]=1, freq[i-1]=1 → freq[i] != 0 AND equal → return false ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    bool uniqueOccurrences(vector<int>& arr) {
        vector<int> freq(2001, 0);

        for (int x : arr)
            freq[x + 1000]++;         // offset to handle negatives

        sort(begin(freq), end(freq));

        for (int i = 1; i < 2001; i++)
            if (freq[i] != 0 && freq[i] == freq[i-1])
                return false;         // duplicate frequency found

        return true;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N) | Counting O(N) + sort O(2001 log 2001) = O(N) |
| 🧠 **Space** | O(1) | Fixed-size array of 2001 — independent of input |

> 📝 Sorting 2001 elements is effectively constant time — the bottleneck is the O(N) counting pass.

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **`x + 1000` offset** — maps `[-1000, 1000]` to valid indices `[0, 2000]` |
| 2 | **Sort then adjacent check** — duplicates are always neighbours after sorting |
| 3 | **`freq[i] != 0` guard** — skips the many zeros; zero is not a real frequency |
| 4 | **Fixed-size array beats `unordered_map`** — O(1) space, faster in practice |
| 5 | **Loop starts at `i=1`** — comparing `freq[i]` with `freq[i-1]` requires `i >= 1` |

---

## ⚠️ Common Mistakes

- ❌ **`freq[x]` without offset** → negative indices → undefined behavior
- ❌ **`freq[i] == freq[i-1]` without `!= 0` check** → zeros match → false negative
- ❌ **Loop starting at `i=0`** → `freq[-1]` access → crash
- ❌ **Not sorting** → non-adjacent duplicates missed

---

## 🔁 The `!= 0` Guard — Why Critical

```
After sorting: [0, 0, 0, ..., 0, 1, 2, 3]
                ^^^^^^^^^^^^^^^^^^^
                many zeros from unused indices

Without guard:
  i=1: freq[1]=0, freq[0]=0 → 0==0 → return false ❌ WRONG

With guard:
  i=1: freq[1]=0 → condition fails (freq[i] != 0 is false) → skip
  ...continues until real frequencies are compared ✅
```

## 🔁 Two Equivalent Clean Solutions

```cpp
// Solution 1 — Your approach (sort + adjacent check)
sort(freq.begin(), freq.end());
for (int i = 1; i < 2001; i++)
    if (freq[i] != 0 && freq[i] == freq[i-1]) return false;
return true;

// Solution 2 — unordered_map + unordered_set
unordered_map<int,int> cnt;
for (int x : arr) cnt[x]++;
unordered_set<int> seen;
for (auto& [val, freq] : cnt)
    if (!seen.insert(freq).second) return false;
return true;
```
