
# 🏆 Find Largest Value in Each Tree Row

> **Platform:** LeetCode 515 | **Topic:** Trees / BFS | **Technique:** Level Order with Max Tracking

**Question Link:** https://leetcode.com/problems/find-largest-value-in-each-tree-row/

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **largest value in each row** (level) of the tree.

```
        1
       / \
      3   2
     / \   \
    5   3   9

Level 1: max(1)       = 1
Level 2: max(3,2)     = 3
Level 3: max(5,3,9)   = 9

Output: [1, 3, 9]
```

---

## 💡 Core Intuition

Standard BFS level-order template — the only change inside the inner loop is **tracking the running maximum** (`mx`) instead of collecting all values. After draining each level, push `mx` to `ans`.

> 🏅 **Analogy:** Judge each floor of a building independently — find the tallest person on each floor and record only that height.

---

## 🤔 Why `INT_MIN` as Initial Value?

`mx` must start at the **smallest possible value** so any real node value (even negative) will replace it on the first comparison.

```
If node values can be negative (e.g., -5, -3, -1):
  mx = 0     → wrong, 0 > all values → never updated ❌
  mx = INT_MIN → -5 > INT_MIN → updated correctly ✅
```

`INT_MIN` = `-2,147,483,648` — guaranteed smaller than any `int` node value.

---

## 🪜 Algorithm Steps

1. 🏁 Push `root` into queue
2. 🔁 While queue not empty:
   - Snapshot `n = q.size()`
   - Initialize `mx = INT_MIN`
   - 🔁 Process exactly `n` nodes:
     - Pop node
     - Update `mx = max(mx, node->val)`
     - Push left/right children if exist
   - Push `mx` into `ans`
3. 📤 Return `ans`

```
Tree:       1
           / \
          3   2
         / \   \
        5   3   9

Initial: queue=[1]

--- Level 1 ---
n=1, mx=INT_MIN
  pop 1  → mx=max(INT_MIN,1)=1, push 3, push 2
ans=[1], queue=[3,2]

--- Level 2 ---
n=2, mx=INT_MIN
  pop 3  → mx=max(INT_MIN,3)=3, push 5, push 3
  pop 2  → mx=max(3,2)=3,       push 9
ans=[1,3], queue=[5,3,9]

--- Level 3 ---
n=3, mx=INT_MIN
  pop 5  → mx=max(INT_MIN,5)=5
  pop 3  → mx=max(5,3)=5
  pop 9  → mx=max(5,9)=9
ans=[1,3,9]

Output: [1, 3, 9] ✅
```

## 🧩 Dry Run — Negative Values

```
Tree:    -1
         / \
       -3  -2

Level 1: mx=INT_MIN → max(INT_MIN,-1) = -1  → ans=[-1]
Level 2: mx=INT_MIN → max(INT_MIN,-3) = -3
                    → max(-3,-2)      = -2  → ans=[-1,-2]

Output: [-1, -2] ✅  (INT_MIN init handles negatives correctly)
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<int> largestValues(TreeNode* root) {
        vector<int> ans;
        if (!root) return ans;

        queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            int n  = q.size();
            int mx = INT_MIN;        // handles negative values correctly

            while (n--) {
                TreeNode* node = q.front();
                q.pop();

                mx = max(mx, node->val);   // track running max

                if (node->left)  q.push(node->left);
                if (node->right) q.push(node->right);
            }

            ans.push_back(mx);       // largest value of this level
        }
        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N) | Every node pushed and popped exactly once |
| 🧠 **Space** | O(W) | Queue holds at most one full level; W = max width |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **`INT_MIN` init** — handles all-negative trees; never use `0` as default max |
| 2 | **`n` used directly** in `while(n--)` — no separate temp needed (unlike LC 637 where `n` is needed post-loop for division) |
| 3 | One variable `mx` replaces entire level vector — O(1) per level instead of O(W) |
| 4 | This is the **simplest mutation** of the BFS template — one line changes |

---

## ⚠️ Common Mistakes

- ❌ **`mx = 0`** → wrong for all-negative trees
- ❌ **`mx = INT_MAX`** → no node value will ever be larger → always stays INT_MAX
- ❌ **`while(n--)` with division after** → here division isn't needed, `n--` is fine unlike LC 637
- ❌ **Missing null check on root** → empty tree should return `[]`, not crash
