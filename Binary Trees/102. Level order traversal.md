# 🌊 Binary Tree Level Order Traversal

> **Platform:** LeetCode 102 | **Topic:** Trees / BFS | **Technique:** Level-by-Level Queue Processing

**Question Link:** https://leetcode.com/problems/binary-tree-level-order-traversal/

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **node values level by level** from left to right, as a 2D vector where each inner vector contains one level.

```
        3
       / \
      9  20
         / \
        15   7

Output: [[3], [9,20], [15,7]]
```

---

## 💡 Core Intuition

Use a **queue** (FIFO) to process nodes level by level. The key trick: **snapshot `q.size()` before processing** each level — this tells you exactly how many nodes belong to the current level. Process exactly that many, collect their values, then move to the next level.

> 🏫 **Analogy:** Students lined up by grade. Count how many are in Grade 1, process them all, then move to Grade 2. The queue naturally fills with the next grade's students as you process the current one.

---

## 🤔 Why Snapshot `q.size()`?

When processing level `L`, you push level `L+1` nodes into the queue. Without snapshotting, you'd mix levels together.

```
Before level 2:  queue = [9, 20]    → n = 2
Process 9  → push nothing (no children)
Process 20 → push 15, 7
After inner loop: queue = [15, 7]   → next level ✅

Without snapshot:
  n keeps growing mid-loop → level 2 and 3 mix together ❌
```

---

## 🪜 Algorithm Steps

1. 🏁 Push `root` into queue
2. 🔁 While queue not empty:
   - Snapshot `n = q.size()` (number of nodes at this level)
   - Create empty `level` vector
   - 🔁 Process exactly `n` nodes:
     - Pop front node
     - Push left and right children (if exist)
     - Add node's value to `level`
   - Push `level` into `ans`
3. 📤 Return `ans`

## 🧩 Dry Run — Skewed Tree

```
Tree:   1
         \
          2
           \
            3

Initial: queue=[1]

Level 1: n=1 → pop 1, push 2 → level=[1]
Level 2: n=1 → pop 2, push 3 → level=[2]
Level 3: n=1 → pop 3, no children → level=[3]

Output: [[1],[2],[3]] ✅
```

### Pseudocode

```
levelOrder(root):
    if not root: return []
    ans = [], queue = [root]

    while queue not empty:
        n = queue.size()
        level = []

        repeat n times:
            node = queue.front(); queue.pop()
            if node.left:  queue.push(node.left)
            if node.right: queue.push(node.right)
            level.push(node.val)

        ans.push(level)

    return ans
```

---

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<vector<int>> levelOrder(TreeNode* root) {
        vector<vector<int>> ans;
        if (!root) return ans;

        queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            vector<int> level;
            int n = q.size();        // snapshot: nodes at current level

            while (n--) {
                TreeNode* node = q.front();
                q.pop();

                if (node->left)  q.push(node->left);
                if (node->right) q.push(node->right);

                level.push_back(node->val);
            }
            ans.push_back(level);    // one complete level done
        }
        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N) | Every node pushed and popped exactly once |
| 🧠 **Space** | O(W) | Queue holds at most one full level; W = max width |

> 📝 Worst case space: **O(N/2)** for the last level of a perfect binary tree
> Best case space: **O(1)** for a skewed tree (only 1 node per level)

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Snapshot `n = q.size()`** before inner loop — separates levels cleanly |
| 2 | **Children pushed during processing** naturally fill the queue for next level |
| 3 | `node` declared inside inner loop here — no scope issue (used immediately) |
| 4 | Empty tree check at start prevents null dereference |
| 5 | This BFS pattern is the **foundation** for all level-based tree problems |

---

## ⚠️ Common Mistakes

- ❌ **Not snapshotting `q.size()`** → loop condition `n--` uses growing size → levels mix
- ❌ **Using `q.size()` directly in `while(q.size()--)` with unsigned** → underflow bug
- ❌ **Pushing children after `level.push_back`** → order doesn't matter here but matters in other variants
- ❌ **Skipping null check on root** → crash on empty tree input

## 🔁 The BFS Level Template

This problem is the **template** for all level-order problems. Variations just change what you do inside the inner loop:

```cpp
while (!q.empty()) {
    int n = q.size();          // ← ALWAYS snapshot first

    while (n--) {
        auto node = q.front(); q.pop();

        // ↓ THIS PART CHANGES per problem
        // LC 102: collect all values → 2D array
        // LC 199: collect only last value → right side view
        // LC 637: sum values, divide → level averages
        // LC 103: zigzag → reverse alternate levels
        // LC 513: track first/last → find bottom-left value

        if (node->left)  q.push(node->left);
        if (node->right) q.push(node->right);
    }
}
```
