# 🔥 Binary Tree Maximum Path Sum

> **Platform:** LeetCode | **Topic:** Binary Tree | **Technique:** Recursive DFS (Postorder)

**Question Link:** [https://leetcode.com/problems/binary-tree-maximum-path-sum/](https://leetcode.com/problems/binary-tree-maximum-path-sum/)

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **maximum path sum** of any non-empty path. A path is any sequence of nodes where each pair of adjacent nodes has an edge — the path does **not** need to pass through the root and can start/end at any node.

    Nodes can have NEGATIVE values — so sometimes skipping a subtree is better.

---

## 💡 Core Intuition

At every node, the best path **through it** = `left contribution + root->val + right contribution`. Track this globally. But what we **return to the parent** is only one direction — `root->val + max(left, right)` — since a path can't split at two nodes.

> 🔀 **Analogy:** At each node you're a junction. You can collect from both arms to form a local path (tracked in `m`). But you can only extend ONE arm upward to your parent — a path can't fork.

---

## 🤔 Two Different Computations Per Node

| Purpose | Formula | Used for |
|---------|---------|----------|
| **Global max** | `l + r + root->val` | Updating `m` — best path through this node |
| **Return to parent** | `root->val + max(l, r)` | Extending path upward — only one branch |

These are two separate things happening at the same node in the same DFS call.

---

## 🤔 Why `max(0, solve(...))`?

A negative subtree contribution would **reduce** the path sum. By clamping to `0`, we effectively **ignore** that subtree — as if the path starts fresh at the current node.

    l = max(0, solve(root->left,  m))   // take left only if it helps
    r = max(0, solve(root->right, m))   // take right only if it helps

---

## 🪜 Algorithm Steps

1. 🏁 Initialize `maxSum = INT_MIN` (handles all-negative trees)
2. 🔁 DFS postorder on every node:
   - Get `l = max(0, solve(left))` and `r = max(0, solve(right))`
   - Update `m = max(m, l + r + root->val)` ← best path through this node
   - Return `root->val + max(l, r)` ← best single-arm extension upward
3. 📤 Return `maxSum`

### Why INT_MIN and not 0?

    If all nodes are negative (e.g. [-3, -1, -2]):
    - Answer must be -1 (least negative single node)
    - Initializing maxSum = 0 would wrongly return 0
    - INT_MIN ensures even a single negative node updates the max ✅

### Pseudocode

    solve(root, m):
        if root is null → return 0

        l = max(0, solve(root.left,  m))    // ignore negative arms
        r = max(0, solve(root.right, m))    // ignore negative arms

        m = max(m, l + r + root.val)        // best path THROUGH this node

        return root.val + max(l, r)         // best single arm UPWARD

    maxPathSum(root):
        m = INT_MIN
        solve(root, m)
        return m

### Full C++ Solution

```cpp
class Solution {
public:
    int solve(TreeNode* root, int& m) {
        if (!root) return 0;

        int l = max(0, solve(root->left,  m));  // ignore if negative
        int r = max(0, solve(root->right, m));  // ignore if negative

        m = max(m, l + r + root->val);          // update global max path

        return root->val + max(l, r);           // return best single arm
    }

    int maxPathSum(TreeNode* root) {
        int maxSum = INT_MIN;                   // handles all-negative trees
        solve(root, maxSum);
        return maxSum;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Two roles per node** — compute local max path (for `m`) AND return best arm (for parent) |
| 2 | `max(0, solve(...))` elegantly **drops negative subtrees** |
| 3 | Pass `m` by **reference** — acts as a global max across all nodes |
| 4 | `INT_MIN` initialization correctly handles **all-negative** trees |

---

## ⚠️ Common Mistakes

- ❌ **Returning `l + r + root->val`** to parent → path forks at two nodes, which is invalid
- ❌ **Initializing `m = 0`** → wrong answer for all-negative trees
- ❌ **Not clamping to 0** → negative subtrees drag down the path sum incorrectly
- ❌ **Passing `m` by value** → global max never updates across calls

---

## 🔁 Pattern Similarities

This problem uses the **exact same DFS skeleton** as these problems:

    Max Depth         → return 1 + max(l, r)
    Diameter          → m = max(m, l+r);        return 1+max(l,r)
    Max Path Sum      → m = max(m, l+r+val);    return val+max(l,r)
    Balanced Tree     → m = abs(l-r) <= 1;      return 1+max(l,r)

    Master this postorder DFS pattern → solves a whole family of tree problems.
