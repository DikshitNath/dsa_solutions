# 🌱 Minimum Depth of Binary Tree

> **Platform:** LeetCode 111 | **Topic:** Trees / BFS | **Technique:** Level Order — Early Exit on First Leaf

**Question Link:** https://leetcode.com/problems/minimum-depth-of-binary-tree/

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **minimum depth** — the number of nodes along the **shortest path from root to the nearest leaf node**.

> A **leaf** is a node with **no left and no right child**.

```
        3
       / \
      9  20
         / \
        15   7

Leaf 9  → depth 2
Leaf 15 → depth 3
Leaf 7  → depth 3

Output: 2  (shortest path: 3 → 9)
```

---

## 💡 Core Intuition

BFS is **perfect** for minimum depth — it explores level by level, so the **first leaf it encounters is guaranteed to be at the minimum depth**. The moment we hit a leaf, return `depth` immediately — no need to explore further.

> 🔍 **Why BFS and not DFS?** DFS might go deep down one branch before finding a shorter path on another. BFS finds the shallowest leaf first by design.

> 🕯️ **Analogy:** Searching floors of a building for the nearest exit. BFS checks every door on floor 1 before going to floor 2 — the first exit found is guaranteed to be the closest.

---

## 🤔 Why NOT Use DFS Here?

```
Tree:       1
           /
          2
         /
        3      ← only leaf, depth 3

DFS (goes left first):
  Visits 1 → 2 → 3 → leaf found at depth 3
  Then backtracks... but there's nothing on the right
  Returns 3 ✅ (correct here, but...)

Tree:       1
           / \
          2   3    ← leaf at depth 2
         /
        4          ← leaf at depth 3

DFS (goes left first):
  Visits 1 → 2 → 4 → depth 3
  Then right: 1 → 3 → depth 2
  Returns min(3, 2) = 2 ✅ but explores MORE than needed

BFS:
  Level 1: [1]    → no leaf
  Level 2: [2, 3] → 3 is leaf! → return 2 immediately ✅
  Never visits node 4 at all!
```

BFS **stops as soon as it finds the first leaf** — DFS always explores the entire tree.

---

## 🤔 The Classic Trap — Single Child Nodes

A common mistake is treating a node with only one child as a leaf.

```
Tree:       1
           /
          2         ← NOT a leaf (has no right, but has left child)
         /
        3           ← actual leaf

Minimum depth = 3, NOT 2

Leaf condition: !node->left && !node->right  ← BOTH must be null ✅
```

If you check only `!node->left` or `!node->right` separately — you'd incorrectly return depth 2 for node `2`.

---

## 🪜 Algorithm Steps

1. 🏁 Push `root` into queue, `depth = 0`
2. 🔁 While queue not empty:
   - Increment `depth++` (entering a new level)
   - Snapshot `n = q.size()`
   - 🔁 Process exactly `n` nodes:
     - Pop node
     - **If leaf** (`!left && !right`) → return `depth` immediately ✅
     - Push left/right children if exist
3. 📤 Return `depth` (fallback — never reached if tree is valid)

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    int minDepth(TreeNode* root) {
        if (!root) return 0;

        int depth = 0;
        queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            int n = q.size();
            depth++;                        // increment before processing level

            while (n--) {
                TreeNode* node = q.front();
                q.pop();

                if (!node->left && !node->right)   // leaf check
                    return depth;                  // first leaf = min depth ✅

                if (node->left)  q.push(node->left);
                if (node->right) q.push(node->right);
            }
        }
        return depth;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N) worst case | Skewed tree — leaf is at bottom; visits all nodes |
| ⏱️ **Time** | O(log N) best case | Balanced tree — leaf found at first level with leaves |
| 🧠 **Space** | O(W) | Queue holds at most one full level; W = max width |

> 📝 BFS is significantly faster than DFS in **balanced trees** — it exits at the first leaf level without exploring deeper branches.

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **BFS > DFS** for minimum depth — BFS finds shallowest leaf first by design |
| 2 | **Leaf = `!left && !right`** — both children must be null, not just one |
| 3 | **`depth++` before inner loop** — depth represents the level currently being processed |
| 4 | **Early return inside inner loop** — exits the moment first leaf is found |
| 5 | **`return 0` for null root** — base case before queue initialization |

## ⚠️ Common Mistakes

- ❌ **Using DFS** → explores unnecessary branches; BFS is optimal here
- ❌ **Leaf check: `!node->left || !node->right`** → single-child nodes falsely treated as leaves
- ❌ **`depth++` after inner loop** → depth is one step behind; off-by-one error
- ❌ **No null root check** → pushing null to queue → crash on empty tree

---

## 🔁 `depth++` Placement — Why Before Inner Loop?

```cpp
// ✅ Correct — depth++ before processing
depth++;           // "I'm now on level depth"
while (n--) {
    ...
    if (leaf) return depth;   // depth is correct ✅
}

// ❌ Wrong — depth++ after processing
while (n--) {
    ...
    if (leaf) return depth;   // depth not yet incremented ❌ off by one
}
depth++;
```

The increment must happen **before** processing so `depth` accurately represents the current level when we find a leaf.

## 🆚 BFS vs DFS for Min Depth

| Feature | BFS (this) | DFS |
|---------|-----------|-----|
| Finds min depth | ✅ Immediately on first leaf | ✅ After full traversal |
| Nodes visited | O(nodes up to min depth level) | O(N) always |
| Early exit | ✅ Yes | ❌ No |
| Code complexity | Slightly more (queue) | Simpler (recursion) |
| Best for | Min depth, shortest path | Max depth, path collection |
