# 🌳 Binary Tree Postorder Traversal

> **Platform:** LeetCode | **Topic:** Binary Tree | **Technique:** Recursive DFS

**Question Link:** [https://leetcode.com/problems/binary-tree-postorder-traversal/](https://leetcode.com/problems/binary-tree-postorder-traversal/)

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **postorder traversal** of its node values as an array.

    Postorder = Left → Right → Root

---

## 💡 Core Intuition

Recursively visit the **left subtree**, then the **right subtree**, and only then **process the current node**. The root is always the **last** element in the output.

> 🏗️ **Analogy:** Demolishing a building — you clear out the left wing first, then the right wing, and only then tear down the main floor you're standing on.

---

## 🤔 Traversal Orders Recap

| Order | Sequence | When Root is Processed |
|-------|----------|------------------------|
| **Preorder** | Root → Left → Right | First |
| **Inorder** | Left → Root → Right | Middle |
| **Postorder** | Left → Right → Root | ✅ Last |

Postorder is useful for **bottom-up problems** — children are always processed before their parent (e.g. tree deletion, height calculation, DP on trees).

---

## 🪜 Algorithm Steps

1. 🚫 Base case: if `root == null` → return
2. ↙️ Recurse into `root->left`
3. ↘️ Recurse into `root->right`
4. ✅ Push `root->val` into `ans` **(process last)**

    Output: [1, 3, 2, 5, 7, 6, 4] ✅  (root always last)

### All Three Traversals on Same Tree

         4
        / \
       2   6
      / \ / \
     1  3 5  7

    Preorder  : [4, 2, 1, 3, 6, 5, 7]   ← root first
    Inorder   : [1, 2, 3, 4, 5, 6, 7]   ← sorted (BST)
    Postorder : [1, 3, 2, 5, 7, 6, 4]   ← root last ✅

### Pseudocode

    postorder(root, ans):
        if root is null → return

        postorder(root.left, ans)     // ↙️ left first
        postorder(root.right, ans)    // ↘️ right second
        ans.push(root.val)            // ✅ process root LAST

### Full C++ Solution

```cpp
class Solution {
public:
    vector<int> postorderTraversal(TreeNode* root) {
        vector<int> ans;
        postorder(root, ans);
        return ans;
    }

    void postorder(TreeNode* root, vector<int>& ans) {
        if (!root) return;                  // base case

        postorder(root->left, ans);         // left subtree
        postorder(root->right, ans);        // right subtree
        ans.push_back(root->val);           // process current node LAST
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | Root is **always the last element** in postorder output |
| 2 | Children are fully processed **before** their parent — ideal for bottom-up problems |
| 3 | Pass `ans` by **reference** to avoid copying on every recursive call |
| 4 | Only difference from preorder: `push_back` moved **after** both recursive calls |

---

## ⚠️ Common Mistakes

- ❌ **Pushing root before recursive calls** → becomes Preorder, not Postorder
- ❌ **Pushing root between left and right** → becomes Inorder, not Postorder
- ❌ **Passing `ans` by value** → result is lost after each call returns
- ❌ **Missing base case** → null pointer dereference on leaf children

---

## 🔄 Iterative Version (Follow-up)

Postorder is the trickiest to do iteratively. A clean trick: reverse of a modified preorder.

    Preorder  produces: Root → Left  → Right
    Modified  produces: Root → Right → Left   (swap left/right push order)
    Reversed  produces: Left → Right → Root   = Postorder ✅

    iterativePostorder(root):
        if root is null → return
        stack = [root]

        while stack not empty:
            node = stack.pop()
            ans.push(node.val)

            if node.left  → stack.push(node.left)    // left pushed first
            if node.right → stack.push(node.right)   // right on top

        reverse(ans)    // flip to get postorder

---

## 🧠 Where Postorder is Used

    → Deleting a tree         (delete children before parent)
    → Calculating tree height (need child heights before computing parent's)
    → Evaluating expression trees (compute leaves before operators)
    → Bottom-up DP on trees   (children's results feed into parent)
