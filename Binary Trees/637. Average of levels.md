# 📊 Average of Levels in Binary Tree

> **Platform:** LeetCode 637 | **Topic:** Trees / BFS | **Technique:** Level Order with Sum Accumulation

**Question Link:** https://leetcode.com/problems/average-of-levels-in-binary-tree/

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **average value of nodes at each level** as a `vector<double>`, from top to bottom.

```
        3
       / \
      9  20
         / \
        15   7

Level 1: avg(3)       = 3.0
Level 2: avg(9,20)    = 14.5
Level 3: avg(15,7)    = 11.0

Output: [3.0, 14.5, 11.0]
```

---

## 💡 Core Intuition

Standard BFS level-order template with one change inside the inner loop — **accumulate a sum** instead of collecting values. After draining each level, divide `sum / n` to get the average and push to `ans`.

> ➗ **Analogy:** Take attendance per classroom floor, add up all scores on that floor, divide by student count — repeat floor by floor.

---

## 🤔 Why Two Variables `n` and `temp`?

```cpp
int n    = q.size();   // saved for division → sum / n
int temp = n;          // used for loop countdown (n-- would destroy n)
```

If you used `n--` in the while loop, `n` would reach `0` by the time you divide — giving **division by zero or wrong result**. `temp` is a sacrificial copy that gets decremented while `n` stays intact for the final division.

```
n=3, temp=3

temp-- loop: temp = 2, 1, 0 → loop ends
sum / n = sum / 3  ✅   (n still = 3)

If we used n--:
sum / n = sum / 0  💥 or sum / wrong_value ❌
```

---

## 🪜 Algorithm Steps

1. 🏁 Push `root` into queue
2. 🔁 While queue not empty:
   - Snapshot `n = q.size()`, set `temp = n`, `sum = 0`
   - 🔁 Process exactly `temp` nodes:
     - Pop front node
     - Add `node->val` to `sum`
     - Push left/right children if exist
   - Push `sum / n` into `ans`
3. 📤 Return `ans`

## 🧩 Dry Run

```
Tree:       3
           / \
          9  20
             / \
            15   7

Initial: queue=[3]

--- Level 1 ---
n=1, temp=1, sum=0
  pop 3  → sum=3, push 9, push 20
ans=[3.0/1] = [3.0], queue=[9,20]

--- Level 2 ---
n=2, temp=2, sum=0
  pop 9  → sum=9, no children
  pop 20 → sum=29, push 15, push 7
ans=[3.0, 29.0/2] = [3.0, 14.5], queue=[15,7]

--- Level 3 ---
n=2, temp=2, sum=0
  pop 15 → sum=15, no children
  pop 7  → sum=22, no children
ans=[3.0, 14.5, 22.0/2] = [3.0, 14.5, 11.0]

Output: [3.0, 14.5, 11.0] ✅
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    vector<double> averageOfLevels(TreeNode* root) {
        vector<double> ans;

        queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            double sum = 0;
            int n    = q.size();    // preserve for division
            int temp = n;           // use for loop countdown

            while (temp--) {
                TreeNode* node = q.front();
                q.pop();

                sum += node->val;

                if (node->left)  q.push(node->left);
                if (node->right) q.push(node->right);
            }
            ans.push_back(sum / n);   // average of this level
        }
        return ans;
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N) | Every node pushed and popped exactly once |
| 🧠 **Space** | O(W) | Queue holds at most one full level; W = max width |

> 📝 `double sum` is important — if declared as `int`, large trees with many nodes per level can **overflow** int range before division.

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **`n` and `temp` are separate** — `n` preserved for division, `temp` used for countdown |
| 2 | **`sum` declared as `double`** — prevents integer overflow on large inputs |
| 3 | No null check needed on root — queue never holds null pointers |
| 4 | This is the **level order template** with sum accumulation — minimal change from LC 102 |

---

## ⚠️ Common Mistakes

- ❌ **`while(n--)` and then `sum/n`** → `n` is 0 at that point → division by zero / wrong result
- ❌ **`int sum`** → integer overflow for trees with many large-valued nodes per level
- ❌ **`sum / n` as integer division** → truncates decimal; `sum` must be `double` or cast explicitly
- ❌ **Missing null check on root** → not needed here since we never push null, but always good habit

---

## 🔁 Integer Overflow Risk

```
Worst case: complete binary tree, last level has N/2 nodes
Each node value up to INT_MAX = 2,147,483,647

Sum = (N/2) * INT_MAX → FAR exceeds int range (2^31 - 1)

int sum   → overflow    ❌
double sum → handles it ✅  (double range ≈ 1.8 × 10^308)
```

## 🔁 BFS Level Template — What Changed vs LC 102

```cpp
// LC 102 — Level Order
while (n--) {
    auto node = q.front(); q.pop();
    level.push_back(node->val);      // collect all values
    ...
}
ans.push_back(level);

// LC 637 — Average of Levels
while (temp--) {
    auto node = q.front(); q.pop();
    sum += node->val;                // accumulate sum
    ...
}
ans.push_back(sum / n);             // divide by count
```

Only the **inner loop body** and **post-loop action** change. The queue scaffolding is identical.
