# 🌳 Binary Tree Inorder Traversal

> **Platform:** LeetCode | **Topic:** Binary Tree | **Technique:** Recursive DFS

**Question Link:** [https://leetcode.com/problems/binary-tree-inorder-traversal/](https://leetcode.com/problems/binary-tree-inorder-traversal/)

---

## 📌 Problem Summary

Given the `root` of a binary tree, return the **inorder traversal** of its node values as an array.

    Inorder = Left → Root → Right

---

## 💡 Core Intuition

Recursively visit the **left subtree first**, then **record the current node**, then visit the **right subtree**. This naturally produces values in **sorted order** for a Binary Search Tree (BST).

> 🗺️ **Analogy:** Reading a book shelf left-to-right. First exhaust everything on the left shelf, note the current book, then move to everything on the right shelf.

---

## 🤔 Why Left → Root → Right?

The three DFS traversal orders differ only in **when you process the root**:

| Order | Sequence | Use Case |
|-------|----------|----------|
| **Preorder** | Root → Left → Right | Tree copying, serialization |
| **Inorder** | Left → Root → Right | Sorted output from BST |
| **Postorder** | Left → Right → Root | Tree deletion, bottom-up DP |

Inorder on a **BST** always yields elements in **ascending sorted order**.

---

## 🪜 Algorithm Steps

1. 🚫 Base case: if `root == null` → return
2. ↙️ Recurse into `root->left`
3. ✅ Push `root->val` into `ans`
4. ↘️ Recurse into `root->right`

    inorder(4)

          inorder(null) → return
        push 2
        inorder(3)
          inorder(null) → return
          push 3
          inorder(null) → return
      push 4
      inorder(6)
        inorder(5) → push 5
        push 6
        inorder(7) → push 7

    Output: [1, 2, 3, 4, 5, 6, 7] ✅  (sorted — it's a BST)

### Pseudocode

    inorder(root, ans):
        if root is null → return

        inorder(root.left, ans)    // ↙️ go left first
        ans.push(root.val)         // ✅ record current
        inorder(root.right, ans)   // ↘️ go right last

### Full C++ Solution

```cpp
class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> ans;
        inorder(root, ans);
        return ans;
    }

    void inorder(TreeNode* root, vector<int>& ans) {
        if (!root) return;                  // base case

        inorder(root->left, ans);           // left subtree
        ans.push_back(root->val);           // process current node
        inorder(root->right, ans);          // right subtree
    }
};
```

## 📊 Complexity Analysis

| Metric | Complexity | Reason |
|--------|-----------|--------|
| ⏱️ **Time** | O(N) | Every node visited exactly once |
| 🧠 **Space** | O(H) | Recursion stack depth = height of tree; O(log N) balanced, O(N) skewed |

---

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | Inorder of a **BST** always produces a **sorted array** |
| 2 | Pass `ans` by **reference** — avoids copying the vector on every call |
| 3 | Base case `if (!root) return` handles both `null` children and empty tree |
| 4 | Can also be done **iteratively** using an explicit stack (avoids recursion stack overflow on skewed trees) |

---

## ⚠️ Common Mistakes

- ❌ **Passing `ans` by value** → each recursive call gets its own copy, result is lost
- ❌ **Processing root before left** → becomes Preorder, not Inorder
- ❌ **Missing base case** → causes null pointer dereference crash

---

## 🔄 Iterative Version (Follow-up)

The recursive call stack can be replaced with an **explicit stack**:

    iterativeInorder(root):
        stack = []
        curr = root

        while curr != null OR stack not empty:
            while curr != null:
                stack.push(curr)
                curr = curr.left       // go as far left as possible

            curr = stack.pop()
            ans.push(curr.val)         // process node
            curr = curr.right          // move to right subtree

    Space: O(H) — same as recursive, but avoids system call stack limits
