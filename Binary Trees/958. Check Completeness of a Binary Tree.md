# 🌲 Check Completeness of a Binary Tree

> **Platform:** LeetCode 958 | **Topic:** Trees / BFS | **Technique:** BFS Null-Sentinel Detection

**Question Link:** https://leetcode.com/problems/check-completeness-of-a-binary-tree/

---

## 📌 Problem Summary

A **complete binary tree** is one where every level is fully filled except possibly the last, which is filled **left to right** with no gaps. Given the root, return `true` if the tree is complete.

```
Complete ✅:         Not Complete ❌:
    1                    1
   / \                  / \
  2   3                2   3
 / \  /               /     \
4   5 6              4       5   ← gap at level 2 (no left child of 3)
```

---

## 💡 Core Intuition — Null Sentinel in BFS

In a **complete tree**, when BFS (level-order) encounters a `NULL` child, **all subsequent nodes must also be NULL**. If any non-null node appears after the first null → gap exists → not complete.

```
BFS queue (including NULLs):
  Push left and right children of every node (even NULL).
  Once a NULL is dequeued, set flag past=true.
  If a non-NULL is dequeued after past=true → return false.
```

> 🏁 **Flag trick:** `past` marks "we've seen the first null". Think of it as the boundary — everything after it must be null.

---

## 🪜 Algorithm Steps

1. Push `root` to queue.
2. While queue not empty:
   - Pop `node`.
   - If `node == NULL` → set `past = true`.
   - Else:
     - If `past == true` → non-null appeared after a null → return `false`
     - Push `node->left` and `node->right` (both, even if null)
3. Return `true`.

## 🧩 Dry Run — Complete Tree

```
Tree:
    1
   / \
  2   3
 / \  /
4   5 6

BFS order with NULLs:
  Push: [1]
  Pop 1 (non-null, past=F): push 2, 3 → [2,3]
  Pop 2 (non-null, past=F): push 4, 5 → [3,4,5]
  Pop 3 (non-null, past=F): push 6, NULL → [4,5,6,NULL]
  Pop 4 (non-null, past=F): push NULL, NULL → [5,6,NULL,NULL,NULL]
  Pop 5 (non-null, past=F): push NULL, NULL → [6,NULL,NULL,NULL,NULL]
  Pop 6 (non-null, past=F): push NULL, NULL → [NULL,NULL,NULL,NULL,NULL,NULL]
  Pop NULL: past=true
  Pop NULL: past=true (no non-null follows)
  ...queue empties

return true ✅
```

## 🧩 Dry Run — Not Complete Tree

```
Tree:
    1
   / \
  2   3
 /     \
4       5   ← 3 has no left child, but has right child!

BFS order:
  Pop 1: push 2, 3
  Pop 2: push 4, NULL
  Pop 3: push NULL, 5   ← NULL before 5!
  Pop 4: push NULL, NULL
  Pop NULL: past=true
  Pop NULL: past=true
  Pop NULL: past=true (3->left)
  Pop 5: non-null but past=true → return false ❌ ✅
```

---

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    bool isCompleteTree(TreeNode* root) {
        bool past = false;
        queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            TreeNode* node = q.front();
            q.pop();

            if (node == NULL) {
                past = true;            // first null seen
            } else {
                if (past) return false; // non-null after null → gap!
                q.push(node->left);     // push both children (even null)
                q.push(node->right);
            }
        }
        return true;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Push NULLs to queue** — only way to detect gaps between children |
| 2 | **`past` flag** — marks the first null; after this, only nulls allowed |
| 3 | **Non-null after `past=true`** → gap → not complete |
| 4 | **Both children pushed always** — even null children are pushed for gap detection |
| 5 | Works on any shape of tree, including single node (root only) |

---

## ⚠️ Common Mistakes

- ❌ **Not pushing NULL children** → gaps are invisible to the BFS → wrong answer
- ❌ **`past = false` inside `else`** → resetting flag on every non-null → never detects gaps
- ❌ **Checking `node->left == NULL || node->right == NULL` inside loop** → doesn't handle deeper gaps

---

## 🔁 Why Push NULLs to Queue?

```
Without pushing NULLs:
  Tree:         Tree (not complete):
      1              1
     / \            /
    2   3          2

  BFS (no NULLs): [1] → [2,3] → [] → true
  BFS (no NULLs): [1] → [2]   → [] → true (wrong! ❌)

With pushing NULLs:
  BFS: [1] → [2, NULL] → pops NULL → past=true → queue empty → true ✅ (single child case)
  BFS: [1] → [2] → pops 2 → pushes NULL,NULL
        → pops NULL → past=true → queue empty → true ✅

The NULL in the queue acts as a "missing node" marker.
```

## 🔁 Equivalent Formulation — Without Storing NULLs

```cpp
// Alternative: stop at first null, check no non-null remains in queue
bool isCompleteTree(TreeNode* root) {
    queue<TreeNode*> q;
    q.push(root);

    while (q.front() != NULL) {      // process until first NULL
        TreeNode* node = q.front(); q.pop();
        q.push(node->left);
        q.push(node->right);
    }

    while (!q.empty()) {
        if (q.front() != NULL) return false;  // non-null after first null
        q.pop();
    }
    return true;
}
```

Same logic, split into two phases. Your single-loop version with `past` flag is cleaner.
