# ⚖️ Balance a Binary Search Tree

> **Platform:** LeetCode 1382 | **Topic:** Trees | **Technique:** Inorder Traversal → Sorted Array → Rebuild Balanced BST

**Question Link:** https://leetcode.com/problems/balance-a-binary-search-tree/

---

## 📌 Problem Summary

Given the `root` of a **possibly unbalanced** BST, return a **height-balanced** BST with the same node values.

```
Unbalanced BST:      Balanced BST:
    1                    3
     \                  / \
      2                2   4
       \              /
        3            1
         \
          4

Both are valid BSTs with same values.
Output must be height-balanced: |left height - right height| ≤ 1 for every node.
```

---

## 💡 Core Intuition — Two-Step Strategy

1. **Inorder traversal** of any BST gives elements in **sorted (ascending) order**
2. **Build balanced BST from sorted array** by always picking the middle element as root

```
Unbalanced BST → Inorder → [1, 2, 3, 4] (sorted)
Sorted array → Build balanced → pick mid=2 as root, recurse
```

> 🔑 This is **LC 108 (Sorted Array to BST)** plugged directly onto the output of inorder traversal.

---

## 🔍 Step 1 — Inorder Traversal

Inorder (left → root → right) on a BST visits nodes in ascending sorted order.

```cpp
void travel(TreeNode* root, vector<TreeNode*>& v) {
    if (root == nullptr) return;
    travel(root->left, v);    // left first
    v.push_back(root);        // then current node
    travel(root->right, v);   // then right
}
```

> 📝 **Key: storing `TreeNode*` instead of `int`** — reuses existing nodes without allocating new memory. More efficient than collecting values and creating new nodes.

---

## 🔍 Step 2 — Rebuild from Sorted Array

Pick middle element as root. Recurse on left and right halves.

```cpp
TreeNode* change(vector<TreeNode*>& v, int left, int right) {
    if (left > right) return nullptr;

    int mid = (left + right) / 2;
    TreeNode* root = v[mid];

    root->left  = change(v, left, mid - 1);   // left half
    root->right = change(v, mid + 1, right);  // right half

    return root;
}
```

---

## 🪜 Algorithm Steps

1. **`travel(root, v)`** — collect all nodes via inorder into `vector<TreeNode*> v`
2. **`change(v, 0, v.size()-1)`** — rebuild balanced BST:
   - `mid = (left+right)/2` → pick middle as root
   - Recursively build left subtree from `[left, mid-1]`
   - Recursively build right subtree from `[mid+1, right]`
3. Return new root

## 🧩 Dry Run

```
Unbalanced BST:
    1
     \
      2
       \
        3
         \
          4

Step 1 — Inorder traversal:
  visit 1 → push 1
  visit 2 → push 2
  visit 3 → push 3
  visit 4 → push 4

v = [node(1), node(2), node(3), node(4)]

Step 2 — Build balanced BST:
change(v, 0, 3):
  mid = (0+3)/2 = 1 → root = node(2)
  left  = change(v, 0, 0):
    mid=0 → root=node(1), left=NULL, right=NULL
  right = change(v, 2, 3):
    mid=2 → root=node(3)
    left  = change(v, 2, 1) → left > right → NULL
    right = change(v, 3, 3):
      mid=3 → root=node(4), left=NULL, right=NULL

Final BST:
      2
     / \
    1   3
         \
          4
```

## 💻 Full C++ Solution

```cpp
class Solution {
public:
    TreeNode* balanceBST(TreeNode* root) {
        vector<TreeNode*> v;
        travel(root, v);
        return change(v, 0, v.size() - 1);
    }

    void travel(TreeNode* root, vector<TreeNode*>& v) {
        if (root == nullptr) return;
        travel(root->left, v);
        v.push_back(root);          // inorder → sorted order
        travel(root->right, v);
    }

    TreeNode* change(vector<TreeNode*>& v, int left, int right) {
        if (left > right) return nullptr;

        int mid = (left + right) / 2;
        TreeNode* root = v[mid];    // middle = root for balance

        root->left  = change(v, left, mid - 1);
        root->right = change(v, mid + 1, right);

        return root;
    }
};
```

## ✅ Key Takeaways

| # | Insight |
|---|---------|
| 1 | **Inorder BST = sorted array** — the fundamental BST property |
| 2 | **Middle element as root** — guarantees equal subtree sizes (±1) → balanced |
| 3 | **`vector<TreeNode*>` not `vector<int>`** — reuses nodes, O(1) space per node vs O(N) for new values |
| 4 | **`(left+right)/2` safe here** — indices are small (N ≤ 10⁴), no overflow risk |
| 5 | Both `travel` and `change` are standard patterns — LC 94 (inorder) + LC 108 (sorted to BST) combined |

---

## ⚠️ Common Mistakes

- ❌ **`v.push_back(root->val)` then `new TreeNode(val)`** — creates new nodes unnecessarily; reuse existing
- ❌ **Preorder or postorder traversal** → doesn't give sorted order for BST
- ❌ **`mid = (left+right)/2` vs `left + (right-left)/2`** — safe here since N ≤ 10⁴, but prefer latter for large inputs
- ❌ **Not resetting `root->left` and `root->right`** — when reusing nodes, old pointers may persist; `change` handles this by always assigning both children

## 🔁 Why Inorder → Sorted?

```
BST property: for every node x:
  all left subtree values < x->val
  all right subtree values > x->val

Inorder = left → root → right
  = smaller values → current → larger values
  = ascending sorted order ✅

Example:
     4
    / \
   2   6
  / \ / \
 1  3 5  7

Inorder: 1, 2, 3, 4, 5, 6, 7 ✅ sorted
```

---

## 🔁 Why Middle Element = Balanced?

```
Array of n elements, pick index mid = (0+n-1)/2:
  Left subarray:  [0, mid-1]   → (mid) elements
  Right subarray: [mid+1, n-1] → (n-1-mid) elements

For n=5, mid=2:
  Left:  2 elements (indices 0,1)
  Right: 2 elements (indices 3,4)
  → perfectly balanced ✅

For n=4, mid=1:
  Left:  1 element  (index 0)
  Right: 2 elements (indices 2,3)
  → height difference ≤ 1 ✅
```
